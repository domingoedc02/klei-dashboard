# Story 18.5: Download site

As the owner, I want a small Thymeleaf web site, on its own port and behind a long secret path, that lists each Electron version with per-OS downloads and serves the version-only manifest, so that staff can install and update the app from one place and a random visitor cannot find or fetch it.

**Assumptions**
- Owner decision OQ-M3 (2026-11-13): the host is this site; it is public on the internet, so the path is secret; the app is for internal use only, so no signing certificates are needed.
- A secret path is a capability URL, not access control. Anyone who holds the URL can download. It is obscurity plus a long random token, accepted by the owner for an internal tool. If the URL leaks, the owner rotates the token (all installed apps then need a reinstall because the URL is compiled in; see 18.3).
- The site is a separate Spring Boot + Thymeleaf application in `electron/download-site/` with its own `pom.xml`, `Dockerfile` and `compose.yml`. It is **not** a module of `backend/`, and `infra/` is not edited. It uses the Boot and Java versions of `backend/app/pom.xml` (read-only reference) after current versions are re-verified at implementation.
- The site is read-only: no upload endpoint, no admin page, no database, no login. Artifacts arrive by the 19.4 workflow writing into the data directory over SSH. The transfer credential is an owner action (OQ-M3 residual); none exists yet.
- Public HTTPS (host name, certificate, DNS) is provided by the owner's reverse proxy (for example Dokploy). The site itself serves plain HTTP on its own port behind that proxy. No host, DNS name or proxy is implied to exist.
- Default port `8090` (`KLEI_DOWNLOAD_PORT`), chosen to avoid the API `8080`, Auth Web `8081`, dev S3 `8333`, Mailpit `8025` and SMTP `1025`. The owner may change it.

**Acceptance Criteria**

**Given** the environment variable `KLEI_DOWNLOAD_PATH_TOKEN` (or `KLEI_DOWNLOAD_PATH_TOKEN_FILE`) is missing, shorter than 43 characters, or contains a character outside `[A-Za-z0-9_-]`
**When** the site starts
**Then** it refuses to start and the message does not print the value.

**Given** a valid token
**When** a request arrives for any path that is not `/{token}`, `/{token}/`, `/{token}/latest.json`, `/{token}/files/{version}/{name}` or the static assets under `/{token}/static/`
**Then** the response is `404` with an empty body and the same headers as any other response, for every method; there is no whitelabel error page, no `robots.txt`, no actuator route, no directory listing, and no redirect from `/{token}` to `/{token}/`.

**Given** the token is compared with the request path
**When** the first path segment is checked
**Then** the comparison is constant-time (`MessageDigest.isEqual`), and the token appears in no application log line, error message or Thymeleaf output.

**Given** the data directory `KLEI_DOWNLOAD_DATA_DIR` holds `<version>/release.json` and the files it names
**When** `GET /{token}/` is requested
**Then** an HTML page lists versions newest first (strict semver order); each version shows its number, publication date, a **Preview** label, and one row per file with OS, architecture, kind, size, SHA-256 and a download link: macOS Apple silicon (arm64) and Intel (x64), Windows 11 x64, Ubuntu 24.04 x64 `AppImage` and `.deb`.

**Given** a version folder
**When** `release.json` is missing, malformed, names a file that is absent, has a different size, or has a name outside `^[A-Za-z0-9._-]{1,128}$`
**Then** that version is not listed and cannot be downloaded; other versions are unaffected; a folder whose name starts with `.` is ignored (an upload in progress).

**Given** `GET /{token}/files/{version}/{name}`
**When** the request names a file listed in that version's `release.json`
**Then** it is streamed with `Content-Disposition: attachment`, `Content-Type: application/octet-stream` and `Cache-Control: no-store`; any other name, a `..`, an encoded `..`, a backslash, an absolute path or an unlisted file in the folder returns `404`.

**Given** `GET /{token}/latest.json`
**When** at least one version is listed
**Then** it returns `200` with `Content-Type: application/json` and exactly `{"version":"<highest semver>","pubDate":"<ISO-8601>"}`: no URL, no notes, no file list, no other field; with no listed version it returns `404`.

**Given** any response
**When** headers are inspected
**Then** it carries `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex, nofollow, noarchive`, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`, and a `Content-Security-Policy` of `default-src 'none'; style-src 'self'; img-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`; the page includes `<meta name="robots" content="noindex,nofollow">`, loads no script, font, image or style from another origin, and sends no cookie.

**Given** the page
**When** read by a keyboard or screen-reader user
**Then** it uses semantic headings and a table with captions and header cells, visible focus, and a contrast of at least 4.5:1, and it works with no JavaScript.

**Given** the page text for first launch
**When** reviewed
**Then** it gives only the user-initiated steps of 18.2 (macOS Finder right-click **Open**, Windows **More info** then **Run anyway**, Linux `chmod +x` for the AppImage), states that the app is unsigned and for internal use, and recommends none of: disabling protections, shell quarantine removal, registry edits. It states that SHA-256 values are shown for comparison and that comparing them is optional.

**Given** the repository
**When** the story is complete
**Then** `git diff --exit-code 51949da2a0f8347c5f1f56fc5d87d8ada6e60643` over the protected paths is empty, `backend/app/pom.xml` is unchanged, and no file under `backend/` or `infra/` references the site.

**Tasks**
- `electron/download-site/pom.xml`: Spring Boot, `spring-boot-starter-web`, `spring-boot-starter-thymeleaf`, test starter; no security starter, no actuator, no database.
- `electron/download-site/src/main/java/co/klei/download/`: `DownloadSiteApplication`, `TokenGate` (a servlet filter: token check, 404 for everything else, headers), `ReleaseStore` (reads the data directory, validates `release.json`, semver order), `SiteController` (page, `latest.json`, file stream, stylesheet), `EmptyError` and `TomcatEmptyErrors` (empty `404` for errors raised before or after the filter).
- `electron/download-site/src/main/resources/templates/index.html`, `static/site.css`: no JavaScript; tokens copied by hand from `backend/app/src/main/resources/static/tokens.css` (read-only reference, not linked).
- `electron/download-site/src/main/resources/application.yml`: `server.port: ${KLEI_DOWNLOAD_PORT:8090}`, whitelabel error off, access log off (the reverse proxy log must also be redacted of the path), no cookies, `spring.mvc.throw-exception-if-no-handler-found`.
- `electron/download-site/Dockerfile`, `compose.yml`: read-only root filesystem, non-root user, data directory mounted read-only, port from `KLEI_DOWNLOAD_PORT`, token from a variable or secret file; `/tmp` is a tmpfs because Tomcat writes there. shortcut: no container health check (the image has no curl); use the platform's TCP check, add one if the platform needs it.
- `electron/download-site/src/test/java/co/klei/download/DownloadSiteTest.java`: MockMvc tests for every Given/Then above, including startup refusal, 404 for `/`, `/robots.txt`, `/error`, `/actuator/health`, a near-miss token, the token with a trailing slash difference, traversal attempts, unlisted files and half-uploaded folders; header assertions; `latest.json` exact fields; no token in captured logs.
- `electron/download-site/.env.example`: the three runtime variables (`KLEI_DOWNLOAD_PORT`, `KLEI_DOWNLOAD_PATH_TOKEN`, `KLEI_DOWNLOAD_DATA_DIR`) with an empty token, for the Dokploy Environment tab; the GitHub-only values are listed as comments. It never holds a real value.
- `electron/download-site/README.md`: configuration, token generation (`openssl rand -base64 32 | tr '+/' '-_' | tr -d '='`), rotation, withdrawing a version (delete its folder), data directory layout, and the capability-URL limits.

**Dev notes**
- `release.json` (written by 19.4 `release-manifest.mjs`, uploaded last): `{"version","pubDate","channel":"preview","files":[{"name","os","arch","kind","size","sha256"}]}`. The site derives `latest.json` from the highest listed version; the workflow does not upload a separate manifest.
- Size is checked on each request; SHA-256 is computed by the publisher, not recomputed by the site. shortcut: no re-hash on read, add a startup hash check if tampering of the data directory becomes a concern.
- Throttling of repeated 404 probes is left to the reverse proxy. shortcut: no in-app rate limit; a 43-character base64url token is 258 bits, so guessing is infeasible, and the limit protects only log noise.
- Reference only, not copied: `backend/app/src/main/resources/templates/` and `static/` (Thymeleaf conventions and visual tokens), `backend/app/pom.xml` (Boot, Kotlin and Java versions). The site is Java only; no Kotlin dependency on `backend/`.
- The app side: 18.3 reads `latest.json` and opens `/{token}/` from build-time constants; the renderer never sees either URL.
- No visitor analytics or telemetry (NFR-6).

**Testing**
- Run the MockMvc tests once the project exists; a container start with a real token on the chosen port, behind a throwaway proxy with HTTPS, is the real check (not run for this documentation task).
- From a second machine, confirm that `/`, `/<wrong token>/` and `/<token>` with a typo return an empty `404`, and that the page and a download work with the right token.

**Prototype unchanged check**
- Require the baseline protected-path diff empty and no untracked file outside `electron/`, `docs/` and new `.github/workflows/electron*.yml`.
- `backend/` and `infra/` (including `infra/docker-compose.yml` ports) are unchanged; the site shares no code, port, secret or image with them.
