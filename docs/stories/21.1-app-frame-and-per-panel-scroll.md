# Story 21.1: App frame and per-panel scroll

As a Staff member on any screen,
I want the sidebar and top bar to stay put and only the content panel to scroll,
So that I never lose navigation by scrolling, and long pages do not drag the whole window.

**Assumptions**
- Reported: Settings scrolled and the sidebar left the screen (screenshot 2). Applies to every screen (Upload, Settings, Gallery, Inquiries, Dashboard, Drafts).
- `docs/ux-spec.md` line 46 already says "Content scrolls, sidebar and top bar do not." This story makes the code and the probe enforce it.
- The CSS frame looks correct on paper (`.app { height: 100vh; overflow: hidden }`, grid `64px minmax(0,1fr) / 240px minmax(0,1fr)`, `.sheet { overflow: auto }`, `.sidebar { overflow-y: auto }`). **The trigger is not confirmed.** First task is a repro; do not change CSS until the cause is seen.
- Two-pane screens (Review, Viewer) get their panes in 21.2 and 21.3. This story fixes the frame and single-pane screens only, and defines the invariant they build on.
- Window sizes: default 1280x800, minimum 1100x700 (`electron/src/main/identity.ts`); capture is 1440x900 (`scripts/shots/common.mjs`). Both 1440x900 and 1100x700 must hold.

**Acceptance Criteria**

**Given** any screen with content taller than the window, at 1440x900 and at 1100x700
**When** the user scrolls (wheel, keyboard, Space, End, focus moving to a lower control)
**Then** `document.scrollingElement.scrollTop` stays 0, the top bar and sidebar do not move, and only `main#view.sheet` (or a pane inside it, see 21.2 and 21.3) scrolls

**Given** the sidebar
**When** the window is 1100x700
**Then** every nav item and the brand are visible with no sidebar scrollbar, and the sidebar never moves when the content scrolls

**Given** focus moves to a control below the fold (Tab, skip link, in-page anchor)
**When** the browser scrolls it into view
**Then** only the content panel scrolls; `html` and `body` do not

**Given** the probe runs over the captured screens
**When** a page, `html` or `body` can scroll vertically, or the sidebar or top bar moved
**Then** `probe.mjs` reports a new finding `frame-scroll`; the desktop side of every captured screen has none

**Given** `styles.test.ts`
**When** it runs
**Then** it asserts the frame contract (`.app` fixed height and `overflow: hidden`; `.sheet` is the scroller; `.screen` no longer forces `min-height: 100vh` inside the frame)

**Given** the story's screens are captured on both sides
**When** `node scripts/capture.mjs --side both` and `npm run shots:diff` run
**Then** `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `dialog-scroll`, `dialog-overflow` or `frame-scroll` for the desktop side, and the run logs no `UNMOCKED` request and no page or console error

**Tasks**
- Repro first: run the app at 1440x900 and 1100x700; open Settings, Upload review and Gallery; record `html`/`body`/`.sheet` `scrollHeight` vs `clientHeight` and `window.innerHeight` vs `100vh`. Write the confirmed cause into the Dev record before editing.
- `desktop/src/styles.css`: fix per the confirmed cause. Candidates, in order: `html, body { height: 100%; overflow: hidden }` (body line 5 has no height or overflow); `.screen { min-height: 100vh }` (line 11) inside the frame; `100vh` vs the Electron viewport (`100dvh` or `height: 100%`); a screen that renders its own tall wrapper outside `.sheet`. Sidebar: `overflow: hidden` only if the nav fits at 700 px high, else tighten spacing so it fits.
- `desktop/scripts/shots/probe.mjs`: add `frame-scroll` (page scroll position or `html`/`body` `scrollHeight > clientHeight`; sidebar/top-bar `getBoundingClientRect` unchanged after scrolling `.sheet` to the end).
- `desktop/scripts/shots/common.mjs` and `capture.mjs`: accept a viewport size (`--viewport 1100x700`) if there is none; geometry output keyed by viewport. Read both files first.
- `desktop/src/styles.test.ts`: frame assertions (see AC). Keep the existing `.sheet` padding assertion (line 81).
