# Story 15.4: Closed command registry and error contract

As the owner, I want exactly nine commands registered in Electron main, checked by a test, with the same error shape as the original, so that a tenth command or a leaked error detail cannot appear unnoticed.

**Assumptions**
- The closed set is `api_request`, `sign_in`, `sign_out`, `upload_files`, `export_gowns`, `check_update`, `install_update`, `set_dirty`, `session_only` (source: `desktop/src-tauri/src/commands.rs::NAMES`).
- Error `kind` values are the twelve in `desktop/src-tauri/src/error.rs::Kind` and `desktop/src/bridge.ts::ErrorKind`: `signed_out`, `keychain_unavailable`, `session_expired`, `no_access`, `failed`, `timeout`, `cancelled`, `offline`, `bad_request`, `too_large`, `update_refused`, `update_unverified`. `update_unverified` stays in the type and is never produced by Electron (18.3).
- Handlers in this story are stubs that reject with `failed` and message "not implemented"; Epics 16 and 17 replace them one by one.

**Acceptance Criteria**

**Given** the registry
**When** the exported `COMMANDS` array is compared with the preload allow list and the main-process handler map
**Then** all three are the same nine names; a test fails on any add, remove or rename in only one place.

**Given** `ipcMain.handle` registrations
**When** the main source is scanned
**Then** exactly one channel is registered for commands (`klei:invoke`), plus the private 17.2 drop channel; no `ipcMain.on`, no `handle` with a name taken from the renderer.

**Given** an IPC message
**When** `event.senderFrame` is not the main frame of the preview window, or its URL is not on origin `app://klei`
**Then** it is rejected with `bad_request`, nothing runs, and the rejection is logged without arguments.

**Given** a handler throws a non-`BridgeError`, or an error carries a token, code, path, response body or stack
**When** the registry converts it
**Then** the renderer receives `{ kind: 'failed', message: 'request failed' }`; `BridgeError` values pass through unchanged; no message contains the substrings that a test seeds as secrets.

**Given** the original contract test `desktop/src-tauri/tests/contract.rs`
**When** its assertions are ported
**Then** `electron/test/contract.test.ts` asserts: the nine names; CSP equal to the Tauri CSP, except that the Windows build may add exactly `http://klei-img.localhost` to `img-src` (17.5) and `connect-src` stays `'none'`; minimum window size 1100×700; no remote URLs in the Electron main source other than the config and the 18.3 constants; no business-content writes outside the allowed modules (`uploads.ts` reads only, `export.ts` writes the one chosen file and removes partials, `keychain.ts` writes the credential store).

**Tasks**
- `electron/src/main/ipc.ts`: single `klei:invoke` handler, frame validation, argument validation from `shared/commands.ts`, error conversion.
- `electron/src/main/commands.ts`: handler map with nine stubs, each typed.
- `electron/src/shared/errors.ts`: `Kind`, `BridgeError`, `toBridgeError`.
- `electron/test/contract.test.ts`, `electron/test/ipc.test.ts`, `electron/test/hostile-renderer.test.ts` (unknown command, wrong payload, foreign frame, sub-frame, post-navigation, oversized input).

**Dev notes**
- Port `desktop/src-tauri/tests/contract.rs` test by test (`the_nine_commands_and_no_others`, `csp_is_not_loosened`, `nothing_is_written_outside_the_keychain`; the updater-URL test becomes an assertion on the 18.3 constants).
- The Tauri capability file `capabilities/default.json` has no Electron equivalent; the preload allow list plus main handler map replace it.
- Error messages never carry tokens, codes or response bodies (comment in `error.rs`).

**Testing**
- Run `electron/test/contract.test.ts`, `ipc.test.ts`, `hostile-renderer.test.ts`. Real-Electron frame tests run in CI (19.2).

**Prototype unchanged check**
- Require the 14.1 gate. The original `desktop/src-tauri/tests/contract.rs` is read and not edited. It remains the test of the Tauri app.
- UI: with all stubs rejecting, the original renderer shows its existing error states; compare the signed-out screen with the baseline capture at 1280×800.

**Dev agent record**
- Files: `electron/src/main/{invoker,ipc,commands}.ts`, `electron/src/shared/{commands,errors}.ts`, `electron/src/main/{index,window}.ts` (wiring), `electron/test/{contract,ipc,preload-electron}.test.ts`.
- `invoker.ts` has no `electron` import so `ipc.test.ts` runs it in plain Node. `ipc.ts` is the only file with `ipcMain` and holds exactly one `ipcMain.handle(INVOKE_CHANNEL)`.
- Checks, in order, each logged by reason only: sender is the preview window, `senderFrame` is that window's main frame (`parent === null`), origin `app://klei` and `isAppUrl(url)`; command is an own member of `COMMANDS`; channel commands carry a UUID event id and plain commands carry none; id not already live; `validate`. Every refusal answers `bad_request` and runs no handler.
- Errors: only a `BridgeError` with a known kind passes; anything else becomes `{failed, 'request failed'}`. Test seeds bearer token, refresh token, path, response body and stack text and asserts none reach the page.
- Reload, close and renderer crash: `releaseOnGone` calls `invoker.release`, which aborts every live call of that sender (`ctx.signal`) and forgets its ids. Events after release are dropped.
- Stubs: all nine reject `failed` / `not implemented`.
- Deferred to the owning stories: handlers must stop on `ctx.signal` (17.1 uploads, 17.4 export removes the partial file and releases its single-run lock). The mechanism is tested here; the file and lock behavior is not, because no handler exists yet. The private 17.2 drop channel is added by 17.2, and `contract.test.ts` currently asserts it is absent.
- `contract.test.ts` ports the three behavior tests of `contract.rs`. The updater-URL test becomes "no remote URL in main, shared or preload"; 18.3 adds its constants to the allow list. The write test allows only `readFile`, `realpath`, `stat` in `app-files.ts` today; 16.3, 17.1 and 17.4 extend it.
- Real Electron, macOS arm64: nine keys, no `ipcRenderer`/`require`/`process`/`Buffer`, plain `{kind,message}` errors, bad payloads give `bad_request`, a sub-frame on `app://klei` gets no `window.klei`, reload keeps the bridge working.
- Not verified: sender frame from a navigated-away or foreign-origin page in real Electron (covered only by the unit table, since the CSP already blocks the navigation in 15.2); Windows and Linux.
- Tests: 63 pass in `electron/`, typecheck clean, gate passes.
