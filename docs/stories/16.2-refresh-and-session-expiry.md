# Story 16.2: Token refresh and session expiry

As a signed-in User, I want an expired access token swapped for a new one once and the call retried, and a refused refresh to sign me out cleanly, so that I am not interrupted and no stale credential lingers.

**Assumptions**
- The access token lives in memory only. The refresh token is stored only through the credential-store interface (implemented in 16.3). This story uses an in-memory test double.
- Refresh is `POST /api/v1/auth/refresh` with `{ refreshToken }`; token pair is `{ accessToken, refreshToken }`.

**Acceptance Criteria**

**Given** no cached access token
**When** an authorised call starts
**Then** one refresh runs first; with no stored refresh token the call fails `signed_out` "signed out"; a credential-store error fails `keychain_unavailable`.

**Given** a call returns 401 with token T
**When** the retry logic runs
**Then** exactly one refresh happens, the call is sent once more with the new token, and the result has `refreshed: true`; a second 401 ends the session as `session_expired`.

**Given** several concurrent calls see the same rejected token
**When** they refresh
**Then** exactly one refresh request reaches the server (single flight); the others reuse the new token. A caller whose rejected token differs from the cached one skips the refresh.

**Given** a refresh response of 200
**When** the pair is accepted
**Then** the refresh token is stored first; if the store refuses, no access token is kept (fail closed) and `keychain_unavailable` is returned.

**Given** a refresh response of 401
**When** handled
**Then** the access token is dropped, the stored refresh token is cleared, and `session_expired` "session expired" is returned.

**Given** a refresh response of 403
**When** handled
**Then** the same cleanup runs and `no_access` "no access" is returned.

**Given** any other refresh status
**When** handled
**Then** `failed` "refresh failed" is returned and the stored token is kept.

**Given** a malformed token response
**When** parsed
**Then** `failed` "bad token response" is returned and nothing is stored.

- `electron/test/session-refresh.test.ts`: `concurrent_requests_share_one_refresh`, `stale_token_refreshes_once_and_retries_once`, `refused_refresh_ends_the_session_and_clears_the_keychain`, `refresh_refused_for_a_role_without_permissions_reports_no_access`, `unusable_keychain_fails_closed`.

**Dev notes**
- Port from `session.rs::{authed, refresh, accept, expire}`; the mutex must serialise refresh without blocking the access-token read.
- The `refreshed` flag lets screens reload Permissions; keep its exact semantics.
- Tokens never appear in logs, errors or the renderer.
