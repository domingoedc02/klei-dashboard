# Story 6.1: Profile and password

As a Staff member,
I want to edit my name and photo and change my password,
So that my details are right and my account stays safe.

**Assumptions**
- Email is not self-editable (A-UX9). The helper reads "Ask an admin to change your email."
- Avatar: JPEG, PNG or WebP up to 2 MB, stored encrypted through `ObjectCipher` (same pipeline as photos, 256 px JPEG, metadata stripped). `app_user.avatar_object_id` points to it.
- Password change revokes the User's other sessions (refresh families other than the current one); the access token of the current session stays valid. The epoch is not bumped.
- Wrong current password counts toward the sign-in rate limit for that account `[ASSUMPTION]`.

**Acceptance Criteria**

**Given** `GET /me/profile` and `PATCH /me/profile {name}` with `If-Match`
**When** called
**Then** name is validated (1 to 80 characters), encrypted, and an Audit Entry is not written (personal data, not an admin action) `[ASSUMPTION]`; a stale version returns 409.

**Given** `PUT /me/avatar` with an image and `DELETE /me/avatar`
**When** called
**Then** the old object is deleted after commit, an oversize (over 2 MB) or wrong type returns 413 or 415, and `GET` of the avatar goes through the same read path as photos.

**Given** `POST /me/password {current, new}`
**When** the current password is right and the new one meets the rule (8+ characters, one number, at most 128)
**Then** the hash is replaced, other sessions are revoked, an Audit Entry `password_changed` is written, and the response is 204; a wrong current password returns 422 with field `current` (code `incorrect`).

**Given** S1
**When** it renders
**Then** it shows the avatar with **Upload photo** and **Remove**, name input, read-only email, **Save changes**, and a second panel with current, new (strength meter) and confirm password and **Update password** with the helper "Other devices will be signed out."; the 2FA card is absent; Loading and Error states exist; errors show under fields.

**Given** success
**When** each action completes
**Then** toasts read "Changes saved" and "Password updated"; the top-bar avatar updates.

**Given** the leak suite
**When** extended
**Then** a Sentinel name, an avatar with Sentinel EXIF and a Sentinel password leave nothing in tables, S3 or logs.

**Tasks**
- Backend: `ProfileController`, `AvatarService`, `PasswordChangeService`, tests.
- Desktop: Settings > Profile tab, avatar component (reused by Staff and Inquiries rows), tests, axe.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && (cd src-tauri && cargo test)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: change name, change password, old refresh token on another session refused).

## Dev record

**Assumptions**
- `GET/PATCH /api/v1/me/profile` (name 1 to 80 characters, `If-Match`; stale 409; blank or over-long 422 `name`). No Audit Entry on rename, as the story says. Any signed-in Role may use it, so there is no new Permission.
- Avatar: `PUT /api/v1/me/avatar` multipart, 2 MB cap (413), JPEG/PNG/WebP only (415), decoded, EXIF stripped, re-encoded as a 256 px JPEG and stored through the same encrypted object pipeline as photos. `GET /api/v1/me/avatar` answers the caller's own image only (404 when none), `no-store` + `nosniff`. `DELETE` is idempotent. Old object is deleted after commit; `ObjectSweepJob` skips avatar ids. `MeResponse.avatar` is a revision number that only busts the webview cache.
- `POST /api/v1/me/password {current, new}`: rule 8..128 with a digit (`PasswordPolicy`); wrong current is 422 `current`/`incorrect` and counts toward the sign-in throttle (429 after 5 for the account); success is 204, replaces the Argon2id hash, `RefreshService.revokeOthers` ends every other refresh family, the current session and its access token stay, the permission epoch is not bumped, and Audit Entry `password_changed` is written (Audit tab label "Password changed").
- Avatar is served only to its owner, so the Staff table keeps letter avatars; the top bar and the Profile tab show the photo.
- Profile is the last Settings tab, open to every Role; the user menu links to `#/settings/profile`. A Role with no admin Permission lands on it, so Settings no longer has an empty state. 2FA card absent.
- Avatar upload stays inside the closed eight-command set: `upload_files` kind `avatar` opens a single-file dialog, Rust reads the file (still the only file reader), enforces 2 MB and PUTs it with no Idempotency-Key. `klei-img://localhost/me/{revision}` serves the own avatar through the signed session and is never cached in Rust.
