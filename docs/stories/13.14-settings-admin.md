# Story 13.14: Settings: Admin tabs

As an Admin,
I want Staff, Roles, AI settings and Audit log to match the prototype,
So that I administer the studio in a layout that reads like the design.

**Assumptions**
- Prototype: `js/settings.js` admin tabs (`adm-tab` staff/roles/ai/audit), `css/screens.css` `.tbl`, `.role-badge`, `.srow`; pairs `settings-{staff-default,staff-empty,staff-add-dialog,roles-default,ai-default,ai-provider-fail,audit-default}`. Desktop: `desktop/src/settings/admin/*.tsx`.
- **Decision D3 (ST-03, ST-32), pending the user's answer.** Assumed option (a), the recommendation: keep the true copy "Changes take effect right away." (the backend bumps the permission epoch, so tokens go stale at once) and move it below the table as in the prototype. The extra `View gallery` permission row stays if it exists in `RoleAdminService` (backend source of truth); the row is `accepted deviation` with that reason. If the user answers (b), use the prototype copy and drop the row only if the backend agrees.
- ST-28: Last active uses the 13.3 formatter (`Today, 8:4x AM`, D1 assumption (a)).
- ST-31 and ST-37 are fixture rows (Staff add-dialog click on an empty form, stored AI key): fix them in `shots/desk/settings.mjs` (13.1 scope for harness changes, done here for the screens this story owns).
- Usage, Keys and the Audit pager have no prototype twin: keep, judge against DESIGN.md.

**Acceptance Criteria**

**Given** the Admin sub-tabs (ST-09)
**When** they render
**Then** they are the prototype's xs pills (4px 8px, 1 px border, dark fill when active)

**Given** the Staff table (ST-25, ST-26, ST-27, ST-28, ST-34)
**When** it renders
**Then** columns are the prototype's (one combined avatar + name + email cell), the role cell uses the dark `Admin` badge, row actions are icon buttons (pencil, trash) plus a ghost `Resend invite`, headers are uppercase xs 600, and Last active reads relative

**Given** Staff empty and Add dialog (ST-29, ST-30, ST-31)
**When** they render
**Then** empty hides the table header row and shows the illustration; the dialog labels are `Full name *` / `Work email *`; the capture opens the dialog with a valid state

**Given** the Roles matrix (ST-03, ST-32, ST-33, D3 assumption (a))
**When** it renders
**Then** blue checkboxes, the Locked pill moved off the Admin header, row height as in the prototype, and the footer copy below the table

**Given** the AI settings (ST-35, ST-36, ST-37, ST-38, ST-39)
**When** they render
**Then** a `Model provider` card, Temperature as a range slider with its live value, `Connection` status inside its card, and the fail pair `settings-ai-provider-fail` matches; the sticky Save is kept if a single request saves both blocks, else it follows the prototype split (decide from `AiSettingService` in the Dev record, no backend change)

**Given** the Audit log (ST-40)
**When** it renders
**Then** a card with an `Audit log` h3 and uppercase headers WHEN / USER / ACTION / IP

**Given** the story's screens are captured on both sides
**When** `node scripts/capture.mjs --side both --only {only}` and `npm run shots:diff -- --only {only}` run
**Then** `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `dialog-scroll` or `dialog-overflow` for the desktop side of these screens (`text-ellipsis` only where the prototype truncates the same text), and the run logs no `UNMOCKED` request and no page or console error

**Given** every audit row listed above
**When** the story is done
**Then** the row's Status in `docs/planning-artifacts/ui-parity/audit.md` is `closed` with the fix commit and the after-screenshot path, or the row says `accepted deviation` with the decision it follows (D1 to D5 in the change proposal) and the reason
