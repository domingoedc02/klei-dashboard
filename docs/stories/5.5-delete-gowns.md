# Story 5.5: Delete Gowns

As an Admin (or anyone granted Delete gown folders),
I want to delete one or many gowns for good,
So that mistakes and old stock leave the Gallery and the storage.

**Assumptions**
- Hard delete, no trash (PRD FR-18). Rows go in one transaction; S3 objects go in `afterCommit`; the sweep catches failures.
- Delete uses `POST /gowns/delete {ids}` (not `DELETE` with a body); at most 100 ids per call.
- The audit detail carries counts and encrypted Gown names, not plaintext.

**Acceptance Criteria**

**Given** `POST /gowns/delete {ids}` with `PERM_DELETE_GOWN`
**When** called
**Then** the Gowns, `gown_attribute`, `gown_term`, Photos, embeddings (none remain) and their `stored_object` rows are deleted in one transaction, the S3 objects are deleted after commit, an Audit Entry `gown_deleted` is written with the count and the encrypted names, and the response is `{deleted: n}`; a caller without the Permission gets 403 and that 403 writes its own Audit Entry.

**Given** ids that do not exist
**When** included
**Then** they are skipped and returned in `missing`; over 100 ids returns 422.

**Given** the object store is down at delete time
**When** the commit succeeds
**Then** the rows are gone, the objects stay until the sweep, and the response is still 200.

**Given** G1 select mode (Admin)
**When** **Delete** is pressed with N selected
**Then** the dialog lists names (up to 3, then "and N more"), the total Photo count, "This can't be undone.", Cancel focused and a red **Delete N gowns**; after success the toast "{N} gowns deleted" shows and the grid reloads from page 1.

**Given** G2
**When** **Delete** is pressed
**Then** the same dialog shows for one gown and the screen returns to Gallery after success.

**Given** a Staff or Viewer by default
**When** the screens render
**Then** Delete is absent (Staff, Viewer) and select mode in G1 offers only Download; a Role granted the Permission sees it right away.

**Given** the leak suite
**When** extended
**Then** after delete no Gown-derived row remains (`gown_term` included) and the bucket holds no object for the deleted Photos.

**Tasks**
- Backend: `GownDeleteService`, afterCommit hook, tests including S3 failure.
- Desktop: select mode delete, dialog, tests, axe.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && (cd src-tauri && cargo test)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: delete the saved gown, bucket object count returns to zero).

## Dev record

**Assumptions**
- `POST /api/v1/gowns/delete {ids}` needs `PERM_DELETE_GOWN` (403 without it; the existing denial path writes that 403's own Audit Entry). Missing or empty `ids` is 422 `ids` `required`; more than 100 distinct ids is 422 `ids` `too_many`. Answer is `{deleted, missing}`; unknown ids are skipped.
- One transaction: Embeddings, Photos, the Gowns (`gown_attribute` and `gown_term` go by `ON DELETE CASCADE`), then the `stored_object` rows of both objects of each Photo. The S3 objects are deleted in `afterCommit`; a failure is logged by class name only and the nightly sweep removes the leftovers, so the response stays 200.
- Audit `gown_deleted` detail is `gowns=N photos=M names=A; B; ...` (first 10 names, then "and K more"). The detail column is encrypted like every Audit Entry column, so the names are not plaintext at rest (`[ASSUMPTION]` the story's "encrypted names" means this).
- Deleting an id twice, or one another caller deleted first, answers 200 with `deleted: 0` and the id in `missing`; the desktop says "Those gowns were already deleted".
- Delete shows only with `PERM_DELETE_GOWN`: in G1 select mode (next to Download .zip, disabled until a pick) and in G2. Confirm dialog (`deleteSpec` in `gallery/remove.ts`): title "Delete gown?" / "Delete N gowns?", body lists up to three names then "and N more", the Photo count and "This can't be undone.", Cancel focused (the shared dialog host focuses Cancel for danger actions), red **Delete gown** / **Delete N gowns**. Success toast "{N} gown(s) deleted". After success G1 leaves select mode and reloads from page 1; G2 goes back to `#/gallery`. Both call `forgetGallery()`.
