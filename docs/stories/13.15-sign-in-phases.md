# Story 13.15: Desktop sign-in phases

As a Staff member,
I want the sign-in and error screens to look consistent and never overlap,
So that I can recover from keychain, network and session problems.

**Assumptions**
- Prototype `auth/login` is a backend Thymeleaf page, out of desktop scope; use it for card geometry only (440 px card, 32 px padding, brand 700). Desktop phases: `booting`, `signedOut`, `waiting`, `failed`, `keychain`, `unreachable`, `expired`, `noAccess` in `desktop/src/App.tsx`; captures `signin-*` are desktop-only.
- SH-30 is a real bug (P1): on `keychain_unavailable` the line "You will sign in again the next time you open the app." paints over the `Try again` and `Continue` buttons.
- SH-26 notes the desktop sign-in has no email/password form (it hands off to the browser); the audit records it as by design (OAuth browser flow), so it stays.

**Acceptance Criteria**

**Given** the keychain-unavailable phase (SH-30)
**When** it renders
**Then** the hint is a separate block above the buttons with spacing, and `geometry.json` has no `overlap` or `covered` for `signin-keychain_unavailable`

**Given** the sign-in cards (SH-26, SH-28, SH-29, SH-31)
**When** each phase renders
**Then** the card geometry is the 440 px card with 32 px padding; waiting and booting have a visible heading so the brand does not jump between phases; error text uses the DESIGN.md error token with a heading; buttons use the shared primary style

**Given** the booting phase (SH-27)
**When** it renders
**Then** it shows a spinner or skeleton, not the bare text `Loading…`

**Given** the story's screens are captured on both sides
**When** `node scripts/capture.mjs --side both --only {only}` and `npm run shots:diff -- --only {only}` run
**Then** `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `dialog-scroll` or `dialog-overflow` for the desktop side of these screens (`text-ellipsis` only where the prototype truncates the same text), and the run logs no `UNMOCKED` request and no page or console error

**Given** every audit row listed above
**When** the story is done
**Then** the row's Status in `docs/planning-artifacts/ui-parity/audit.md` is `closed` with the fix commit and the after-screenshot path, or the row says `accepted deviation` with the decision it follows (D1 to D5 in the change proposal) and the reason

**Given** each prototype/desktop pair of the story
**When** the lead reads the montage in `ui-parity/diff/`
**Then** the Dev record has one line per pair: `match`, or the remaining difference and why it is fixture-only noise (SVG gown art, fixed clock, mock data). Pixel % is recorded in the Dev record as a trend and is not a gate
