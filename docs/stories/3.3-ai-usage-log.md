# Story 3.3: AI usage log

As an Admin,
I want to see every AI request the app made, with its outcome,
So that I can check what was sent, spot failures and later add a quota.

**Assumptions**
- `ai_usage` and its writer exist from Story 3.1. Later AI stories (4.3, 4.4, 8.3) write rows through the same recorder.
- No credits or quota meter in the MVP (PRD OQ 6). Not shown in the sidebar either.
- Prompts and responses are stored encrypted. The screen shows purpose, model, size, outcome, duration, time and user; the prompt and response bodies are not shown in the list. OPEN QUESTION (non-blocking): should an Admin be able to open a row and read the stored prompt and response? Default: no; they stay stored for audit and future metering and are not exposed by any endpoint in the MVP.
- Offset paging, 50 rows per page, newest first by `seq`.

**Acceptance Criteria**

**Given** `GET /admin/ai/usage?page=n`
**When** called with `PERM_AI_SETTINGS`
**Then** it returns 50 rows `{time, user, purpose, model, size, outcome, durationMs}`, `page`, `pages`; neither prompt nor response is in the payload; a caller without the Permission gets 403.

**Given** purposes
**When** the recorder writes a row
**Then** `purpose` is one of `test`, `embed`, `describe`, `chat` and `outcome` is one of `ok`, `error`, `timeout`, `refused`; a test asserts no other value is accepted.

**Given** a failed AI call
**When** the caller's transaction rolls back
**Then** the usage row still exists (own transaction).

**Given** the usage tab (S7 sub-tab)
**When** it renders
**Then** it shows a table with Time, User, Purpose, Model, Size, Outcome pill, Duration, a pager like the Audit log, Loading skeleton rows, Error block with Retry and Empty "No AI requests yet".

**Given** the leak suite
**When** extended
**Then** a Sentinel prompt and response sent through a stub call are in `ai_usage` only as padded envelopes, and no usage endpoint returns them.

**Tasks**
- Backend: `AiUsageController`, `AiUsageQuery`, enum guard test.
- Desktop: usage sub-tab, table, pager reuse, tests, axe.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && (cd src-tauri && cargo test)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: the Test connection call from earlier appears on page 1).

## Dev record

**Done**
- Backend: `AiUsageQueryService` (50 per page, newest first by `seq`, `pages` at least 1, user names resolved in one query: `System` when no user, `Deleted user` when the id no longer exists), `AiUsageController` `GET /api/v1/admin/ai/usage?page=n` (`PERM_AI_SETTINGS`, page outside 1..1,000,000 is 422). Payload `{items:[{id,time,user,purpose,model,size,outcome,durationMs}],page,pages}`; no prompt or response field exists in the DTO. The recorder and own-transaction write came from 3.1 and are unchanged.
- Desktop: `UsageTab.tsx` as Settings tab "AI usage" (`PERM_AI_SETTINGS`), table Time, User, Purpose, Model, Size, Outcome pill, Duration, pager like Audit log, skeleton rows, error block with Retry, empty "No AI requests yet".
- Leak suite: `ai_usage.prompt_ct` and `response_ct` now carry Sentinels; `usageEdits` records a call and asserts the list returns neither.
- Smoke: usage list returns 200, shows the Test connection row, has no prompt/response key, `page=0` is 422.

**Checks run**
- `cd backend && ./mvnw verify`: 125 integration tests, 0 failures (`AiUsageIT` 7).
- `cd desktop && npm test`: 84 pass (`UsageTab.test.tsx` 5 incl. axe); `tsc`, `npm run build`, `cargo test` (20+3) ok.
- Compose smoke on throwaway project `kleismoke`: SMOKE PASS, project removed; dev `klei` stack untouched.

**Decisions**
- OPEN QUESTION (prompt/response viewing) left at default: stored encrypted, exposed by no endpoint.
- Purpose labels shown to the user: Test connection, Photo matching, Description, Assistant.

**Shortcuts**
- Dates use the browser locale until Story 6.3 adds the chosen format and timezone.
- Offset paging counts all rows per request; fine at expected volume, switch to keyset paging if the log passes ~100k rows.
- No retention or purge of `ai_usage`: add with a quota story.
