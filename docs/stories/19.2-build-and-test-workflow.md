# Story 19.2: Build and test workflow

As a developer, I want every Electron change built, type-checked, tested and smoke-launched on the three target OS families in CI, so that a break shows up before packaging.

**Assumptions**
- New file `.github/workflows/electron.yml`; triggers on `push` and `pull_request` with `paths: ["electron/**", ".github/workflows/electron*.yml"]` (the filter is allowed here because 19.1 has none and is the protection).
- Matrix `os: [macos-latest, windows-latest, ubuntu-latest]`, `fail-fast: false`, `defaults.run.working-directory: electron`, `shell: bash`. Runner images and Node version are verified at implementation.
- Env `KLEI_API_URL: http://127.0.0.1:8080`, `KLEI_AUTH_URL: http://127.0.0.1:8081` (as `desktop.yml`).
- Linux needs Xvfb for Electron (`xvfb-run`), and a system package list recorded at implementation.

**Acceptance Criteria**

**Given** the workflow
**When** read
**Then** steps are, in order: checkout, setup-node with npm cache keyed on `electron/package-lock.json`, `npm ci`, `npm run typecheck`, `npm test`, `npm run build` (renderer from 14.4 and main/preload), smoke launch, and "No tokens in the build output".

**Given** the smoke launch
**When** `KLEI_SMOKE=1` runs the built app (under `xvfb-run` on Linux)
**Then** the first `api_request` answers `signed_out`, the app exits 0 within 60 s, and a non-zero exit or a timeout fails the job.

**Given** the build output (`electron/build/`, `electron/dist/`)
**When** scanned for secret-shaped strings
**Then** a JWT-shaped string (`eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.`) or the PKCE test vector in the output fails the job; `electron/test/` is excluded from the scan, as the Tauri job scans only `dist` and the binary.

**Given** the hostile-renderer, contract, boundary and ported session tests
**When** `npm test` runs
**Then** they are included and must pass; skipped tests fail the job unless listed in `electron/test/allowed-skips.json` with a reason.

**Given** the workflow
**When** scanned by `electron/test/workflows.test.ts`
**Then** it has no secrets, `permissions: contents: read`, no reference to `desktop/` as a working directory, and does not run `npm` inside `desktop/`.

**Tasks**
- `.github/workflows/electron.yml`.
- `electron/scripts/smoke.mjs`: launches the built app, enforces timeout and exit code.
- `electron/scripts/scan-secrets.mjs`: the scan above.
- Workflow env sets `KLEI_DOWNLOAD_BASE_URL` to the placeholder `https://download.invalid/` plus a 43-character dummy segment so the 18.3 build check passes with no real URL.
- `electron/test/workflows.test.ts`: extend for this file.

**Dev notes**
- Port the intent of the steps in `.github/workflows/desktop.yml` (read only): `npm ci`, `npm test`, `npm run types:check`, build, smoke launch, "No tokens in the bundle".
- The Rust steps (`cargo test`, `cargo clippy`) have no Electron equivalent; ported behaviour tests replace them.
- Linux headless: Secret Service is absent; smoke uses memory credentials.

**Testing**
- Not run here. The first real run is the evidence. A failing run is a finding for the owning story, not a reason to edit `desktop.yml`.

**Prototype unchanged check**
- Require the 14.1 gate. No `desktop/**` path appears in the workflow triggers or steps. Existing `desktop.yml` does not run for an `electron/**`-only change (its paths do not match).
