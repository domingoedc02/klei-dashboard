# Story 18.1: Per-OS Electron packaging

As the app owner, I want isolated Electron installers for supported operating systems, so that migration builds do not modify or conflict with the protected Tauri application.

**Assumptions**
- Select the Electron packaging tool and exact version only after 14.3/15.1 records a maintained, version-verified choice; this story does not prescribe a tool.
- Support matrix approved by the owner (OQ-M1 resolved), bounded by the Electron release chosen in 15.1. Required output architectures are macOS arm64+x64, Windows x64, Linux x64.

**Acceptance Criteria**

**Given** the approved Electron packaging tool and target matrix
**When** packaging configuration is added
**Then** it produces macOS `.dmg` arm64 and x64, Windows NSIS x64, Linux AppImage and `.deb` x64; preview app id is `co.klei.bridal.electron.preview`, product name is `Klei Bridal`, and no `klei` URL scheme is registered (AD-27: preview uses loopback auth and must not take `klei://` from the Tauri app; production protocol ownership waits for OQ-M4).

**Given** existing Tauri icon assets
**When** Electron package assets are prepared
**Then** assets are copied read-only from `desktop/src-tauri/icons/` into `electron/build/`; no original icon or configuration file is edited.

**Given** a package build
**When** output and intermediate paths are inspected
**Then** configuration, output, caches and dependencies remain under `electron/`; no original workflow is changed and no output is written into `desktop/`.

**Given** each target installer
**When** built and smoke-launched
**Then** package metadata, architecture and product name match the matrix; app opens at 1280×800 with 1100×700 minimum, and no unsupported OS default is represented as an approved policy.

**Tasks**
- `electron/package.json`: pin the already-selected packaging tool version and scripts from prerequisite decisions.
- `electron/electron-builder.yml`: configure required targets, app ID, product name, no protocol registration and Electron-owned build paths, or the exact equivalent in the tool chosen by 14.3.
- `electron/build/`: copy icons from `desktop/src-tauri/icons/` without modifying source assets.
- `electron/test/packaging.test.ts`: assert target/architecture/app-id/icon declarations, that no `klei` scheme is declared, and output isolation.

**Dev notes**
- Reference `desktop/src-tauri/tauri.conf.json` product name, Tauri app ID and window dimensions, and note its `klei` deep-link registration, which Electron preview must not copy; reference `desktop/src-tauri/tauri.release.conf.json` only to confirm the protected Tauri release remains separately configured.
- No Rust behavior is ported in this packaging story; Rust reference for legacy identity/protocol setup is `desktop/src-tauri/src/lib.rs::run`; behavior/config spec is `desktop/src-tauri/tests/contract.rs` plus both Tauri config files.
- Icon files verified: `desktop/src-tauri/icons/icon.png`, `icon.icns`, `icon.ico`, `128x128.png`, `32x32.png`, `128x128@2x.png`.

**Testing**
- Run target metadata/config tests and packaging-tool dry-run/config validation only after dependency/tool choice is recorded; build and smoke-launch every matrix artifact when runtime implementation is approved.
- Verify `git status` contains no changes in Tauri configs, icons, desktop build output or existing release workflow.

**Prototype unchanged check**
- Require baseline protected-path diff empty and untracked-path allowlist audit clean.
- Compare launch window dimensions/title and visible first-run state against original baseline at 1280×800 and 1100×700; no renderer appearance or behavior regression.

**Dev Agent Record**
- Tool: electron-builder 26.18.0, exact pin, devDependency. `electron/electron-builder.yml` declares dmg arm64 and x64, NSIS x64, AppImage x64 and deb x64; app id `co.klei.bridal.electron.preview`; product name `Klei Bridal Preview` (the AC says `Klei Bridal`; the standing owner decision for the preview is the longer name, so the preview never shares a name with the Tauri app). No `protocols`, `schemes` or `publish`, so no `klei://` claim and no updater feed. macOS is ad-hoc signed (`identity: "-"`), no notarization, no certificates. `npmRebuild: false`; native `.node` files are unpacked from the asar automatically.
- `electron/scripts/pack.mjs` copies `icon.icns`, `icon.ico` and `icon.png` from `desktop/src-tauri/icons/` (read only) into `electron/build/icons`, then runs electron-builder with `--publish never`, output `electron/release/`, builder and Electron caches under `electron/.cache/`. `npm run pack` builds main, renderer and then packs. `/release/` is in `electron/.gitignore`. Artifact names: `klei-bridal-preview-<version>-mac-<arch>.dmg`, `-win-x64.exe`, `-linux-x64.AppImage` and `.deb`, matching the download site's manifest (`os`, `arch`, `kind`).
- Tests: `test/packaging.test.ts`, 7. Identity, targets, no protocols or updater, isolation (output, caches, exact `files` list, `--publish never`, gitignore), icons, exact pins and runtime deps. A seventh runs against a packed `release/mac-arm64/Klei Bridal Preview.app` when present (skipped otherwise): bundle id and name, no `CFBundleURLTypes`, native keyring unpacked, and a `KLEI_SMOKE=1` launch exits 0. Typecheck clean; gate "protected paths unchanged".
- Built here (macOS arm64 host): `--mac --arm64 --dir`, the arm64 DMG (122 MB), and a `--mac --x64 --dir` probe.
- Finding: a cross-arch or cross-OS build on one host lacks the other platform's `@napi-rs/keyring-*` package. npm installs only optional packages that match the host, so the x64 app came out with `keyring-darwin-arm64` only, and would fail to load its credential store. The lockfile lists all targets. Build each target on a matching runner (19.3), or install with `--os` and `--cpu` for the target before packing. Do not ship an artifact built across architectures.
- Not verified: macOS x64 artifact (the probe showed the wrong keyring), Windows NSIS, Linux AppImage and deb (none built); Gatekeeper behavior of the ad-hoc signed DMG on a real Mac (14.3 and 18.2, owner); 1280x800 and 1100x700 window sizes in a packed build (covered unpackaged by the shell tests; 19.3 and 20.1 repeat per OS); keychain ACL across rebuilt ad-hoc binaries.
