# Story 17.6: Webview behavior and persistence parity

As a Staff member, I want clipboard, rich-text paste, unsaved-review warnings and hash routing to work in packaged Electron, so that native-shell migration does not alter daily interaction or persist business content in Chromium storage.

**Assumptions**
- This is a test-and-configuration story only; original `desktop/` renderer code must remain unchanged. Any needed compatibility fix belongs under `electron/`.
- Review all renderer reads/writes for browser persistence; sentinel audit covers Chromium profile files and logs without retaining the sentinel.

**Acceptance Criteria**

**Given** Assistant, Viewer or Two-factor recovery codes
**When** a user invokes Copy in Electron
**Then** `navigator.clipboard.writeText` succeeds through the trusted secure application origin, preserves the existing success toast, and clipboard denial preserves the existing error copy.

**Given** plain text is pasted into `Composer`
**When** the paste handler runs
**Then** it inserts only `text/plain` through `document.execCommand('insertText')`, does not insert clipboard HTML, and keeps the caret/editor usable.

**Given** Review contains unsaved edits
**When** the window closes or navigates away
**Then** hash routing remains functional; in-app leave guard remains active and `beforeunload` presents the native unsaved-work confirmation; accepting or cancelling produces no silent loss.

**Given** a unique business-content sentinel is viewed, typed, copied and rendered
**When** the app closes and its Electron profile/cache/log/crash-dump locations are inspected
**Then** the sentinel is absent from localStorage, sessionStorage, IndexedDB, cookies, Cache Storage, Chromium disk cache, logs and crash dumps; only the explicitly user-chosen archive export may persist business content. Swap files, hibernation images and OS-level page files are outside the app's control: the audit records them as a residual host risk (full-disk encryption recommended in the install guide), and where feasible the sentinel test also scans the OS temp directory and the packaged app's data directories.

**Given** the browser compatibility checks
**When** run against Electron's selected Chromium build
**Then** clipboard, `execCommand`, `beforeunload` and hash routing checks pass at the supported default/minimum window sizes, and no renderer code under `desktop/` is edited.

**Tasks**
- `electron/test/webview-behavior.test.ts`: exercise clipboard copy, plain-text paste, unsaved `beforeunload`, and hash navigation with the packaged Electron renderer.
- `electron/test/persistence-sentinel.test.ts`: place a unique sentinel in test-only business content, close the app, inspect all Chromium persistence stores/profile cache/log/crash-dump paths, assert no match, remove test artifacts.
- `electron/src/main/window.ts`: make only Electron-owned origin/cache/profile settings necessary to satisfy tests; do not enable storage or persistent cache as a workaround.

**Dev notes**
- Read-only behavior call sites: `desktop/src/assistant/Assistant.tsx`, `desktop/src/gallery/Viewer.tsx`, `desktop/src/settings/TwoFactor.tsx`, `desktop/src/inquiries/Composer.tsx`, `desktop/src/upload/Review.tsx`; hash routing is owned by the existing shell route code under `desktop/src/shell/`.
- Rust native behavior reference: `desktop/src-tauri/src/lib.rs::run` handles the native window drag/drop lifecycle; clipboard, editor commands and review unload warning have no Rust implementation and are specified by renderer behavior/tests.
- No `desktop/src-tauri/src/*_tests.rs` covers Chromium storage; acceptance is a fresh Electron sentinel audit, not inferred from Rust.

**Testing**
- Run the two Electron behavior/persistence tests on each supported OS build; record browser/Electron version, profile locations inspected and sentinel result.
- Do not run original screenshot capture entry points; use the Electron-owned harness and keep outputs under `electron/`.

**Prototype unchanged check**
- Require clean baseline diff for protected paths and ensure no untracked path outside the approved list; explicitly verify all listed renderer sources and tests remain identical to baseline.
- Compare interaction, focus, toasts and geometry at 1440×900, 1280×800 and 1100×700; zero new parity findings, no original parity artifacts overwritten.

**Dev Agent Record**
- Renderer audit (`desktop/src`, read-only): clipboard writes in `Assistant.tsx:85`, `Viewer.tsx:62`, `TwoFactor.tsx:16`; `execCommand` in `Composer.tsx` (paste as `insertText` of `text/plain` at 237, format, link, paragraph separator); `beforeunload` in `Review.tsx:113`. No `localStorage`, `sessionStorage`, `indexedDB` or cookie use anywhere.
- Found by the first test run: Electron refused `navigator.clipboard.writeText` because `PERMISSIONS_ALLOWED` was empty. `boundary.ts` now allows exactly `clipboard-sanitized-write`; clipboard read, notifications, media, USB and the rest stay denied (the hostile-renderer test still passes). `boundary.test.ts` pins the one-entry list.
- Found by design: Electron closes a window with a `beforeunload` handler silently. `window.ts` handles `will-prevent-unload` with a native Keep reviewing / Leave box using the in-app dialog's words; Keep stays, Leave closes.
- Tests: `webview-behavior.test.ts` (4, real Electron on `app://klei/`: copy gives "Copied" and the OS clipboard holds the text; paste inserts only `text/plain`; dirty close asks and keep or leave work; hash routing stays in one document). `persistence-sentinel.test.ts` gained 2: the scan finds a sentinel in contents (UTF-8 and UTF-16), nested files and names; a real run types, pastes, copies, renders and stores a unique sentinel in localStorage, sessionStorage, a cookie, Cache Storage and IndexedDB (each confirmed accepted), closes, and finds it in no file of the profile or the temp directory. `launch.ts` is the shared launcher. Page code is `test/fixtures/behavior/`, which repeats the original calls line for line.
- Full suite 189 pass, 0 fail; typecheck clean; gate passes.
- Not verified: the real renderer's Copy buttons and Review screen (need a signed-in session; 20.1), a packaged build (the tests run the built main unpackaged), Windows and Linux (run the same two files per OS in 19.2 and 20.1), Chromium crash dumps and OS swap (a crash was not provoked; swap is out of scope per the AC).
