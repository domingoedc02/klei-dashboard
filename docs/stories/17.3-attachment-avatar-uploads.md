# Story 17.3: Attachment and avatar uploads

As a Staff member, I want to attach inquiry files or replace my avatar through native file selection, so that uploads retain existing limits and never expose local paths to the renderer.

**Assumptions**
- Attachment and avatar operations use the existing API session, native dialogs and `{stored,rejected,cancelled}` summary; no resend, cancellation or progress is added.
- `attachment` requires a 36-character hex/dash inquiry ID, accepts any file type up to 20 MiB, and processes selected files sequentially.

**Acceptance Criteria**

**Given** `attachment` is invoked with an invalid target ID
**When** validation runs
**Then** it rejects as `bad_request` before reading files or making a request.

**Given** a valid inquiry and selected files
**When** attachment upload runs
**Then** files above 20 MiB are rejected as `size`; unreadable files are rejected as `unreadable`; each eligible file is sent sequentially as multipart `file` to `/api/v1/inquiries/{targetId}/attachments` with a fresh random 16-byte lowercase-hex `Idempotency-Key`; 413 maps to `size`, 422 to `unreadable`, 403 to fatal `no_access`, and any other unexpected result to fatal `failed`. A network error is not retried.

**Given** a selected attachment succeeds
**When** the response is processed
**Then** its returned ID is in `stored`; a missing response ID fails as `failed`; no path or file bytes cross into renderer IPC.

**Given** `avatar` is invoked
**When** the Photos picker returns one file
**Then** the file is limited to 2 MiB, PUT as multipart `file` to `/api/v1/me/avatar` with no idempotency key; success returns `stored:['avatar']`, 413 is `size`, 415 is `type`, 403 is fatal `no_access`, unreadable input is `unreadable`, and other errors are `failed`.

**Given** either native dialog is dismissed
**When** the command resolves
**Then** it returns `cancelled:true` without a request; unknown `upload_files` kinds reject as `bad_request` with `unknown upload kind`.

**Tasks**
- `electron/src/main/uploads.ts`: port sequential attachment and avatar logic, target/size validation, fresh key generation and response mapping.
- `electron/src/main/commands.ts`: native multi-file attachment dialog; single-file avatar picker with `Photos` filter; preserve dismissed-dialog semantics.
- `electron/src/preload/bridge.ts`: dispatch existing `attachment` and `avatar` calls, exposing summaries only.
- `electron/test/uploads.test.ts`: add cases for ID validation, size/unreadable handling, key freshness/shape, all status mappings, no retry, avatar no-key behavior and dialog cancellation.
