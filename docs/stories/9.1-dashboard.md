# Story 9.1: Dashboard

As a signed-in User,
I want a home screen with the four numbers and lists I check first,
So that I see what needs attention and can jump straight to it.

**Assumptions**
- Four widgets: Recent uploads, Unread inquiries, AI processing status, Total gowns. Each fails and loads on its own (UX-DR7).
- A9 (Gate 5, closed): Gown figures need `PERM_VIEW_GALLERY`; Inquiry figures need `PERM_REPLY`. A widget the caller may not see is absent, not an error. A User whose Role holds no Permission cannot sign in (Story 1.6), so the Dashboard never renders empty.
- The UX spec's D1 role line "V gets Forbidden" is superseded by this rule: a default Viewer (`PERM_VIEW_GALLERY` only) sees the Gown widgets.
- "Recent uploads" shows the five newest Gowns with mosaic, name and date. "New this week" uses `DayBucket.lastN(7)`.
- AI processing status reflects the caller's own batch phase; for others it shows "Idle".
- The Dashboard is the default start page (Story 6.3).

**Acceptance Criteria**

**Given** `GET /dashboard`
**When** called with a valid token
**Then** it returns `{recentGowns[5]?, totalGowns?, newThisWeek?, aiStatus, inquiries?}` where the Gown fields are present only with `PERM_VIEW_GALLERY` and `inquiries` (`unread`, `new`, three latest) only with `PERM_REPLY`; `totalGowns` equals the Gallery `total` for no filters.

**Given** `aiStatus`
**When** the caller has an active batch
**Then** it holds phase, step name and progress, and a link target (Upload processing or review); otherwise `idle`.

**Given** D1
**When** it renders for Admin or Staff
**Then** the four widgets show: Recent uploads (rows or "No uploads yet" with **Upload photos**), Unread inquiries (count plus three latest or "You're all caught up"), AI processing status (phase line with progress, "AI is idle"), Total gowns (number with "+N this week"); each widget links to its screen; counts use the sidebar badge poll.

**Given** a default Viewer
**When** D1 renders
**Then** only Recent uploads, AI status (always idle) and Total gowns show, and no Inquiry element exists in the DOM.

**Given** a Role with `PERM_REPLY` but without `PERM_VIEW_GALLERY`
**When** D1 renders
**Then** only the Inquiry widgets and AI status show, and no Gown element exists in the DOM.

**Given** one widget's data fails
**When** the response has an error for it
**Then** only that widget shows its error block with Retry; the rest render. (The endpoint returns per-widget `error` fields rather than failing as a whole.)

**Given** loading
**When** the screen opens
**Then** flat skeletons at final size show (no layout shift when data arrives).

**Given** the empty Workspace
**When** nothing exists
**Then** the Dashboard shows "No uploads yet" with the empty-state art and **Upload photos** (for a Viewer, a sentence only).

**Given** NFR-2
**When** the 5,000-Gown benchmark runs (Story 9.4)
**Then** `GET /dashboard` p95 is within the "Gallery page" target.

**Given** the leak suite
**When** extended
**Then** nothing new is stored.

**Tasks**
- Backend: `DashboardController`, `DashboardService` (reuses `GownQueryService`, inquiry counts, upload status), tests.
- Desktop: Dashboard route, widget components, per-widget error handling, tests, axe.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && (cd src-tauri && cargo test)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: dashboard totals match Gallery total; a Viewer-token call has no `inquiries`, and a token without `PERM_VIEW_GALLERY` has no Gown fields).

## Dev record

**Assumptions**
- "New this week" is Gowns whose creation-day HMAC is in `DayBucket.lastN(7)`; `totalGowns` is the Gallery's unfiltered `total`.
- AI status is the caller's own batch only: `idle` (no batch or EMPTY), `processing` (with step 1-4, done, total), `review`, `error`. Other Users' runs show as idle.
- `inquiries.latest` is the three newest New Inquiries, fetched only when something is unread.
- Absent means not permitted: Gown fields need `PERM_VIEW_GALLERY`, `inquiries` needs `PERM_REPLY` (`@JsonInclude(NON_NULL)`); `aiStatus` and `errors` always present. This supersedes the UX spec's "Viewer gets Forbidden" (A9).
- `errors` names failed widgets (`recent`, `total`, `inquiries`, `ai`); the call itself still answers 200. A failed Gown page marks both `recent` and `total`.
- Dashboard was already the default start page (6.3).

**Done**

- AI status of other Users' runs is not shown.
