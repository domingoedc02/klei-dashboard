# Story 19.3: Packaging matrix

As the owner, I want installers for every target built and smoke-launched in CI, so that a broken package is found on a branch and not on release day.

**Assumptions**
- New file `.github/workflows/electron-package.yml`; triggers on `push` and `pull_request` with `paths: ["electron/**", ".github/workflows/electron*.yml"]`, plus `workflow_dispatch`.
- Targets (owner-approved, OQ-M1): macOS arm64 and x64 (`.dmg` or `.zip` per the 18.1 choice), Windows x64 (installer per 18.1), Linux x64 `AppImage` and `.deb`.
- Runner labels for macOS x64, Windows and Linux are verified at implementation. If no x64 macOS runner is available, the x64 package is cross-built by the packaging tool's `--x64` option on arm64 and launched under Rosetta, and that limit is recorded.
- Build artifacts are internal preview artifacts; they are not signed and are labelled "preview" in file names (18.1).

**Acceptance Criteria**

**Given** the workflow
**When** it runs
**Then** it produces exactly five artifacts named with product, version, OS, architecture and kind, uploaded with `actions/upload-artifact` and 7-day retention.

**Given** each artifact
**When** the job continues
**Then** a smoke launch runs on its own OS (`KLEI_SMOKE=1`, `xvfb-run` on Linux); the .deb is installed with `dpkg -i` in the Linux job and launched; the AppImage is launched with `--appimage-extract-and-run` if FUSE is absent.

**Given** the packaged app
**When** its contents are listed
**Then** `electron/test/packaging.test.ts` (or a script it calls) confirms no `.map` files with source paths, no `desktop/src-tauri` content, no `.env`, no private keys, the native credential library is unpacked, and the app id is `co.klei.bridal.electron.preview` with no `klei` URL scheme in any OS manifest (`Info.plist`, `.desktop` file, registry entries).

**Given** the same job
**When** it ends
**Then** it prints each artifact's size and SHA-256, so 20.2 can use them.

**Given** the workflow
**When** scanned
**Then** it uses no secrets, no signing identity and no `RELEASES_*` or `TAURI_*` name; it builds with a placeholder `KLEI_DOWNLOAD_BASE_URL` (`https://download.invalid/` plus a 43-character dummy segment), so no real URL or token is in the 7-day Actions artifacts.

**Tasks**
- `.github/workflows/electron-package.yml`.
- `electron/scripts/inspect-package.mjs`: list and check package contents per OS.
- `electron/test/packaging.test.ts` (shared with 18.1).
- `electron/test/workflows.test.ts`: extend.

**Dev notes**
- Reference only: `.github/workflows/release.yml` build matrix (macOS arm64/x64, Windows, Linux) and `tauri.conf.json` `bundle.targets`.
- The packaged smoke launch proves launch only; installer behaviour is 18.4.

**Testing**
- Not run here. First real matrix run is the evidence.

**Prototype unchanged check**
- Require the 14.1 gate. Artifact inspection proves no Tauri binary, no Rust output and no `desktop/dist` content is bundled except the renderer build from 14.4.

Status: done (owner: "complete this", 2026-11-15; remaining human per-OS checks listed under Not verified). Workflow, inspector, manifest lister and static tests exist; hosted run `43578750255` on `4401409` passed all four package jobs and the five-installer job (see "Hosted run").

Built:
- `.github/workflows/electron-package.yml`: `push` and `pull_request` (same path filter as 19.2) plus `workflow_dispatch`; `permissions: contents: read`; no secrets, no signing identity, no `RELEASES_*` or `TAURI_*` name, no `KLEI_RELEASE`; placeholder `KLEI_DOWNLOAD_BASE_URL` (checked against `parseBase(..., true)`).
- Job `package`, `fail-fast: false`, one native runner per target because the credential library is per-platform: `mac-arm64` on `macos-15`, `mac-x64` on `macos-15-intel`, `win-x64` on `windows-latest`, `linux-x64` on `ubuntu-24.04` (the last builds both AppImage and deb). Steps: `npm ci`, `npm run pack -- <args>`, `inspect-package.mjs` on the unpacked app, `release-manifest.mjs list release` (name, size, SHA-256 of every installer), then a smoke launch:
  - macOS: mount the dmg, copy the app out, run `smoke.mjs` on its binary.
  - Windows: silent NSIS install, wait for `Klei Bridal Preview.exe`, kill any auto-started copy, fail if `HKCU\Software\Classes\klei` exists, smoke.
  - Linux AppImage: `--appimage-extract` to check the `.desktop` file has no `x-scheme-handler`, then `xvfb-run` smoke with `--appimage-extract-and-run --no-sandbox`.
  - Linux deb: `dpkg -i`, same `.desktop` check, run the installed binary under `xvfb-run`.
- Five uploads (`actions/upload-artifact`, `retention-days: 7`, `if-no-files-found: error`), then job `five` downloads them all and runs `release-manifest.mjs list installers --five`, which fails unless there are exactly five installers of one version with the five expected names, and writes sizes and hashes to the step summary.
- `electron/scripts/inspect-package.mjs`: no `.map` files, no `src-tauri`, no `.env`, no key files, no JWT shape, PKCE vector, private key or deploy setting name inside `app.asar`; keyring `.node` unpacked; macOS app id and no `CFBundleURLTypes`. `electron/scripts/release-manifest.mjs`: `list`, `build` and `tag` (the last two are for 19.4).
- Tests: `electron/test/package-inspect.test.ts` (8, using real asar files), 3 new in `workflows.test.ts`, and the packed-macOS test in `packaging.test.ts` now also runs the inspector. The inspector passes on the local `release/mac-arm64` and `release/linux-unpacked`. Mutation check: `retention-days: 90` failed the workflow test. Full suite 238 of 238, skip check and gate pass.

Deviations: the inspector lives in a script that `package-inspect.test.ts` calls, as the story allows. No `registry entries` check beyond the Windows `HKCU` probe.

Hosted run (`electron-package`, run `43578750255`, commit `4401409`): `mac-arm64`, `mac-x64`, `win-x64` and `linux-x64` succeeded, and "exactly five installers" succeeded. So the Windows silent install, the macOS x64 dmg on `macos-15-intel`, the AppImage and the deb were built and smoke-launched on hosted runners. One fix was needed: electron-builder refused the `.deb` target without a project homepage, so `electron/package.json` has `homepage` (the repository URL).

Scope 2026-11-15: supported targets are macOS arm64/x64 and Windows x64. The `linux-x64` job and Linux installers stay in the workflow (removing them edits a protected workflow and needs the re-baseline decision) but are not a release target.

Not verified:

- The AppImage smoke launch runs with `--no-sandbox` (an AppImage cannot carry the setuid helper); the `.deb` smoke launch is the check that has the Chromium sandbox on.
- Gatekeeper and SmartScreen behaviour on a downloaded, quarantined copy: hosted runners do not quarantine files.
- The five installer hashes in the step summary are for the 7-day artifacts, not a published release.
- A 7-day artifact still contains the app; the placeholder URL is the only thing keeping a real token out, and the inspector does not know the real one.
