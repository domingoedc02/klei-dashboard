# Story 13.1: Parity harness: capture, diff, probe

As a developer,
I want one repeatable command that renders every screen and state of the prototype and the desktop app side by side and flags overlap, clipping and overflow,
So that layout bugs show up in a screenshot before a story is called done (Epic 11 ended every story with "Not verified: manual side-by-side").

**Assumptions**
- Built and committed in `8bffb62` (Phase 1). This story records it, closes the loose ends the audit found, and documents it. No product code changes.
- Playwright (`@playwright/test` 1.64.1), `pixelmatch` and `pngjs` are devDependencies of `desktop/` only. The backend never sees them.
- Layout: `desktop/scripts/capture.mjs` (`--side prototype|desktop|both`, `--only <substring of id-state>`), `diff.mjs`, `shots/{common,screens,fixtures,tauri-shim,gown-art,probe,desktop}.mjs`, `shots/desk/*.mjs`. Output in `docs/planning-artifacts/ui-parity/{prototype,desktop,diff}/`, plus `report.json`, `geometry.json`, `copy.json`.
- Prototype-only chrome (`.stsel`, `.seg[aria-label="Wireframe state"]`, `[data-act="toggle-role"]`) is hidden on the prototype side in every capture. The prototype `auth/*` pages are backend templates and are out of scope.
- Capture facts: 1440x900, `deviceScaleFactor 1`, `reducedMotion: reduce`, desktop clock fixed (`page.clock.setFixedTime`), `klei-img://**` routed to the same SVG gown art the prototype draws, fixtures mirror prototype `js/data.js`. A full run takes about 32 s; a one-screen desktop run is `node scripts/capture.mjs --side desktop --only <x>`.
- Gate = zero geometry findings plus the lead's read of every pair. Pixel % is a report metric only.
- Audit findings that touch the harness: UR-14 and UR-15 (the `upload-review-photos-selected` and `upload-review-combo-open` desktop captures show a per-photo menu and the topbar Actions menu, not the states their names promise): this story marks them `pending: 13.8`; 13.8 makes them real. UR-21 (no long-name fixture, so the Low pill collision is unproven): this story adds `upload-review-long`; 13.7 closes the row. ST-31/ST-37 (Staff add-dialog and AI key fixtures) are fixed in 13.14 and IQ-09 (loading and filtered-empty captures open no thread) in 13.11, because each needs that screen's own fixture work.

**Acceptance Criteria**

**Given** the repo at `8bffb62`
**When** `cd desktop && npm run shots` runs
**Then** 53 prototype/desktop pairs plus the desktop-only states are written and the run ends with no `FAILED` PNG (the stale `settings-staff-add-dialog.FAILED.png` was removed in `60a241a`)

**Given** `desk/upload.mjs`
**When** a desktop capture is named `upload-review-photos-selected` or `upload-review-combo-open`
**Then** the capture shows that state. Until 13.8 ships the inline panel, these two desktop captures are listed in `screens.mjs` as `pending: '13.8'` and the diff report prints them as `pending`, not as a pair that matches or fails

**Given** a Review fixture with a 60-character gown name and a Low group
**When** `upload-review-long` is captured on both sides
**Then** the pair exists (prototype uses the same name via `proto-groups.json`), so UR-21 can be proven or cleared by geometry

**Given** `geometry.json`
**When** `npm run shots:diff` finishes
**Then** `report.json` also carries a per-screen count of geometry findings by kind and a `pending` list, so a story can read its own gate from one file

**Given** `docs/ops.md`
**When** a developer opens it
**Then** a short section "UI parity capture" lists the commands (`npm run shots`, `npm run shots:proto`, `npm run shots:diff`, `--only`, `--side desktop`), where the output goes, the probe kinds, and the rule that the backend never depends on Playwright
