# Story 11.2: Shell fidelity

As a Staff member,
I want the sidebar, top bar, search, bell, dialogs and toasts to match the prototype,
So that I find my way around by icons and labels and can skip to the content from the keyboard.

**Assumptions**
- Prototype: `index.html`, `js/core.js` (`K.shell`), `css/shell.css`. Current: `desktop/src/shell/Shell.tsx`, `SearchBox.tsx`, `Bell.tsx`, `ui.tsx`, `permissions.ts` (`NAV`), `styles.css`.
- First task is to confirm the rows marked "verify": the search empty-state copy in `SearchBox.tsx`, the unread dot in `Bell.tsx`, the exact `NAV` labels, and dialog focus handling in `ui.tsx`.
- Depends on Story 11.1 for tokens and `icons.tsx`.
- Brand moves from the top bar to the sidebar: a 'K' mark plus the text "Klei Bridal". `ux-spec.md` (text wordmark in the top bar) is corrected.
- Nav items: Dashboard, AI Upload, Gallery, Inquiries, Settings, each with an icon, under the eyebrow "Workspace". Active item: tint `rgba(0,0,0,.08)`, weight 600, accent icon. The Inquiries badge shows "{n} new" only when n > 0 (the app's current behaviour, kept; the prototype always renders it).
- Top bar padding 24, search max width 480 (was 548), profile button a pill with a 32 px avatar.
- `[ASSUMPTION]` Straight apostrophes in copy become curly ones only where the prototype uses them ("You’re all caught up").
- Demo-only prototype controls ("View as", "Wireframe state") are not built.
- Bell menu is 360 wide with a footer link "Go to Inquiries"; the unread dot is 8 px on the bell. Toast sits 24 px from the bottom and right, with a check icon on success.

**Acceptance Criteria**

**Given** the Shell
**When** `Shell.test.tsx` renders it
**Then** the first focusable element is a link "Skip to main content" that moves focus to the main region `#view` on activation.

**Given** the sidebar
**When** rendered
**Then** it shows the 'K' mark and "Klei Bridal", the eyebrow "Workspace", five nav items with icons, and the active item carries `aria-current="page"` and the active style.

**Given** unread inquiries n > 0
**When** the nav renders
**Then** the Inquiries item shows a pill "{n} new"; at n = 0 no pill renders.

**Given** the search field
**When** empty and focused
**Then** its placeholder reads "Search gowns, inquiries…" and its popup (max 6 hits, grouped Gowns / Inquiries) uses `--elev-raised`.

**Given** a query with no hits
**When** the popup renders
**Then** it shows `No results for “{q}”`, the line "Check the spelling or try a gown name, fabric, or client.", and a **Clear search** button that empties the field.

**Given** the bell
**When** there are unread notifications
**Then** an 8 px dot shows on the bell icon; opening the menu shows "Notifications", **Clear all**, the items, and a footer link **Go to Inquiries**; with none, it shows "You’re all caught up".

**Given** the profile menu
**When** opened
**Then** it shows name and role, **Profile settings**, **Sign out**, 280 wide, with the pill trigger.

**Given** a dialog from `openDialog`
**When** it opens
**Then** it is 480 wide with `--elev-raised`, the safe button has initial focus, Escape closes it, and focus returns to the opener.

**Given** `toast("…")`
**When** shown
**Then** it appears 24 px from the bottom and right inside a `role="status"` region, success toasts carry a check icon, the error variant keeps its red style, and it clears after 3200 ms.

**Given** buttons
**When** rendered
**Then** `.btn` has radius 4, weight 600, padding 8 16; the secondary button has the filled `rgba(0,0,0,.05)` background.

**Given** axe on the Shell
**When** `Shell.test.tsx` runs it
**Then** zero violations (landmarks, names for icon-only buttons, contrast).

**Decisions**
- Dialog focus, Escape and focus return already worked (`DialogHost`: danger focuses Cancel, else confirm); kept and covered by a test. The dialog is 480 wide on `--elev-raised` since 11.1.
- Skip link is a hash link with `preventDefault` because the hash is the router. Toast region has `role="status"` only while a toast shows; an always-present live region would match every `getByRole('status')` query in other screens' tests.
- Error toasts keep `role="alert"` and the red style, no check icon. `aria-label` "Notifications, {n} unread" on the bell kept.
- Demo-only "View as" / "Wireframe state" not built.

**Not verified**: keyboard-only pass on macOS; side-by-side with the prototype; in-browser axe on the desktop Shell (jsdom has no layout, so `color-contrast` is off in `Shell.test.tsx`; contrast is covered by `styles.test.ts`).
