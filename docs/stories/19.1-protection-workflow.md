# Story 19.1: Protection workflow

As the owner, I want a CI job that fails whenever a pull request touches the protected Tauri app, whatever else it changes, so that path filters can never hide a forbidden edit.

**Assumptions**
- New file `.github/workflows/electron-protect.yml` is the only workflow file added by this story. It is an allowed addition (MFR-1). Existing workflows are not edited; `desktop.yml` keeps its `paths` filter (`desktop/**`, `docs/api/openapi.json`, `.github/workflows/desktop.yml`) and runs on push only.
- The job runs the gate script from 14.1 (`electron/scripts/protected-paths.mjs`); no logic is written inline in YAML.
- A pull request that rewrites the protection workflow itself can weaken its own check. Mitigation is outside the repository files: make the job a required status check and require review for `.github/workflows/electron-protect.yml` and `electron/scripts/protected-paths.mjs` (owner action, listed in Open Questions).

**Acceptance Criteria**

**Given** `.github/workflows/electron-protect.yml`
**When** read
**Then** its `on:` block has `pull_request` and `push` with **no** `paths`, `paths-ignore`, `branches-ignore` or `tags-ignore` keys; `permissions: contents: read`; no secrets; no `pull_request_target`.

**Given** the job
**When** it runs
**Then** it checks out with `fetch-depth: 0`, installs Node (version recorded in 15.1), runs `node electron/scripts/protected-paths.mjs`, and fails when the script exits non-zero.

**Given** a branch that edits `desktop/package.json`, or `.github/workflows/desktop.yml`, or adds `backend/x`
**When** the job runs
**Then** it fails and prints each offending path.

**Given** a branch that adds only `electron/**`, `docs/**` and `.github/workflows/electron*.yml`
**When** the job runs
**Then** it passes.

**Given** the workflow file
**When** scanned by `electron/test/workflows.test.ts`
**Then** the test asserts the keys above, the absence of path filters, and that the only added workflow files match `electron*.yml`.

**Tasks**
- `.github/workflows/electron-protect.yml`.
- `electron/test/workflows.test.ts`: parse YAML (dev dependency pinned in `electron/package.json`), assert the rules; reused by 19.2 to 19.4.
- Document the required-status-check setting in `electron/BASELINE.md` as an owner action.

**Dev notes**
- Existing reference: `.github/workflows/desktop.yml` (read only).
- Do not use third-party actions beyond `actions/checkout` and `actions/setup-node`, pinned to a full commit SHA at implementation.
- Same script runs locally (14.1) and in CI, so there is one definition of "unchanged".

**Testing**
- Run `electron/test/workflows.test.ts`. Run the job on a throwaway branch with a deliberate edit to a protected path and confirm it fails; then delete the branch. Not run in this documentation task.

**Prototype unchanged check**
- This story adds a new workflow file only. Require `git diff --name-status 51949da… -- .github/workflows` to show only added `electron*.yml` files (status `A`), and no change to any existing workflow (the 14.1 script enforces this).
