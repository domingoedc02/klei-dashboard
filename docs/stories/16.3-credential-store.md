# Story 16.3: Credential store, `sign_out` and `session_only`

As a User, I want my refresh token kept in the OS credential store, removed when I sign out, and kept only in memory if I choose "Continue without saving", so that no token ever sits in a file.

**Assumptions**
- The library comes from the 14.3 spike 1 decision (`@napi-rs/keyring` recommended, version pinned after web check). If spike 1 finds no equivalent on an OS, this story stays blocked for that OS.
- Preview credential entry: service `co.klei.bridal.electron.preview`, account `refresh-token`. The Tauri entry `co.klei.bridal` is never read, written or deleted by Electron.
- There is no plaintext fallback, no `safeStorage` + file, no `localStorage`. Memory mode is chosen only by the User ("Continue without saving"), by `KLEI_SMOKE=1`, or in development builds (as `lib.rs` does with `KLEI_KEYCHAIN=os` to force the real one).

**Acceptance Criteria**

**Given** the credential interface `load`, `store`, `clear`
**When** the OS store has no entry
**Then** `load` returns none; `clear` on a missing entry succeeds; `store` overwrites; other OS errors map to a typed error, logged without the token.

**Given** `session_only`
**When** invoked
**Then** from then on all credential calls use process memory; nothing is written to the OS store; the next launch shows sign-in again.

**Given** the OS store is unavailable or denies access
**When** `sign_in` or any refresh needs it
**Then** the command fails `keychain_unavailable` "keychain unavailable"; no access token is kept, and no file is written.

**Given** `sign_out`
**When** invoked
**Then** the in-memory access token and any pending sign-in are dropped first; if a refresh token exists, `POST /api/v1/auth/logout` with `{ refreshToken }` is attempted and its failure is ignored (works offline); then the credential is cleared, and a clear failure returns `keychain_unavailable`.

**Given** the whole Electron main source
**When** scanned
**Then** it has no write of a token to any file, `localStorage`, `electron-store`, `safeStorage` or log line, and the credential module is the only file importing the keyring library.

**Tasks**
- `electron/src/main/keychain.ts`: interface, `OsKeychain`, `MemoryKeychain`, `SwitchKeychain` with `useMemory()`.
- `electron/src/main/session.ts`: `signOut`.
- `electron/src/main/commands.ts`: `sign_out`, `session_only`.
- `electron/test/keychain.test.ts`: port of `memory_mode_round_trips_without_the_os_and_can_be_switched_on`; fake OS store for the typed-error cases.
- `electron/test/session-signout.test.ts`: `sign_out_revokes_on_the_server_and_empties_the_keychain`, `sign_out_works_offline`.
- `electron/test/persistence-sentinel.test.ts`: static scan plus (in real runs) a profile-directory scan that finds no token (shared with 17.6).
- Real-OS credential check on macOS, Windows and Linux; recorded in the 14.3 spike note.

**Dev notes**
- Port from `desktop/src-tauri/src/keychain.rs` and `session.rs::sign_out`.
- A library that links native code must be unpacked from the asar archive in packaging (18.1).
- Linux: a Secret Service provider may be absent (headless CI). Keep fail-closed; smoke runs use memory mode.

**Testing**
- Run the unit tests; real-OS store tests are manual or self-hosted runs and are not part of the documentation task.

**Prototype unchanged check**
- Require the 14.1 gate. The Tauri keychain entry must be unchanged after an Electron sign-in and sign-out (check on a machine with both).

**Dev Agent Record**
- `@napi-rs/keyring` 2.1.2 added exact-pinned to `electron/package.json`. `main/keychain.ts` is the only importer (sentinel test): `Keychain` now async (`load/store/clear`), `OsKeychain(service)` over `AsyncEntry(service,'refresh-token')` loaded lazily on first use, `MemoryKeychain(broken?)`, `SwitchKeychain(os, memory).useMemory()`. OS errors become `KeychainError('keychain unavailable')`; only the OS message is logged, never the token. A failed open is retried next call. Clearing a missing entry is success.
- Service name is `KEYCHAIN_SERVICE = co.klei.bridal.electron.preview` in `identity.ts`, never the Tauri `co.klei.bridal`.
- `index.ts`: memory mode when `KLEI_SMOKE=1` or unpackaged unless `KLEI_KEYCHAIN=os` (mirrors `lib.rs`).
- `session.ts`: `signOut()` drops the access token, loads the stored token (a load error is ignored), best-effort `POST /api/v1/auth/logout`, then clears; a clear failure is `keychain_unavailable`. All keychain calls in `session.ts` are awaited.
- `commands.ts`: `sign_out` and `session_only` are real and return `null`; `createHandlers` gains `useMemory`.
- Tests: `keychain.test.ts` (6), `session-signout.test.ts` (6), `persistence-sentinel.test.ts` (3: keyring import only in `keychain.ts`; no `localStorage`/`sessionStorage`/`indexedDB`/`document.cookie`/`safeStorage` in any source; refresh token only in `keychain.ts` and `session.ts`). `preload-electron.test.ts` probe after reload now expects `sign_out` to resolve.
- Real macOS login keychain round trip with the real library (missing, store, load, clear, clear-missing) ran once against a throwaway service `co.klei.bridal.electron.preview.test`; the entry was cleared.
- Full suite 100 pass, typecheck clean, gate passes.
- Not verified: Windows and Linux credential stores; macOS ACL behavior across rebuilt ad-hoc binaries; the Tauri entry untouched is by service name only (no run against a real Tauri sign-in); profile-directory token scan (needs a real signed-in run, owned by 17.6); packaging of the native module (18.1).
