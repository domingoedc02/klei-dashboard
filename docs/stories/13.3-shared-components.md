# Story 13.3: Shared components and formatters

As a Staff member,
I want buttons, pills, dialogs, empty states and dates to look and read like the prototype,
So that every screen story reuses one set of parts.

**Assumptions**
- Prototype source: `css/base.css` and `css/screens.css` component rules (`.btn*`, `.pill*`, `.banner`, `.card`, `.field`, `.dlg`, `.menu`, `.empty`, `.skel`, `.toast`), `js/core.js` (`K.dlg`, `K.illo`, `K.fmt*`).
- This story fixes the shared pieces only. Screen layouts stay in their own stories. Where a row lists a pill, dialog or empty state (SH-07, SH-10, SH-15, SH-19, UR-12, UR-19), the shared part is fixed here and the screen story re-checks the pair.
- **Date formatter depends on decision D1 (IQ-08), pending the user's answer.** Assumed option (a), the recommendation: keep the user's date-format preference for absolute dates (`format.ts`: DD/MM/YYYY, YYYY-MM-DD, MM/DD/YYYY) and add a list/relative formatter for `Today`/`Yesterday`/short month (`Nov 3`, `Jun 14, 2027`, `Oct 2026`, `9:42 AM`). If the answer is (b) the literal prototype style replaces the preference in lists; if (c) the formatter is dropped and every date row (DB-10, SH-14, GL-02, VW-05, IQ-08, CP-03, ST-28) becomes `accepted deviation`.
- Dialogs: prototype `K.dlg` card 480 px wide, title ~20 px, body ~16 px muted, buttons 36 px high and right-aligned with the secondary action first (Keep reviewing) and the destructive one last (Discard batch, red).

**Acceptance Criteria**

**Given** the Low, Medium and High confidence pills (UR-12)
**When** they render
**Then** High is green, Medium neutral grey, `Low · check` the `pill-warn` colours from `base.css`. The pill keeps its size and never shrinks under a long name

**Given** the profile pill, search-none state, notifications-empty state and Assistant suggestion chips (SH-07, SH-10, SH-15, SH-19)
**When** they render
**Then** each matches its prototype pair: initials avatar `EP` + name + chevron; centred illustration and blue `Clear search`; `You're all caught up` with the prototype art and body; stacked pill chips shown only on the greeting

**Given** a confirm dialog such as Discard this batch? (UR-19)
**When** it opens
**Then** width 480 px, title ~20 px, body ~16 px muted, buttons 36 px high and right-aligned in the prototype order. `Dialog` tests still prove focus trap and Esc

**Given** a date in a list or card (D1 assumption (a))
**When** the formatter is called with a value from today, yesterday, this year and another year
**Then** it returns `9:42 AM`, `Yesterday`, `Nov 3`, `Jun 14, 2027`; with the preference set to DD/MM/YYYY an absolute date still uses that format. `format.test.ts` covers each branch and the month-year form `Oct 2026`

**Given** the shared `.card`, `.field`, `.banner`, skeleton and empty-state classes
**When** a screen story uses them
**Then** values equal the prototype (card padding 24, radius 12, no shadow; banner neutral grey; empty-state art 144 px). `styles.test.ts` asserts the card, banner and art-size rules

**Given** the story's screens are captured on both sides
**When** `node scripts/capture.mjs --side both --only {only}` and `npm run shots:diff -- --only {only}` run
**Then** `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `dialog-scroll` or `dialog-overflow` for the desktop side of these screens (`text-ellipsis` only where the prototype truncates the same text), and the run logs no `UNMOCKED` request and no page or console error

**Given** every audit row listed above
**When** the story is done
**Then** the row's Status in `docs/planning-artifacts/ui-parity/audit.md` is `closed` with the fix commit and the after-screenshot path, or the row says `accepted deviation` with the decision it follows (D1 to D5 in the change proposal) and the reason

**Given** each prototype/desktop pair of the story
**When** the lead reads the montage in `ui-parity/diff/`
**Then** the Dev record has one line per pair: `match`, or the remaining difference and why it is fixture-only noise (SVG gown art, fixed clock, mock data). Pixel % is recorded in the Dev record as a trend and is not a gate
