# Story 7.1: Create and list Inquiries

As a Staff member with Reply to inquiries,
I want to see client inquiries in an inbox with status and unread state,
So that I know who to answer first.

**Assumptions**
- Inquiries enter through `POST /inquiries` by an authenticated User token only (FR-24). Public intake is deferred. This endpoint is also what the leak suite and demo seed use.
- Client is matched by `CLIENT_EMAIL` blind index; a new email creates a Client.
- The first Message of a new Inquiry has direction `in` and no author.
- `seq` moves to a fresh `nextval` only by `InquiryStateService.touch()` on a new Message (architecture §4.3).
- Status values: New, Replied, Closed. `status_bidx` and `unread_bidx` are written by the entity listener. Unread is one flag per Inquiry for the whole Workspace (A3).
- The sidebar "N new" count comes from `GET /inquiries/count` and polls every 30 s (ADR-6).
- Viewer: no Inquiries (A-UX16); the endpoints require `PERM_REPLY`.
- Seed data for demo is a dev-only script `infra/ci/seed.sh` calling the API; no production seed.

**Acceptance Criteria**

**Given** `POST /inquiries {clientName, clientEmail, subject, body}` with `PERM_REPLY` and optional `Idempotency-Key`
**When** valid
**Then** a Client is matched or created, the Inquiry (status New, unread) and its first Message are stored encrypted, the preview (first 120 characters) is stored encrypted, term rows are written for client name and subject (`TermIndexer`), a Notification is requested through `NotificationPort`, and the response is 201; invalid email or oversize body (over 20,000 characters) returns 422.

**Given** `POST /inquiries/query {status, before, limit}`
**When** called
**Then** it returns `{items, next}` newest activity first by `seq`, limit 25, each item with client name, subject, preview, time, status and unread; `status` filters through `status_bidx` (All, New, Replied, Closed).

**Given** `GET /inquiries/count`
**When** called
**Then** it returns the number of Inquiries with status New and unread through `status_bidx` and `unread_bidx`.

**Given** I1
**When** it renders
**Then** it shows three panes (list 320, thread, composer area), chips All, New, Replied, Closed, rows with avatar initial, client name, subject, preview, time and status pill, unread rows with `body-strong` name and an 8px accent dot, and the thread pane text "Select an inquiry to read it."; the sidebar shows "N new" only when N > 0.

**Given** states
**When** loading, empty and filtered-empty occur
**Then** loading shows skeleton rows, empty shows "No inquiries yet" with the empty-state art, filter-empty shows "No {status} inquiries".

**Given** a new Message elsewhere
**When** the 30 s poll runs
**Then** the client refetches page 1 and never uses `seq` as a watermark.

**Given** a Viewer
**When** the route or API is used
**Then** the sidebar item is absent and the API returns 403.

**Given** the leak suite
**When** extended
**Then** Sentinel client name, email, subject and body from `POST /inquiries` leave no plaintext.

## Dev record

**Assumptions**
- Migration is V17 (`client`, `inquiry`, `inquiry_term`, `message`, sequence `inquiry_activity_seq`).
- `inquiry.seq` is a fresh `nextval` of `inquiry_activity_seq` (OQ-2 plaintext). `InquiryStateService.touch()` moves it on later activity (7.3 reply, Client message); newest activity sorts first. `message.seq` is an identity column.
- `status` is an encrypted enum (`new`/`replied`/`closed`) with `status_bidx`; `unread` is an encrypted flag with `unread_bidx`. Badge = count of `status_bidx=new and unread_bidx=1`, no decryption.
- Client match is by `email_bidx` (canonical: NFKC, trimmed, lower-cased); an existing Client keeps its first name. Unique index makes a parallel first contact retry once.
- Validation (422, fixed codes, values never echoed): `clientName` and `subject` required, single line (whitespace folded), <=80 and <=200 chars; `clientEmail` required, <=254, one `@` and a dot in the domain part; `body` required, <=20,000 chars (trimmed). Query: `status` must be new/replied/closed; `before` >=1; `limit` 1..50, default 25.
- `Idempotency-Key` is optional; stored as HMAC of `userId|key` in `message.idem_bidx` (unique where not null). Replay answers 200 with the first Inquiry; a fresh create answers 201.
- Preview = first 120 chars, line breaks folded to spaces, never cuts a surrogate pair.
- Notification `NEW_INQUIRY` goes to ACTIVE Users whose Role holds `PERM_REPLY` and whose `Prefs.newInquiry` is not false, never to the author. It is called inside the create transaction, so a failed create sends nothing. `StubNotificationPort` stays a no-op until 8.1.
- A Client message reopening a Closed Inquiry (AD-21) belongs to 7.3.
- Terms: `Terms.of("clientName subject")` into `inquiry_term` (`BidxDomain.INQUIRY_TERM`); body words are not indexed (search of body text is not promised by 8.2's whole-word rule yet).
