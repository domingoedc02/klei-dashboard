# Story 5.4: Download .zip

As any signed-in User,
I want to download a gown, or several, as a .zip with photos and details,
So that I can share or archive them outside the app.

**Assumptions**
- The Rust shell builds the zip (architecture §7.2): it asks the backend for decrypted photos one at a time and writes the file the User chose. The backend never holds the archive.
- Limits: at most 100 gowns and 100 MB of photos per export (architecture §7.2). Over the limit shows "Too many to download at once. Select fewer." `[ASSUMPTION]` Plaintext is written to disk only to the destination the User picked; this is the one accepted plaintext write, documented in the release checklist.
- `details.txt` holds name, attributes, date added and description in English (US) text with LF line endings; file names are sanitized (no path separators, no `..`, no control characters).
- The Download button sits on the viewer and on Gallery select mode; Viewer keeps it (UX G1).
- Photos inside a zip use names `photo-1.<ext>`, with the extension from magic bytes returned in a response header `X-Image-Type`.

**Acceptance Criteria**

**Given** `POST /gowns/export {ids}` with at most 100 ids
**When** called with `PERM_VIEW_GALLERY` (403 `forbidden` without it)
**Then** it returns a manifest of `{gownId, name, photos:[{id, type}], details}`; over 100 ids or an estimated 100 MB returns 413 `too_large`; unknown ids are omitted and reported in `missing`.

**Given** the shell command `export_gowns(ids)`
**When** run
**Then** it opens the save dialog, fetches photos one at a time with fixed headers, streams them into the zip, writes `details.txt` per gown (one folder per gown when more than one), shows per-gown progress, and on cancel deletes the partial file it created.

**Given** a name like `../x` or a name with an emoji or a long name
**When** the folder and file names are built
**Then** they are sanitized and truncated to 80 characters, with a suffix to keep names unique; a Rust test covers path traversal.

**Given** a failure mid-export
**When** a photo cannot be fetched
**Then** the export stops, the partial file is removed and the toast "Download failed. Try again." shows; no partial zip is left.

**Given** G2
**When** **Download .zip** is pressed
**Then** one gown is exported; in G1 select mode **Select all**, "{N} selected" and **Download .zip** are enabled only when N > 0.

**Given** the leak suite
**When** extended
**Then** server-side no zip, no temp file and no decrypted bytes are persisted (the test lists the container temp directory after an export).

**Tasks**
- Backend: `ExportManifestController`, size estimation from encrypted sizes, header `X-Image-Type`, tests.
- Rust: `export_gowns`, zip writer (`zip` crate), sanitizer, tests with a mock backend.
- Desktop: buttons, selection state, progress UI, tests, axe.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && (cd src-tauri && cargo test && cargo clippy -- -D warnings)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: export manifest for the saved gowns).

## Dev record

**Assumptions**
- `POST /api/v1/gowns/export {ids}` needs `PERM_VIEW_GALLERY`. More than 100 distinct ids, or more than 100 MB of summed `Photo.size`, is 413 `too_large`; an empty or missing list is 422 on `ids`; unknown ids come back in `missing`. Items keep the asked order, Photos go by `createdAt` then id. The server answers a manifest only (ids, type, details text); it builds, stores and logs no archive.
- `GET /api/v1/gowns/{id}/photos/{pid}?size=full` also sends `X-Image-Type`. The Rust shell takes the file extension from the manifest `type`, not the header.
- `details.txt` is plain text: Name, one line per Taxonomy type that has values, Date added, Description (`No description yet.` when blank).
- The .zip is plaintext by design (FR-17) and is written only where the User chose in the save dialog. Failure or cancel removes the partial file. A dismissed save dialog is not an error (`cancelled: true`).
- Shell stays at eight commands: `export_gowns(kind: start|cancel, ids, on_event)`. `tests/contract.rs` lets only `export.rs` call `File::create` (once) and `remove_file`.
- Photos are stored as they are (no recompression); `details.txt` is deflated. One folder per Gown only when more than one Gown is exported. Names pass the sanitizer (no separators, `..`, control characters, reserved Windows names; 80 characters, 200 bytes) and repeats get " (n)" case-insensitively.
- Gallery select mode works over the loaded pages; "Select all" means all loaded Gowns. Viewer also has Download .zip. Select mode is reused by 5.5.

**Checks run**
- `./mvnw verify`: 180 IT (4 new in `GownExportIT`: permission and ids rule, manifest order/type/details/missing, 413 on count and size, `X-Image-Type`), 103 unit, 0 failures. `LeakSuiteIT` gained a check that an export leaves no `.zip` or JPEG-magic file in the temp directory.
- `npm test`: 162 passed (new Download and Select-and-download tests with axe); `npx tsc --noEmit` and `types:check` clean.
- `cargo test`: 43 unit (8 new in `export_tests.rs`) + 3 contract passed; `cargo clippy --all-targets -- -D warnings` clean.
- Compose smoke on throwaway `kleismoke`: SMOKE PASS including the new `export-*` checks (anonymous 401, empty 422, manifest 200 with name/details/missing, 101 ids 413); project torn down, the four dev `klei-*` containers untouched.

**Not verified**
- Real save dialog and the written .zip opened on macOS, Windows and Linux.
- Download of 100 Gowns or 100 MB end to end (limits are tested at the manifest only).

**Shortcuts**
- One whole Photo (up to 25 MB) is held in memory at a time while zipped; streaming to disk later if needed.
- Manifest dates are UTC, en-US, until the preferences story (6.3).
- Cancel takes effect between and during photo fetches, not while the save dialog is open.
- Select-all does not load further pages.
