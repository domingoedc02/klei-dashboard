# Story 21.6: No-limit upload

As a Staff User,
I want to add as many gown photos to a batch as I have,
So that a big shoot does not have to be split into batches of 200.

**Assumptions**
- Reverses the 200-photo cap (PRD OQ 14, Stories 11.5 U-1, 12.7, 13.6 UP-05). Decided by the owner on 2026-11-14.
- Not truly unlimited. The backend keeps one safety ceiling, `klei.upload.max-photos` (env `KLEI_UPLOAD_MAX_PHOTOS`, default 5,000), so a batch can never crash the server. Past it the server answers 413 `too_large` with `extensions.limit`, and the app shows "Batch is full".
- Why a ceiling: grouping holds two matrices of 4 bytes per photo pair (5,000 photos = 100 MB; heap is about 600 MB, `ExitOnOutOfMemoryError`); the commit body is 1 MiB, about 26,000 ids; Postgres allows 32,767 bind parameters, so IN-lists break near 16,000 photos. Raise the ceiling past 16,000 only after those are paged.
- Embedding stays serial (one provider call per photo). 5,000 photos take 5,000 calls; a failed call fails the run and Retry resumes. Parallel embedding is not part of this story.

**Acceptance Criteria**

**Given** a batch of 300 photos
**When** the User adds them
**Then** all 300 are stored, no "Batch is full" row appears, and the hint reads "300 photos stored"

**Given** `klei.upload.max-photos` is 5 and 5 photos are stored
**When** a 6th is sent
**Then** the server answers 413 `too_large` with `extensions.limit` 5, the app lists that file and every later one as "Batch is full. Group these photos, then upload the rest.", and sends no more requests

**Given** a 413 without `extensions.limit` (an image over 40 megapixels)
**When** the app reads it
**Then** the file is listed as "Image is too large: over 40 megapixels" and the rest carry on

**Given** 2,000 photos in 20 tight gowns
**When** `Clusterer.cluster` runs
**Then** it returns 20 groups of 100 in under a few seconds, and on random vectors its groups equal a plain O(n^3) average-link search

**Given** a batch of 300 stored photos and 80 rejected files
**When** the screen renders
**Then** the strip shows 60 photos and "and 240 more", the rejected list shows 50 lines and "and 30 more", and the summary line still counts 80
