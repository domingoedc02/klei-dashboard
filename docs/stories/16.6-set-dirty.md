# Story 16.6: `set_dirty`

As a User with an unsent Reply or an Upload review in progress, I want the app to remember that I have unsent work, so that nothing can interrupt or discard it.

**Assumptions**
- Source: `desktop/src-tauri/src/commands.rs::set_dirty` and `session.rs::{set_dirty, is_dirty}`: one boolean in main, set by the renderer, read by the update gate (18.3).
- In Electron the flag also feeds the Electron-only update gate and nothing else; no auto-restart exists.
- Renderer calls: `bridge.setDirty(dirty)` through `desktop/src/shell/context.ts` and `Shell.tsx`, from every form that holds unsent work: `desktop/src/inquiries/{Composer,EditClient}.tsx`, `desktop/src/upload/{Upload,Review}.tsx`, `desktop/src/gallery/EditGown.tsx`, `desktop/src/settings/{AiTab,SignatureTab,ProfileTab,AwayCard}.tsx`. The registry needs no per-screen knowledge; the list is for the prototype-unchanged check.

**Acceptance Criteria**

**Given** `set_dirty({ dirty: true })`
**When** invoked
**Then** it resolves with no value and `isDirty()` returns true; `false` resets it; any non-boolean fails `bad_request`.

**Given** the window reloads
**When** main notices
**Then** the flag is unchanged: as in `session.rs`, it is one process-wide boolean changed only by `set_dirty`, and the renderer re-sets it after remount.

**Given** the flag
**When** read by another module
**Then** it is read through one accessor; there is no other state, no persistence, and no event sent to the renderer.

**Tasks**
- `electron/src/main/session.ts` (or `electron/src/main/dirty.ts` if `session.ts` grows): `setDirty`, `isDirty`.
- `electron/src/main/commands.ts`: `set_dirty` handler.
- `electron/test/dirty.test.ts`: port of `dirty_flag_round_trips`, type validation, flag unchanged across a window reload.

**Dev notes**
- Port from `session_tests.rs::dirty_flag_round_trips`. The `beforeunload` guard in `Review.tsx:113` is a browser behaviour handled in 17.6, not here.

**Testing**
- Run `electron/test/dirty.test.ts`.

**Prototype unchanged check**
- Require the 14.1 gate. `bridge.setDirty` call sites in `desktop/src` are read only; no screen change.
