# Story 1.4: Users, bootstrap Admin and plaintext-leak suite

As an operator,
I want the first Admin created at startup from environment values and a build step that proves no plaintext reaches storage,
So that the system can be signed into and the encryption promise is checked on every build.

**Assumptions**
- Tables created here: `app_user`, `role`, `role_permission`, `permission_epoch`, `audit_entry`, `stored_object` (needed by `app_user.avatar_object_id`; keys and wrap only, no upload yet).
- Argon2id via BouncyCastle, m=64 MiB, t=3, p=1, PHC string wrapped by the envelope (architecture §6.1).
- `AuditService` is the single writer of `audit_entry` (AD-21). Its screen comes in Story 2.5.
- Default Role set seeded by migration through `MigrationCrypto`: Admin, Staff, Viewer with the default matrix from FR-36, plus `PERM_VIEW_GALLERY` (on for all three Roles; architecture §6.3) and the system `PERM_KEY_ROTATE` (Admin only).

**Acceptance Criteria**

**Given** an empty database and `KLEI_BOOTSTRAP_ADMIN_EMAIL`, `KLEI_BOOTSTRAP_ADMIN_PASSWORD`
**When** the app starts
**Then** one verified Admin exists, its name, email and password hash stored encrypted, `email_bidx` set, and one Audit Entry `bootstrap_admin` is written (FR-1).

**Given** an Admin already exists
**When** the app starts with the same variables
**Then** nothing is created and the boot continues (the first-run path fails only if asked to create over an existing Admin).

**Given** the password policy
**When** the bootstrap password is under 8 characters or lacks a number
**Then** the boot stops with a code and no value.

**Given** `PasswordHasher`
**When** a password is hashed and verified, and a wrong one is verified
**Then** verify succeeds only for the right one, parameters are inside the PHC string, and at most two hashes run at once.

**Given** `AuditService.record(action, detail)`
**When** called
**Then** one `audit_entry` row appears with `ts_ct`, `actor_id_ct`, `actor_name_ct`, `action_ct`, `detail_ct`, `ip_ct` encrypted, and a trigger rejects any UPDATE or DELETE on the table.

**Given** `LeakSuiteIT` (Testcontainers PostgreSQL, the pinned SeaweedFS image, Mailpit)
**When** it runs
**Then** it creates a user through the app code with Sentinel strings in plain, base64, hex and URL-encoded forms, dumps every table with `COPY … TO STDOUT` and `pg_dump`, decodes `bytea` as text and hex, lists S3 keys and reads bodies and metadata, reads captured logs, and fails if any Sentinel appears.

**Given** the same suite
**When** it checks structure
**Then** it fails if any column is outside the allowlist or any `_ct` or `_bidx` value is not a padded envelope, and it swaps two ciphertexts between rows and between columns and asserts decryption fails.

**Given** the suite design
**When** a later story adds a table
**Then** it extends a `SentinelCatalog` registry (one entry per field) and the build fails if a new `_ct` column has no catalog entry.

**Tasks**
- `V3__identity.sql`; entities; `RoleService`; seed through `MigrationCrypto`; `BootstrapAdmin` at startup after the crypto self-test (startup checks 5 and 6).
- `PasswordHasher`; `AuditService`; audit trigger.
- `LeakSuiteIT`, `SentinelCatalog`, CI wiring so `./mvnw verify` runs it.
- Extend `.env.example` with the bootstrap variables and the note to remove them after first boot.

**Checks**
- `cd backend && ./mvnw verify` (includes `LeakSuiteIT`)
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (smoke asserts health only; sign-in through the Auth Web arrives in Story 1.6).
- Desktop tests: not applicable yet.
- NFR-1: leak suite is the check.

**Deviations**
- `permission_epoch` uses the `version` column as the epoch counter; one seeded row.
- `app_user.last_active_ct` and `prefs_ct` deferred to Stories 1.5 and 6.3; `stored_object` holds keys only.
- Seed migration `V4__SeedRoles` is a Spring `@Component` extending `BaseJavaMigration` so it can use `MigrationCrypto`.
- `BootstrapAdmin` also reads `<NAME>_FILE`; compose passes both variables as optional (empty default).
- `infra/ci/gen-keys.sh` now emits a dev bootstrap Admin (email fixed, random password).
- Mailpit is started and searched but receives no mail yet (mail arrives in Story 1.6).
- `BackendIT` access-log test waits up to 5 s: the filter logs after the response is sent (race seen once in a full run).

**Risk.** Sentinel set covers fields writable today; each later story must add its catalog entry or the build fails. S3 object in the suite is sealed through `ObjectCipher` directly, not an upload path, until Story 4.1. Data directory grep runs inside the PostgreSQL container with `grep -rlaF`; a fixed-width encoding of a Sentinel outside the searched forms would not be found.
