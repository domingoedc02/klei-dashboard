# Story 4.5: Review Groups

As a Staff member,
I want to read each group and fix its name, tags and description,
So that only gowns I have checked reach the Gallery.

**Assumptions**
- Review phase only; moving, splitting and merging Photos is Story 4.6, saving is Story 4.7. The sticky footer buttons appear here but **Save** and **Discard** are enabled by 4.7 (the same rule as 4.2: a control ships only when its endpoint exists in `openapi.json`).
- Edits autosave 600 ms after the last keystroke with `PATCH /uploads/{id}/groups/{gid}` and `If-Match`; a failed save shows "Not saved. Retry." on the row and keeps the typed text in memory.
- Tag comboboxes accept Taxonomy values only (FR-10). Free text is not creatable here; the helper reads "Missing a tag? An admin can add it in Settings." Admins see a link.
- The Taxonomy comes from `GET /taxonomy` (Story 3.2).

**Acceptance Criteria**

**Given** phase `review`
**When** U1 renders
**Then** the left list (320) shows each Group with mosaic, name, Photo count and a Confidence pill (High, Medium, "Low · check"; percentage in the tooltip); Low-confidence groups come first; the selected row takes the active fill; the first Low group is selected on entry.

**Given** a selected Group
**When** the editor renders
**Then** it shows a name input (required), five tag comboboxes (Silhouette, Fabric, Neckline, Sleeve, Train; multiple values per type), a description textarea (up to 2,000 characters with counter) and the Photo grid.

**Given** an edit
**When** it autosaves
**Then** `PATCH` replaces name, attributes or description, returns 409 `conflict` on a stale version (the editor reloads that Group and shows "This group changed. Your edit was not applied." with the new values), returns 422 with field codes for an empty name or a value outside the Taxonomy, and encrypts everything.

**Given** the user leaves and returns
**When** the screen loads
**Then** `GET /uploads/current` restores the review with every saved edit; unsaved typing within the debounce window is flushed on unmount.

**Given** a Photo thumbnail is clicked
**When** the lightbox opens
**Then** the full image loads through `klei-img://`, previous/next works, Esc closes; a failed photo shows "This photo couldn't be loaded." with Retry.

**Given** a Viewer
**When** the route opens
**Then** the forbidden view shows.

**Given** the leak suite
**When** extended
**Then** Sentinel names and descriptions edited here leave no plaintext.

**Tasks**
- Backend: `UploadGroupController` (`PATCH`), `UploadGroupService`, Taxonomy validation.
- Desktop: Review layout, Group list, editor, combobox component (reused by Story 5.3), autosave hook, lightbox, tests, axe.

**Checks**

- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: patch a group name and read it back).

## Dev record

**Assumptions**
- Autosave failure text is "Couldn't save. Your changes are kept here." with Retry (in the editor, not on the row); stale text is "This group changed. Your edit was not applied." with Reload, which reloads the batch and remounts the editor (spec said the editor reloads that group; one batch reload is the smaller change).
- The list keeps the server order (Low confidence first, then position); the first group is selected on entry, which is the first Low group whenever one exists.
- Tags are chips plus one native select per type, not a combobox; only Taxonomy values are offered. The shared combobox for Story 5.3 is not built yet (shortcut: native select, upgrade when 5.3 needs type-ahead). The "Settings" hint is plain text, not an Admin link.
- Tags are saved as the whole list on each change; the server stores Taxonomy spelling in Taxonomy order. A name or description is only sent when edited.
- Full photos load through `klei-img://{batch}/{photo}/full`, never cached; thumbnails keep the 300 s memory cache.

**Done**
