# Story 3.2: AI behavior settings and Taxonomy

As an Admin,
I want to set how loosely photos are grouped, the tone of descriptions, and the list of allowed tags,
So that AI results match how the studio names its gowns.

**Assumptions**
- Adds the Grouping, Description tone, Advanced toggle and Tag taxonomy sections of S7 on the same tab as Story 3.1.
- Taxonomy types are Silhouette, Fabric, Neckline, Sleeve, Train. Seed values are copied from the wireframe `js/data.js` (read only) by a migration through `MigrationCrypto`.
- "Advanced AI model" uses `vision_model_adv_ct` from 3.1. The toggle is disabled with the tooltip "Set an advanced vision model first." while that field is empty.
- `gown_attribute` does not exist yet (Story 4.7). The "in use" count therefore reads `gown_attribute` and `upload_group` only once they exist. Until then the check counts zero. Story 4.7 adds the real count and its test. `[ASSUMPTION]`
- Taxonomy has no blind index (architecture §4.2). The list is decrypted in memory (tens of rows).
- Tone values: Warm, Editorial, Factual (PRD FR-38).

**Acceptance Criteria**

**Given** `GET /taxonomy`
**When** called with any valid token
**Then** it returns all values grouped by type, each with `id`, `type`, `value` and `version`.

**Given** `PUT /taxonomy` with `PERM_AI_SETTINGS`
**When** a value is added, renamed or removed
**Then** names are trimmed, empty and duplicate (case-insensitive within a type) values return 422, a rename keeps the id so Gowns follow it, and an Audit Entry is written.

**Given** a value that is in use (count greater than zero)
**When** removal is attempted
**Then** it returns 409 `conflict` with `extensions.usedBy = n` and nothing changes; the UI opens the dialog "Used by {n} gowns. Reassign them first." with **OK** only.

**Given** a Taxonomy rename
**When** saved
**Then** a `TaxonomyChanged` event is published (consumed by `TermIndexer` in Story 5.3; a no-op listener exists now and a test asserts the event fires).

**Given** `PUT /admin/ai` with sensitivity 1 to 5, tone, advanced flag
**When** saved
**Then** values outside range return 422; the label under the slider reads Very loose, Loose, Balanced, Strict or Very strict for 1 to 5; defaults are 3 and Warm.

**Given** the Grouping and Tag taxonomy sections
**When** the screen renders
**Then** the slider and tone select share the sticky save bar of 3.1; each Taxonomy group is a card of removable tags with an **Add** input (Enter adds, no empty value); adds and removes save immediately with a toast, they do not wait for the save bar; Loading and Error follow UX-DR7.

**Given** a non-Admin
**When** they call `PUT /taxonomy`
**Then** 403; `GET /taxonomy` still works because Gallery and Upload need it.

**Given** the leak suite
**When** extended
**Then** Sentinel Taxonomy values and tone settings leave no plaintext; the seed rows are ciphertext.

**Tasks**
- Backend: `V8__taxonomy_and_ai_behavior.sql` (taxonomy_value; extra `ai_setting` columns already exist from 3.1, none added), `TaxonomyService`, `TaxonomyController`, `UsageCounter` interface with a zero implementation, seed through `MigrationCrypto`.
- Desktop: behavior sections, tag editor, in-use dialog, tests, axe.

**Checks**

## Dev record

**Done**
- Backend: `V9` (`taxonomy_value`; four new `ai_setting` columns, they did not exist after 3.1) and Java seed `V10__SeedTaxonomy` (19 values through `MigrationCrypto`). `TaxonomyService` (one op per `PUT`, row lock, trimmed, 60 chars, case-insensitive duplicate per type), `TaxonomyController` (`GET` any token, `PUT` `PERM_AI_SETTINGS`), `TaxonomyChanged` event on rename, `UsageCounter` port in core, audit action `TAXONOMY_CHANGED` (detail "added|renamed|removed <type>", no value text).
- 409 with `extensions.usedBy`: `ProblemException.extensions`, `Problems.json`, `OpenApiConfig` declares `usedBy`. AI behavior: `visionModelAdv`, `sensitivity` 1-5 (3), `tone` warm|editorial|factual (warm), `advanced`; 422 `out_of_range`, `invalid`, `needs_model`.
- Desktop: slider with labels, tone radios, Advanced switch (disabled with reason until a model is set), `TaxonomyCards` (chips, Enter adds, immediate save, in-use dialog with OK only), audit label.
- Infra: `smoke.sh` reads seeds (19, Mikado), adds, duplicate 422, no If-Match 400, stale 409, removes; pg_dump holds no tag text.

**Checks run**

- `cd desktop && npm test`: 79 pass (`AiTab.test.tsx` 17 incl. axe); `npm run build`, `types:check`, `tsc` ok. `cargo test`: 20+3 pass.

**Discrepancies vs story text**

- `GET /taxonomy` uses `@TokenAuthorized` (ArchUnit AD-9).
- An omitted `visionModelAdv` clears it (same as the other model names), so `advanced: true` must resend the model.

**Shortcuts**
- `ZeroUsageCounter`: nothing is ever "in use" until Story 4.7 supplies the real count and test.
- No-op `TaxonomyChanged` listener until Story 5.3 (`TermIndexer`).
- Two identical concurrent adds can both land (no blind index on `value`).
- Rust long timeout still keyed to `/api/v1/admin/ai/test` only.
