# Story 3.1: AI provider settings and Test connection

As an Admin,
I want to enter the AI provider, its key and models in the app and prove they work,
So that later AI features run on my provider and my key stays secret.

**Assumptions**
- The key is typed at runtime in this screen and stored encrypted. It is never in `.env`, the repo, the bundle or CI. The Dev agent must not ask the user for it: all automated checks use a stub provider.
- This story builds the Provider and Models sections of S7 and the sticky save bar. Grouping, Description tone and Tag taxonomy are Story 3.2 and add their columns by a later migration.
- `ai_usage` is created here because Test connection is the first AI call (every call writes a row). The screen over it is Story 3.3.
- `AiProviderPort` starts with `embed` and `listModels`. `describe` and `chat` are added by Stories 4.4 and 8.3.
- Test connection runs on the saved settings. The Test button is disabled while the form has unsaved changes ("Save changes first.") `[ASSUMPTION]`, so the key is only ever sent through the save path.
- Preset base URLs and model names are copied from the wireframe `js/settings.js` (read only). Default preset is LiteLLM `https://nextgen-ai.enlinka.co`, embedding model `dinov2-base`.
- A fixed dev flag `KLEI_AI_DEV_MODE=true` allows HTTP and loopback/private addresses for stub providers. It is honoured only under Spring profiles `dev` or `test`; the backend refuses to start if it is set under any other profile.
- OPEN QUESTION (non-blocking): the Ollama preset points at a local address that AD-12 refuses in production. Default: the preset stays, Test connection reports "Address not allowed", and the user can still use LiteLLM. Revisit only if Ollama is wanted.

**Acceptance Criteria**

**Given** `GET /admin/ai`
**When** called with `PERM_AI_SETTINGS`
**Then** it returns preset, base URL, organization, models, temperature, max tokens, status, tested time and `apiKeySet`, with a fixed mask `••••••••` that is never derived from the key; the key is returned by no endpoint, log or error.

**Given** `PUT /admin/ai` with `If-Match`
**When** the base URL scheme or host changes and `apiKey` is absent
**Then** it returns 422 `validation_failed` with field `apiKey` (code `required_on_host_change`); when URL, key or organization changes, `status` resets to Not tested; changing scheme or host writes an Audit Entry; saving clears the 60 s settings cache.

**Given** validation
**When** the URL does not start with `http://` or `https://`, or the key is empty for a non-Ollama preset
**Then** it returns 422 with field codes only, never the submitted value.

**Given** the SSRF guard
**When** an outbound call is made
**Then** HTTPS is required, the host is resolved once and the connection pinned to that IP, loopback, link-local, private, CGNAT, ULA and cloud-metadata ranges are refused, redirects are not followed, response size and time are capped (60 s, one retry), and the provider's body is never echoed to the client. A unit test covers each range and a rebinding case.

**Given** `POST /admin/ai/test`
**When** called
**Then** it runs three checks in order, Provider reachable (`GET /models`), Models loaded (count), Image embedding (`POST /v1/embeddings` with one tiny generated image, vector length read from the response and greater than zero), and returns `{checks:[{id,label,ok,detail}], status}`; `detail` is a fixed cause string (for example "Unauthorized", "Timed out", "Address not allowed", "dimension 0"), never provider text; the result sets `status_ct` and `tested_at_ct` and fills the model lists from a successful call.

**Given** any AI call, success or failure
**When** it finishes
**Then** one `ai_usage` row (purpose, model, size, outcome, duration, prompt, response, user) is written in its own transaction and never inside the caller's DB transaction; prompt and response are stored encrypted (for the test: a fixed label and a summary).

**Given** the Provider and Models sections (S7)
**When** the screen renders
**Then** it shows preset select, base URL (mono), API key (shows the mask with **Replace**), organization, chat model, vision model, embedding model, temperature, max tokens, the status pill (Not tested, Testing, Connected, Failed), **Test connection** with the three result rows, and the sticky **Save AI settings** (disabled until a change); Loading and Error states follow UX-DR7; a non-Admin sees no tab.

**Given** the leak suite
**When** extended
**Then** a Sentinel base URL, organization, key, model name and a stubbed provider response pass through save and Test, and no Sentinel appears in any table, log, S3 object or error body.

**Given** CI
**When** the dev profile starts
**Then** a pinned WireMock stub provider (service `ai-stub`, mappings in `infra/ci/stub-ai/`) answers `/models` and `/v1/embeddings` for the smoke test; no real provider is ever called from CI.

**Tasks**
- Backend: `V8__ai_setting_and_usage.sql` (V7 is `user_last_active`), `AiSettingService`, `AiProviderPort` and OpenAI-compatible adapter, `SsrfGuard`, `AiUsageRecorder` (`REQUIRES_NEW`), `AiAdminController`, dev flag check, OpenAPI update.
- Infra: `ai-stub` in the dev profile, `infra/ci/stub-ai/mappings/`, `smoke.sh` extension.
- Desktop: AI settings tab (Provider and Models), save bar, test result block, tests, axe.
- Manual, operator only, never in CI: enter the real key in the screen and run Test connection.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && (cd src-tauri && cargo test)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: save settings pointing at `ai-stub`, Test returns three green checks, the key is not in `GET /admin/ai`).

**Shortcuts**
- Rust long timeout is keyed on one path; a second slow call (3.2 describe) needs a per-call option.
- Read timeout is not retried (would double a 60 s wait).
- Ollama preset on `localhost` reports "Address not allowed" outside dev mode: OPEN QUESTION, non-blocking (a local model would need an allow-list entry).
- Spike S-1 (data URI as embedding `input`) is verified against the stub only. Operator step: enter the real key, run Test connection, confirm the embedding row is green.
- Grouping, tone and taxonomy sections are Story 3.2.
- `OpenApiConfig.kt` import order is not alphabetical.
