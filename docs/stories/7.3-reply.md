# Story 7.3: Reply

As a Staff member with Reply to inquiries,
I want to write a formatted reply with attachments and send it by email,
So that the client gets an answer and the inquiry shows it was answered.

**Assumptions**
- Attachments are picked through the Rust command `upload_files('attachment', inquiryId)`: Story 1.7 registers `upload_files(kind, targetId)` with `kind` in {`photo`, `attachment`}, Story 4.2 uses `photo`, this story uses `attachment` (user ok at Gate 5; AD-10 text updated). Endpoint: `POST /inquiries/{id}/attachments` (one file per request, `Idempotency-Key`, encrypted like photos, owner `attachment.object_id` once the Reply is sent; unsent ones are swept after 24 h).
- Sender address comes from `KLEI_MAIL_FROM` (documented in `.env.example`); a missing value fails startup check in non-dev profiles. Replies set `Reply-To` to the same address. The User's name appears in the Signature, not in `From`.
- Limits: at most 10 attachments, 20 MB total per Reply `[ASSUMPTION]` (typical SMTP limits).
- Sanitizer: allow-list B, I, U, STRONG, EM, UL, OL, LI, A, BR, DIV on the client and on the server (jsoup `Safelist`); links limited to `http`, `https`, `mailto` with `rel="noopener noreferrer"`; everything else is dropped.
- The server is the authority: it re-sanitizes whatever the client sent. The composer is a minimal contenteditable with the six toolbar actions; no editor dependency `[ASSUMPTION]`.
- The Reply is the only mail that carries content (PRD §7.1). It goes to the Client's email with `MailPort` template `reply`.
- Reply state machine (architecture §8.2): `pending` saved with the status change in one transaction; send after commit; `sent` or `failed`; a `pending` row older than 5 minutes shows as not sent; retry is user-driven only.
- Draft: one per Inquiry per User, autosaved 1.5 s after the last change, stored encrypted.

**Acceptance Criteria**

**Given** `PUT /inquiries/{id}/draft {body}` and `DELETE /inquiries/{id}/draft`
**When** called with `PERM_REPLY`
**Then** the Draft is stored encrypted (unique per Inquiry and User), bodies over 100,000 characters return 422, and DELETE is idempotent.

**Given** `POST /inquiries/{id}/reply` with `Idempotency-Key`, sanitized `body` and attachment ids
**When** the Inquiry is not Closed
**Then** in one transaction the sanitized body (plus the rendered Signature when enabled) is stored as a `message` (direction `out`, author, `mail_state=pending`), the Inquiry becomes Replied through `InquiryStateService`, `seq` is touched, the Draft is deleted and an Audit Entry `reply_sent` (no content) is written; after commit the mail is sent and the state becomes `sent` or `failed`; a repeat with the same key returns the first Message and sends nothing twice.

**Given** a Closed Inquiry
**When** a Reply is posted
**Then** 409 `conflict`.

**Given** a send failure
**When** SMTP errors
**Then** the Message stays `failed`, the response still returns 201 with `mailState: "failed"`, and the UI shows an error toast with **Retry**; `POST /messages/{id}/retry` re-sends the same Message, never creates a second one, and works on `failed` or on `pending` older than 5 minutes only.

**Given** the mail
**When** Mailpit receives it
**Then** To is the Client, Subject is the Inquiry subject (CR/LF stripped), the body is the sanitized HTML, attachments are decrypted from `stored_object` into the mail only in memory, and the Signature is appended; the leak test reads Mailpit and finds only these fields.

**Given** hostile HTML (`<script>`, `onerror`, `javascript:` links, nested `<style>`)
**When** posted
**Then** the stored and sent body contains none of them; a table-driven test covers at least 12 payloads on the server and 12 on the client.

**Given** the composer (I1)
**When** it renders
**Then** it shows read-only-looking To and Subject, the toolbar (B, I, U, bulleted, numbered, link), the body, the attachment list with **Attach files**, the Signature preview from `SignatureRenderer`, the "Saved as draft" status, **Discard** and **Send**; Enter sends when the preference is on, Shift+Enter adds a new line, otherwise Cmd/Ctrl+Enter sends.

**Given** Discard
**When** pressed
**Then** the Draft is removed with the undo toast "Draft discarded. Undo." (undo is a client-side re-`PUT`, A-UX11).

**Given** Send is pressed
**When** the shell is offline
**Then** Send is disabled with the banner, the typed text stays in memory, and the Draft is already on the server if the last autosave succeeded.

**Given** success
**When** the Reply is sent
**Then** the toast "Reply sent to {first name}" shows, the thread shows the new Message, the list row moves to the top and its pill becomes Replied.

**Given** the leak suite
**When** extended
**Then** Sentinel reply bodies, filenames and attachment bytes leave no plaintext in tables, S3 or logs, Mailpit is read and matched against the allowed content, and a failing SMTP run leaves no plaintext in logs.

**Tasks**
- Backend: `V19__attachment_and_draft.sql`, `ReplyService`, `HtmlSanitizer` (jsoup), `MailPort` `reply` template, `DraftController`, `MessageRetryController`, `AttachmentService` (encrypted objects, owner `attachment.object_id`), `KLEI_MAIL_FROM` startup check, sweep update for attachments.
- Desktop: composer, toolbar, client-side sanitizer (same allow-list, tested against the shared payload fixture in `docs/fixtures/xss-payloads.json`), attachments list via `upload_files('attachment', inquiryId)`, autosave, Send and Retry flows, tests, axe.

## Dev record

**Assumptions**
- `MailPort.sendReply(ReplyMail): Boolean` is synchronous (SMTP via `JavaMailSender`); `send` stays async and void. Failure logs the exception class name only.
- Reply mail: sanitized HTML plus HTML-escaped Signature, plain-text alternative from `HtmlSanitizer.plain`, `Reply-To` = `KLEI_MAIL_FROM`, Subject = Inquiry subject through `header()`, attachments decrypted in memory only. `KLEI_MAIL_FROM` startup check exempts dev/test.
- jsoup allow-list B, I, U, STRONG, EM, UL, OL, LI, A, BR, DIV; links http/https/mailto with `rel="noopener noreferrer"`. Client `sanitizeHtml` uses the same list; both run the 21 cases of `docs/fixtures/xss-payloads.json`.
- `POST /reply` and `POST /attachments` need `Idempotency-Key` (400 without), scoped per User. The webview JSON path sends `idempotencyKey` through `bridge.request` and Rust `ApiCall`.
- Stored body is clean HTML plus Signature HTML; `DetailMessage.html` is true for `out`; the client sanitizes again before rendering. A Client's Message stays plain text.
- Limits: at most 10 unsent files, 20 MB total (413), any file type.
- Closed Inquiry reply returns 409; Reopen arrives with 7.4.
- Audit `REPLY_SENT` carries no detail. Reply sets unread false, preview from plain text, `lastMessageAt` now.
- Retry allowed for `failed`, or `pending` older than 5 minutes; otherwise 409.
- A Draft with no text is no Draft. Discard also removes unsent files; Undo restores text only.
- Rust `attach_files`: sequential, fresh random key per file; `stored` holds attachment ids.
- Migration is V19 (story text said V15, taken by Signature).
