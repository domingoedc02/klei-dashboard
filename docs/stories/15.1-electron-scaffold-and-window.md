# Story 15.1: Electron scaffold and window

As a developer, I want an isolated `electron/` project that opens a window with the same title, size and limits as the Tauri app, so that every later story has one place to build on.

**Assumptions**
- Electron version, TypeScript tooling and test runner are chosen here after a web check of current stable Electron and its support window (OQ-M1). Versions are pinned in `electron/package-lock.json`. The existing desktop toolchain (TypeScript 5.9.3, Vitest 5.1.0) is the default for tests.
- `electron/` has its own `package.json`, lockfile, `tsconfig.json` and `.gitignore`. Root files are not edited.
- The Tauri window facts are: label `main`, title "Klei Bridal", 1280×800, minimum 1100×700 (`desktop/src-tauri/tauri.conf.json`).
- Preview identity (AD-27): app id `co.klei.bridal.electron.preview`, product name "Klei Bridal Preview", own `userData` directory, own credential entry. No `klei://` claim.

**Acceptance Criteria**

**Given** `electron/package.json`
**When** it is read
**Then** it has `"private": true`, pinned versions, scripts `build`, `typecheck`, `test`, and no dependency on or workspace link to `desktop/`.

**Given** the main process starts
**When** the first window is created
**Then** it has title "Klei Bridal", initial size 1280×800, minimum 1100×700, a stable internal label `main`, is created hidden and shown on `ready-to-show`, and has no menu bar customisation beyond what Tauri's default window shows on that OS.

**Given** `app.setPath('userData', …)` and the app name
**When** the app is ready
**Then** `userData` is a directory named for the preview identity, set before `ready`, and not shared with the Tauri app's data directory.

**Given** a second launch of the preview app
**When** the single-instance lock is already held
**Then** the second process exits and the first window is shown and focused; the lock key belongs to the preview identity, so an installed Tauri app still starts independently.

**Given** `KLEI_API_URL` and `KLEI_AUTH_URL` build-time values
**When** the app starts
**Then** they are read in main only (config module in 16.1) and never reach the renderer; a missing value in a packaged build is a build failure, matching Tauri's compile-time assertion.

**Tasks**
- `electron/package.json`, `electron/package-lock.json`, `electron/tsconfig.json`, `electron/.gitignore`, `electron/vitest.config.ts`.
- `electron/src/main/index.ts`: app entry, identity, `userData`, single-instance lock.
- `electron/src/main/window.ts`: `createMainWindow()` with the settings above; webPreferences are added by 15.2.
- `electron/test/window.test.ts`: assert window options (extracted as a plain object) and identity constants.
- Record Electron version, Node ABI and the web-check date in `electron/BASELINE.md`.

**Dev notes**
- Reference only: `desktop/src-tauri/tauri.conf.json` (window, `identifier: co.klei.bridal`), `desktop/src-tauri/src/lib.rs::run` (single-instance focus callback, smoke exit after 60 s).
- Smoke mode (`KLEI_SMOKE=1`): keep the contract from `lib.rs` (in-memory credential, first `api_request` answers signed out, exit shortly after). It is the CI smoke launch for 19.2 and 19.3. Define the Electron variable name `KLEI_SMOKE` with the same meaning; document it in `electron/BASELINE.md`.
- Do not create a native application menu or tray: the Tauri app has none (`docs/brownfield-architecture.md`, absent features).

**Testing**
- Run `electron/test/window.test.ts` and `npm run typecheck` in `electron/`. Launch checks (window size, single-instance, `userData` path) are real-Electron checks on each OS in 20.1.

**Prototype unchanged check**
- Require the 14.1 gate. No file under `desktop/` is opened for writing. Compare launch window size and title against the baseline at 1280×800 and 1100×700 (resize to minimum; confirm the window cannot go below 1100×700).
