# Story 17.5: `klei-img` image protocol

As a Staff member, I want thumbnails, originals and my avatar served through the existing image URLs, so that photos display without writing business content to disk.

**Assumptions**
- Electron registers a privileged `klei-img` scheme before app readiness and serves it from the main process; `desktop/src/platform.ts` remains unchanged.
- `desktop/src/platform.ts` chooses `http://klei-img.localhost` from the user agent on Windows, and Electron's user agent contains `Windows`, so the unchanged renderer will request that origin. The user agent is not changed (the same `platform.ts` user-agent test also drives the Credential Manager label copy).
- Because Chromium enforces CSP before any request handler runs, a handler alone is not enough. Default mechanism (to confirm in spike 14.3/14.4, packaged Windows): the Windows build's `app://` CSP adds exactly `http://klei-img.localhost` to `img-src` (no other http origin, `connect-src` stays `'none'`), and main answers that host with `protocol.handle('http', …)` routed to the same validated handler; any other `http` request through that handler fails closed without touching the network. Fallback if the spike shows that cannot work: an Electron-owned renderer build alias for `platform.ts` only (Option B in 14.4).

**Acceptance Criteria**

**Given** a request to `klei-img`
**When** the protocol handler receives it
**Then** only GET is accepted; valid forms are `/{batch}/{photo}[/full]`, `/g/{gown}/{photo}[/full]` and `/me/{digits<=18}`, including percent-encoded slash forms; all other paths or methods return 400.

**Given** an accepted path and an initialized session
**When** bytes are fetched
**Then** batch and gown paths map only to the matching API resource; avatar maps to `/api/v1/me/avatar`; network/session failure returns 503, upstream 404 returns 404 and any other non-200 result returns 502.

**Given** a response
**When** it is returned to Chromium
**Then** it includes `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, and magic-byte-sniffed `Content-Type` (`image/png`, `image/webp`, otherwise `image/jpeg`); no business content is written to disk.

**Given** a thumbnail response
**When** it is cached in memory
**Then** only thumbnails are retained for 300 seconds, with at most 400 entries; full images and avatars are never cached; expired entries are removed before insertion.

**Given** Windows uses `http://klei-img.localhost`
**When** renderer requests a thumbnail or full image
**Then** the request is allowed by a CSP that names only `http://klei-img.localhost` beyond the `klei-img:` scheme, is served by the same validated handler, any other `http` request is refused without network access, and `desktop/src/platform.ts` and all original renderer files remain unchanged. Verified on packaged Windows, with a negative test that `http://example.com/x.png` does not load.

**Tasks**
- `electron/src/main/image-protocol.ts`: register `klei-img`, strict path parser, API mapping, response headers/MIME sniff, thumbnail-only TTL/cap cache and status mapping.
- `electron/src/main/protocol.ts`: on Windows only, add the single `http://klei-img.localhost` image origin to the CSP source (shared with 15.2's `electron/src/main/csp.ts`) and register the fail-closed `http` handler for that host before readiness; no other CSP directive is relaxed.
- `electron/test/image-protocol.test.ts`: cover GET-only, UUID/avatar path validation, encoded slashes, upstream statuses, magic MIME and cache exclusions/limits/expiry.

**Dev Agent Record**
- `image-protocol.ts` (new): `parse` (the three layouts, `%2F` and `%2f`, UUID-shaped ids, `/me/{1..18 digits}`; everything else null), `mime` (PNG and WebP magic bytes, JPEG otherwise), `Thumbs` (thumbnails only, 300 s TTL, 400 entries, expired entries purged before an insert, injectable clock; full images and avatars never kept), `imageHandler` (GET only; every answer, errors included, `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`; sniffed `Content-Type` on 200; 400 refused path or method, 503 call failure, 404 upstream 404, 502 any other non-200), `windowsAlias` (only `http://klei-img.localhost` with no port or credentials reaches the handler; any other http request gets 403 without touching the network). Nothing is written to disk.
- `protocol.ts`: `klei-img` registered as a privileged standard secure scheme before ready; `installImageProtocol` handles `klei-img` on the session and, on Windows only, `http`. `window.ts` `setupSession(api)` installs it with the live `Session`; `index.ts` passes it.
- `csp.ts`: `CSP` is unchanged and still equals the Tauri release CSP. `cspFor(platform)` returns it as is, and on `win32` adds only `http://klei-img.localhost` to `img-src`; `connect-src` stays `'none'`. `SECURITY_HEADERS` uses `cspFor()`.
- `desktop/src/platform.ts` and every original renderer file unchanged; layouts checked against `thumbUrl`, `fullUrl`, `gownThumbUrl`, `gownFullUrl`, `avatarUrl`.
- Tests: `image-protocol.test.ts` (7: parse good and bad paths, mime, TTL boundary with a fake clock, 400 ceiling and purge, header and status mapping on every branch, 503 offline and signed out, alias allow and fail-closed list with the backend log unchanged) and `image-protocol-electron.test.ts` (1, real Electron: `klei-img://` answered by the handler through the partition, `http://example.com` blocked by `img-src`, alias origin blocked off Windows). `contract.test.ts` allows the one `http://klei-img.localhost` literal and checks `cspFor`.
