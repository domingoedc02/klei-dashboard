# Story 11.3: Sign-in pages fidelity

As a Staff member,
I want the sign-in, invite, verify and reset pages and the desktop sign-in screen to read and behave like the prototype,
So that errors tell me what to do and each step feels part of the same product.

**Assumptions**
- Prototype: `js/auth.js`, `css/` auth blocks. Current: Thymeleaf templates `login.html`, `invite.html`, `verify.html`, `forgot.html`, `reset.html` in `backend/app/src/main/resources/templates/`, `static/auth.css`, and the desktop phases in `desktop/src/App.tsx` (lines ~84 to 147).
- First task is to confirm the unverified rows: show/hide control and busy state on `login.html`, the invite footer, and the existing strength meter on `reset.html` (`strength.js`).
- Copy per prototype (exact strings):
  - Desktop login card (440 wide, 'K' mark): h1 "Welcome back", lede "Sign in to manage gowns and inquiries."
  - `login.html`: h1 "Welcome back"; label "Work email" with placeholder `you@kleibridal.com`; "Password" with Show/Hide; checkbox "Keep me signed in"; link "Forgot password?"; error "Email or password is incorrect. Check both and try again, or reset your password."; busy button "Signing in…" disabled with a spinner.
  - `invite.html`: pill "Invitation"; h1 "Join Klei Bridal"; line "{Inviter} invited you as **{Role}**."; readonly Email with hint "Set by your admin. Cannot be changed."; Name, Password, Confirm password; footer "Already have an account? Sign in".
  - `verify.html`: h1 "Check your email"; six digit boxes 48×56, each `aria-label="Digit {n} of 6"`, paste fills all six; button "Verify email"; "Didn’t get it?" with **Resend**; resend toast text "New code sent to {email}".
  - `forgot.html`: h1 "Forgot your password?"; "Enter your work email and we’ll send a reset link."; button "Send reset link"; sent state h1 "Reset link sent".
  - `reset.html`: h1 "Choose a new password"; "Use at least 8 characters with a number."; four-segment strength bar; button "Update password".
- Inline validation on focusout, cause plus remedy: "Enter your work email, for example you@kleibridal.com." and "Password is too short. Use at least 8 characters." Server stays the authority; client rules never replace server checks.
- Kept as is (stronger than the prototype): the 30 s resend countdown, anti-enumeration answers (the "Reset link sent" page appears for unknown emails too), rate limits, and the extra states (invitation expired, link expired).
- `[ASSUMPTION]` The inviter name and role are read from the invitation row; no new column. If the inviter was deleted, the line reads "You were invited as **{Role}**."
- Desktop phases not in the prototype ("Loading…", "Finish signing in in your browser", "Sign-in didn't finish. Try again.", "Can't reach the server. Check your connection.", "Session expired", "Your account has no access yet. Ask an admin.") get the same card layout and tokens, copy unchanged.
- OPEN QUESTION (A-1): the six-box code replaces one input. Default: keep a hidden single input with `autocomplete="one-time-code"` so password managers and SMS autofill still work, boxes mirror it.

**Acceptance Criteria**

**Given** the desktop sign-in screen
**When** `App.test.tsx` renders the signed-out phase
**Then** it shows a card with the 'K' mark, h1 "Welcome back" and "Sign in to manage gowns and inquiries.", and the other phases render inside the same card.

**Given** `GET /login`
**When** `AuthWebIT` renders it
**Then** the h1, labels, placeholder, show/hide button, checkbox and "Forgot password?" link appear as listed above.

**Given** a wrong password
**When** the form is posted
**Then** the page shows exactly "Email or password is incorrect. Check both and try again, or reset your password." in an alert, and the same text appears for an unknown email (no enumeration).

**Given** the Sign in button is pressed with valid-looking input
**When** the request is in flight
**Then** the button is disabled, reads "Signing in…" and shows a spinner; with scripting off the form still posts normally.

**Given** an empty or malformed email on focusout
**When** the field loses focus
**Then** an inline message with the cause and the remedy shows, `aria-invalid="true"` is set, and the message is tied to the field with `aria-describedby`.

**Given** a valid invitation link
**When** `InviteFlowIT` renders the page
**Then** it shows the pill "Invitation", the h1 "Join Klei Bridal", the inviter line with role, a readonly email with the hint, and the footer link to sign in.

**Given** the verify page
**When** the user pastes "123456" into the first box
**Then** all six boxes fill, the hidden input holds "123456", and the form can be submitted with Enter.

**Given** a wrong or expired code
**When** submitted
**Then** the page shows "That code is incorrect or has expired." (existing copy) and the boxes keep focus on the first.

**Given** the forgot-password page for any email
**When** submitted
**Then** it shows "Reset link sent" with identical timing and text for known and unknown addresses (`ResetFlowIT`).

**Given** axe on each page
**When** `AuthWebIT` runs it
**Then** zero violations, with the six boxes labelled and the error alert announced.

**Given** the leak suite
**When** extended
**Then** page output holds no email or role other than the invited one; the invite page does not reveal whether an account exists for any other email.
