# Story 11.11: Assistant drawer copy and states match the prototype

As a Staff member,
I want the Assistant drawer to look and read like the approved prototype,
So that the first thing it says and the way it waits feel the same as what I saw.

**Assumptions**
- Prototype wins except where the prototype is a simulation. Dropped: the footer words "Replies are simulated". Kept from the desktop: the provider-disclosure note, Copy, gown mosaics, **New chat**, server-saved history, the "can't reach your AI provider" state with a permission-gated **Open settings** link.
- The prototype suggestion "Draft a reply to Hannah" names a sample person. `[ASSUMPTION]` the chip shows the first name of the open thread's customer ("Draft a reply to {first}"), and "Draft a reply" when no thread is open. "Suggest gowns for a beach wedding" is a fixed example.
- Chips sit under the greeting as a vertical stack and go away after the first user message (prototype).
- First task: confirm the rows marked **verify** (header avatar and shadow, message bubble colours, New chat placement) in `Assistant.tsx` and `prototype/v0.1.0/js/assistant.js`.

**Acceptance Criteria**

**Given** a new chat
**When** the drawer opens
**Then** the header shows a 24 px assistant avatar and the title "AI Assistant", the drawer has the raised shadow and left border, the first message reads "Hi! I can summarize inquiries, draft replies and suggest gowns from your gallery.", and three chips show under it: "Summarize new inquiries", "Draft a reply to {first}" (or "Draft a reply"), "Suggest gowns for a beach wedding".

**Given** the first message is sent
**When** the chat has a user turn
**Then** the chips are hidden.

**Given** the input
**When** it renders
**Then** the textarea placeholder reads "Ask anything about your inquiries or gowns…" and the footer reads "Enter to send · Shift+Enter for a new line"; the provider-disclosure note stays above the form.

**Given** the assistant is working
**When** a reply is pending
**Then** three animated dots show (`aria-label` "The assistant is typing", reduced-motion shows static dots), not the text line.

**Given** messages
**When** they render
**Then** user turns are solid accent bubbles and assistant turns grey radius-12 bubbles, Copy and gown mosaics keep working.

**Given** Esc
**When** the drawer is open
**Then** it closes and focus returns to the **AI Assistant** button.

**Given** the leak suite
**When** extended
**Then** no new data leaves the app: chip text is static copy plus a first name already on screen, and a test asserts the prompt sent for "Draft a reply to {first}" holds no email, id or filename (existing Story 8.3 test shape).

**Tasks**
- Desktop: `desktop/src/assistant/Assistant.tsx` (`CHIPS`, greeting, placeholder, footer, dots, bubbles), `desktop/src/shell/Shell.tsx` (drawer header), `desktop/src/styles.css` (`.drawer`, `.assist-line`, dots).
- Backend: none.
- Tests: `Assistant.test.tsx` (greeting, chips with and without a thread, chips hidden after send, placeholder, dots role and reduced motion, Esc focus return).

**Checks**
- `cd desktop && npm test && npm run types:check`
- `node infra/ci/axe.mjs` with the drawer open.
