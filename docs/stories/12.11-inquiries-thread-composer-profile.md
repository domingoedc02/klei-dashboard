# Story 12.11: Inquiries, thread, composer and customer profile layout

As a Staff member,
I want the inquiry list and thread to scroll inside their own panes with the composer pinned, and the thread to read as mail cards,
So that I can answer a long conversation without the reply box drifting off screen.

**Assumptions**
- Audit rows G-11 (no height chain), G-12 (flat messages), G-25 (misc). Group B (frame and scroll chain) and group C (selector collisions).
- Prototype: `css/screens.css:113-117` `.inq { grid-template-columns: 320px minmax(0, 1fr) }` at a fixed height, with `.pane-body` scrolling and the composer pinned; `js/inquiries.js:87` `mail()` renders From <address> / To / time cards (`screens.css:179-207`); `:84-90` pane head: h2 `od-truncate`, "{n} message(s)", status pill, 140px status select, **Reopen** or **Close inquiry** in the head; `:93` closed banner above the composer; `:54` and `:75-81` hover card hides on mouseout, Esc, click and scroll; `screens.css:174` `.hc` z-index 30 (above the page, below dialogs).
- App today: `styles.css:328` `.inq-panes` has no height and no `min-height: 0`, so the whole `.sheet` scrolls and the composer leaves the screen; `:346` `.inq-thread`; `:347` dead media query; `:356-361` flat `.messages`; `:373-374` `.composer-link input { min-width: 16rem }` forces overflow at 1100; `:505` `.inq-thread > .empty { min-height: 420px }` around a 240px-wide art (`Inquiries.tsx:161` `height={240}`); `:513` `.hc` z-index 30 equals `.scrim` z-index 30 (`:87`), so a hover card can paint over a dialog scrim. `Inquiries.tsx:120` h1 sits above both panes; `Thread.tsx:113` missing thread is a bare lede, `:136` `<ol className="messages">`, `:166` **Reopen** lives in the closed banner, the status control is a native select; `CustomerCard.tsx:62`, `:74`, `:76` the card hides on mouseout only; `ClientProfile.tsx:51` no crumb while loading.
- Height decision: panes get `height: calc(100vh - <topbar> - <sheet padding>)`, built from the 12.2 tokens (`--space-page-bottom`, top bar height) with `min-height: 0`; at 700px tall that is about 540px, enough for a thread and the composer.
- z-index decision: add `--z-hovercard: 35` in `styles.css` (`:root`, not DESIGN.md; layering is not a design token) above the scrim (30) so the card never sits under a scrim, and hide it whenever a dialog opens.
- Empty-art: the missing-thread and no-selection empties are whole-pane views; they use the 12.3 compact size (96px, `width: auto`), not `height={240}`.
- Status select: styled with the 12.3 `.field`/select treatment, 140px wide, kept as a native `<select>` (accessible and testable); the prototype's look is matched by CSS only.
- 11.8 and 11.9 stay `done`; this story corrects them.

**Acceptance Criteria**

**Given** the Inquiries screen with 30 inquiries and a 40-message thread at 1100x700
**Then** the list pane and the thread pane each scroll on their own, the composer stays pinned at the bottom of the thread pane, and `.sheet` has no vertical scroll from the panes.
Test: `styles.test.ts` `it('inquiry panes are height-bound with min-height 0')` (reads `.inq-panes`, `.inq-thread`); `Thread.test.tsx` `it('keeps the composer outside the scrolling message list')` asserts the composer is not a descendant of the scroll container.

**Given** a thread with messages
**Then** each message renders as a `.mail` card with From <address>, To, and time (prototype `inquiries.js:87`, `screens.css:179-207`), inside a `role="list"` whose items remain focusable in order; inbound and outbound are visually distinct.
Test: update `Thread.test.tsx:76`, `:121`; `it('renders From and To on each message')`.

**Given** the thread pane head
**Then** it holds the h2 subject (ellipsis), "{n} message(s)", the status pill, the status select (140px) and **Reopen** or **Close inquiry** (prototype `inquiries.js:84-90`); the closed banner above the composer has text only, no button.
Test: update `Thread.test.tsx:216` `it('puts Reopen in the thread head and not in the closed banner')`.

**Given** the inquiry is missing
**Then** the thread pane shows a compact empty block (title, help, **Back to inquiries** button), not a bare paragraph (`Thread.tsx:113`).
Test: update `Thread.test.tsx:113`.

**Given** the customer hover card is open
**When** the pointer leaves, Esc is pressed, the page scrolls, any click happens, or a dialog opens
**Then** the card closes; its z-index is above the scrim.
Test: `CustomerCard.test.tsx` `it('closes on Esc, click and scroll')`; `styles.test.ts` `it('hover card layers above the scrim')`.

**Given** the composer's "Copy link" input at 1100px
**Then** it has `min-width: 0; flex: 1` and never forces horizontal overflow (`styles.css:373-374` loses `min-width: 16rem`).
Test: `styles.test.ts` `it('composer link input can shrink')`.

**Given** the Client profile is loading or errored
**Then** the crumb "Inquiries / Client" is present in every state (`ClientProfile.tsx:51`).
Test: `ClientProfile.test.tsx` `it('shows the crumb while loading')`.

**Given** `node infra/ci/shots.mjs --only inquiries`, `--only inquiries-thread` and `--only client-profile` (the 12.1 screenshot command)
**When** run at 1100x700 and 1280x800
**Then** `report.json` shows no overflow or footer-cover failure; the PNGs show pinned composer, mail cards, head actions, and match the prototype `inquiries` screens.
