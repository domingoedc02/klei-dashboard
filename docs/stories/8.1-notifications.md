# Story 8.1: Notifications

As a signed-in User,
I want a bell that tells me about new inquiries, finished AI work and team activity,
So that I notice what needs me without watching every screen.

**Assumptions**
- `NotificationPort` is the only writer of `notification` rows. Stories 4.3 and 7.1 already call a stub; this story replaces the stub with the real implementation and adds the team-activity producers.
- Event types: `new_inquiry` (to Users with `PERM_REPLY`), `ai_finished` (to the Batch owner), `team_activity` (to Admins: invite accepted, Role changed on someone, key rotation done) `[ASSUMPTION]`. Each respects the recipient's toggle from Story 6.3.
- A notification stores `type`, `title` (may hold a Client name), `target` (route and id) and `read`, all encrypted; `seq` plaintext for ordering (six-table allowlist).
- The menu shows the 20 most recent; "Clear all" deletes the caller's rows.
- Polling: the bell refreshes with the 30 s inbox poll (ADR-6).

**Acceptance Criteria**

**Given** `NotificationPort.notify(type, recipients, title, target)`
**When** called inside a business transaction
**Then** rows are written for each recipient whose toggle is on, in the same transaction, and a unit test proves a rollback leaves none.

**Given** `GET /notifications`, `POST /notifications/read`, `DELETE /notifications`
**When** called with any valid token
**Then** they return the caller's last 20, mark the listed ids read, and delete all of the caller's rows; ids of other Users are ignored (404-equivalent: omitted from the result).

**Given** the bell
**When** unread rows exist
**Then** a dot shows; opening the menu lists items with icon, title, time and unread style; clicking one marks it read and navigates to its target (Inquiry thread, Upload review, Settings tab); **Clear all** empties the menu with the toast "Notifications cleared"; the empty state reads "You're all caught up".

**Given** the 4.3 completion and 7.1 creation paths
**When** they run
**Then** the real notifications appear (replacing the stub assertions).

**Given** a User with the toggle off
**When** an event occurs
**Then** no row is created for them (integration test per type).

**Given** the leak suite
**When** extended
**Then** a Sentinel Client name in a notification title leaves no plaintext.

**Tasks**
- Backend: `V16__notification.sql`, `NotificationService`, controller, producers, tests.
- Desktop: bell menu, polling hook, navigation targets, tests, axe.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && (cd src-tauri && cargo test)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: an inquiry creates a notification for the Admin).

## Dev record

**Assumptions**
- Migration is `V20__notification.sql` (the Tasks line above says V16; V16 was taken by preferences).
- Team-activity producers: invite accepted, Role changed. Recipients are Admins, never the actor. Key rotation is not built yet; add its producer when 9.x lands.
- The list is the newest 20 rows; `unread` counts those 20. `POST /api/v1/notifications/read` takes `ids` (1-50, else 422 `ids` `required`/`too_many`); ids of other Users are ignored.
- Row exists only for ACTIVE Users whose toggle is not off (`newInquiry`, `aiFinished`, `teamActivity`; unset = on). Checked inside `NotificationService.notify`, in the caller's transaction (rollback leaves none).
- Targets: `inquiries/{id}`, `upload`, `settings`. Bell navigates with `#/{target}`.
- Every column encrypted; `seq` is the accepted plaintext column (OQ-2 list now seven tables incl. notification).
