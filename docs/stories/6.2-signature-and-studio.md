# Story 6.2: Signature and Studio

As a Staff member,
I want a signature with a live preview, and as an Admin I want to set the studio name and address,
So that every reply ends the same way.

**Assumptions**
- Away message and closure schedule are deferred (user, Gate 3, FR-32) and not built.
- The signature is plain text lines; rendering as HTML is Story 7.3's job and uses the same `SignatureRenderer` so preview and Send match (FR-31). This story creates the renderer and its tests.
- `workspace` is one row with a fixed id, created by a migration through `MigrationCrypto` with empty values.
- Studio block visible to Admin only (`PERM_MANAGE_STAFF`) `[ASSUMPTION]`: the PRD says "set by an Admin"; the code uses the Permission, not the Role name.

**Acceptance Criteria**

**Given** `GET/PUT /me/signature` with `If-Match`
**When** called
**Then** enabled flag, sign-off, name, title and phone are stored encrypted, limits are 80 characters each, and validation errors return field codes.

**Given** `GET/PUT /admin/workspace` with `PERM_MANAGE_STAFF`
**When** called
**Then** studio name (80) and address (240, up to 4 lines) are stored encrypted; the signature footer uses them; a caller without the Permission gets 403 on `PUT` and sees the values read-only through `GET /me/signature` (which returns the studio lines inside the preview model).

**Given** S2
**When** it renders
**Then** the left panel has the "Add my signature to replies" toggle, sign-off, name, title, phone; the right panel shows the live preview built by `SignatureRenderer` from the same model the server will use; one **Save changes** per view; the Admin sees a "Studio" block below.

**Given** the toggle is off
**When** previewing
**Then** the preview shows "Signature is off. Replies will end without one."

**Given** the same input
**When** the server and the front end render
**Then** a golden-file test in both runtimes produces the same text (backend unit test and Vitest compare to one shared fixture).

**Given** the leak suite
**When** extended
**Then** Sentinel signature and studio values leave no plaintext.

**Tasks**
- Backend: `V13__signature_and_workspace.sql`, `SignatureService`, `WorkspaceService`, `SignatureRenderer`, controllers.
- Desktop: Signature tab, preview component, Studio block, shared fixture in `docs/fixtures/signature.json` used by both test suites.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && (cd src-tauri && cargo test)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: save signature, read back).

## Dev record

**Assumptions**
- The migration is **V15** (`V15__signature_and_workspace.sql`), not V13 as the story text says: V13 and V14 already exist.
- `signature` is keyed by `user_id` with `on delete cascade` from `app_user`, so `StaffService.delete` needs no extra code (`SignatureIT` deletes a User and counts zero rows). It is created by the first save, like `ai_setting`; version 0 in the API means "no row yet". `workspace` is also created by the first Admin save (fixed id `...00b1`), not by migration: the story's "created by migration through `MigrationCrypto`" was skipped because the lazy singleton pattern is already in the code base and an empty row adds nothing.
- `GET/PUT /api/v1/me/signature` (any signed-in Role, `If-Match`; missing header 400, stale 409). Fields `signoff`, `name`, `title`, `phone` each 80 characters or fewer after trim, one line only (422 `too_long` / `invalid`); `enabled` required (422 `required`). A User with no row gets a switched-off blank with sign-off "Warm regards," and their account name.
- `GET/PUT /api/v1/admin/workspace` needs `PERM_MANAGE_STAFF` (403 otherwise). Studio name 80 characters or fewer, address up to 4 non-blank lines and 240 characters in all; blank lines are dropped and each line trimmed before storing.
- The signature response carries `studio` and the finished `preview` text for every Role, so a User without the Permission sees the Studio read-only.
- Preview text: sign-off, name, title, then `Studio name · phone`, then the address lines; blank parts are dropped; switched off gives an empty string. Matches the wireframe's `build()` with the business name now coming from the Studio. Plain text only; HTML is Story 7.3 on the same renderer.
- No Audit Entry for either save: FR-40 does not list them. If the Studio should be audited, add an `AuditAction` and a writer.
- Signature is the last Settings tab, after Profile, open to every Role; the Admin sees the Studio block inside it, below the signature fields, under one **Save changes** (signature first, then Studio, each with its own version).
