# Story 12.12: Settings frame, Away message on Signature, Staff table

As an Admin,
I want the Away message beside the signature, the Staff list to show real rows, and the Settings tabs to fit the window,
So that Settings matches the approved prototype and nothing says "No staff yet" next to a staff row.

**Assumptions**
- Audit rows G-13 (Staff empty at one row), G-14 (Away on its own Admin sub-tab), G-26 (Settings misc). User decisions 2026-11-11: **move Away to Signature**; **Staff empty only at 0 rows**.
- Prototype: `js/settings.js:55-63` the Signature form, then Away as a `card od-stack` form (Admin only, `data-submit="away"`, margin-top 16px) below it; `:91-97` Staff card with a table, empty only at 0 rows; `css/screens.css:131-133` `.srow` and `.set-col` (720px), `:135-137` `.tbl`; `css/shell.css:61-64` `.tabs`; `css/base.css:92-96` pill-track `.switch`; `css/shell.css:72` compact empty art 144px.
- App today: `Settings.tsx:7` imports `AwayCard`, `:29` `SUBS` includes `'away'`, `:36-38` `fromHash` maps `#/settings/admin/away`, `:100` renders `AwayCard`; `SignatureTab.tsx:26`, `:134`, `:146` (Studio card), `:158` (Preview); `AwayCard.tsx:27`, `:109`; `StaffTab.tsx:188` `.row-actions`, `:208` `items.length <= 1`, `:210` `<img width={160}>`; same `width={160}` at `AuditTab.tsx:71` and `UsageTab.tsx:49`; `styles.css:104-107` `.tabs`, `:125` `.row-actions` nowrap (Staff's six columns overflow at 1100), `:139-142` `.sig-preview`, `:179-180` bare `.switch`; `AuditTab.tsx:91` IP cell is plain (prototype: mono, muted).
- **What changes versus 11.10 and 11.12:** 11.10 deferred Away to 11.12 and left it as an Admin sub-tab. 11.12's placement line ("on the Preferences-side of the admin area") was ambiguous. This story supersedes both: Away lives on the **Signature** tab, Admin only (`PERM_AWAY`), as its own form below the signature form and above nothing else. `Admin > Away` no longer exists as a sub-tab. 11.12's behaviour (fields, permissions, validation, API) is unchanged. 11.10's Settings IA tests and the Away hash tests change as listed below.
- Empty art height for the three tabs: **144px** (12.3 `.empty img`, prototype `shell.css:72` compact). The 160px figure is the whole-view rule in DESIGN.md; Settings tab empties are inside a card, so the compact figure applies. Remove the `width={160}` attributes.
- Dropped from the audit: "Taxonomy appended after the sticky save row" (G-26 part). `AiTab.tsx:373` `TaxonomyCards` is already before the sticky save row at `:374`. Not changed.
- Roles tab and Keys tab keep their current layout beyond the `.set-col` and `.srow` classes from 12.3.

**Then** the signature form (Studio and Preview) is followed by a separate **Away message** card/form in the same tab (prototype `settings.js:55-63`) with the same fields, validation and save behaviour as 11.12.
**Given** a non-Admin
**Then** the Away card is not rendered on Signature.
Test: `SignatureTab.test.tsx` `it('shows the Away form below the signature for admins only')`; update `AwayCard.test.tsx:31`.

**Given** `SUBS` in `Settings.tsx`
**Then** it no longer contains `'away'`, and the Admin sub-tabs are the others only.
**Given** a stored or bookmarked hash `#/settings/admin/away` or `#/settings/away`
**Then** `fromHash` opens Signature (no blank screen, no thrown error) and scrolls to the Away card.
Test: update `AwayCard.test.tsx:135` (hash) to expect Signature; update `Settings.test.tsx:44`, `:54`, `:60` (sub-tab list and hash cases); add `it('maps the old away hashes to signature')`.

Test: change `StaffTab.test.tsx:75` from "empty state when only the Admin exists" to `it('shows the empty state only at zero rows')` plus `it('shows the table with one row')`.
