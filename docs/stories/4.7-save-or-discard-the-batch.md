# Story 4.7: Save or discard the batch

As a Staff member,
I want to save the reviewed groups as gowns or throw the batch away,
So that the Gallery fills with checked gowns and nothing is left over.

**Assumptions**
- This story creates `gown`, `gown_attribute`, `gown_term` and the `TermIndexer` (architecture §4.3). Search itself is Story 8.2; terms are written now so a Gown never exists without them.
- "Only the newest is New" is `gown.is_new_ct`: Save clears the flag on all earlier Gowns and sets it on the newest created in the batch `[ASSUMPTION]`.
- `gown.seq` comes from a sequence. `gown.day_bidx` = `BidxDomain.GOWN_DAY` of the creation day (A2: UTC).
- Photo ownership moves to the Gown by setting `photo.gown_id` and clearing `batch_id`/`group_id` references. `idem_bidx` stays unique with `batch_id` (null `batch_id` after Save) `[ASSUMPTION]`.
- Save is one transaction; embeddings and discarded Photos are deleted in it, S3 objects in `afterCommit` (the sweep catches failures).
- The Story 3.2 "in use" counter is replaced here with the real count over `gown_attribute` and `upload_group`.
- Save needs `PERM_UPLOAD_IMAGES`. Audit Entries `upload_saved` and `upload_discarded` carry counts only.

**Acceptance Criteria**

**Given** `POST /uploads/{id}/save`
**When** the batch is in `review` with at least one non-empty Group having a name
**Then** one Gown per Group is created with its name, attributes (rows in `gown_attribute`), description, confidence, `day_bidx`, `created_by`; its Photos move to the Gown; `TermIndexer` writes `gown_term` rows from name, Silhouette and Fabric; embeddings, discarded Photos, groups and the batch are deleted; only the newest Gown is New; an Audit Entry `upload_saved` is written; the response is `{saved: n}`.

**Given** a Group with an empty name
**When** Save is requested
**Then** 422 with `fields:[{name:"groups[i].name",code:"required"}]`, nothing is saved, and the UI selects that Group.

**Given** `DELETE /uploads/{id}`
**When** called after the dialog
**Then** the batch, groups, Photos, embeddings and objects are deleted, an Audit Entry `upload_discarded` is written, and the screen resets to empty.

**Given** Save twice (double click or retry after timeout)
**When** the second request arrives
**Then** it returns the first result (the batch no longer exists, and the response is replayed from the `Idempotency-Key`); no Gown is duplicated.

**Given** the sticky footer (U1 review)
**When** it renders
**Then** it shows text button **Discard batch** and primary **Save {N} gowns**; Discard opens "Discard {N} photos? This deletes them and can't be undone." with Cancel focused and a danger button; Save shows a spinner, then the toast "{N} gowns saved to Gallery" and the empty phase.

**Given** a taxonomy value used by a saved Gown
**When** removal is attempted in Settings
**Then** it returns 409 `conflict` with the real `usedBy` count.

**Given** a Gown created here
**When** the Gallery tests (Story 5.1) query it
**Then** it appears with `day_bidx` filtering working.

**Given** the leak suite
**When** extended
**Then** Sentinel Gown names, descriptions and attributes saved from a batch leave no plaintext, `gown_term.term_bidx` holds only envelopes of the right shape, and the objects remaining in the bucket equal the kept Photos times two.

**Tasks**
- Backend: `V12__gown.sql` (`gown`, `gown_attribute`, `gown_term`), `GownFactory`, `TermIndexer`, `SaveBatchService`, `DiscardBatchService`, usage counter swap, user-delete hook from Story 2.3's OPEN QUESTION (default: discard the batch).
- Desktop: footer, dialogs, toast, reset, tests.

## Dev record

**Assumptions**
- Migration is `V14__gown.sql` (V12 and V13 were taken). `photo.batch_id` becomes nullable; `photo_gown_fk` has no cascade, so Gown deletion (Epic 5/6) must delete its Photos in code.
- Replay is keyed by the batch id, not by `Idempotency-Key`: `gown.save_bidx = HMAC(IDEM, "save|<batchId>")` plus `created_by_id`. The Tauri `request` helper cannot send that header, and the batch is gone after the first Save, so a repeat returns `{saved:n}` with no header. The Save button is also disabled while saving. `[ASSUMPTION]`
- Only the newest Gown is New: the previous top Gown (`order by seq desc`) is set `isNew=false` and the last Gown made in the batch gets `isNew=true`. Save follows the review order (low confidence first, then position). `[ASSUMPTION]`
- Photos dropped in review (state `DISCARDED`) are deleted at Save with their stored objects; kept Photos get `gown_id`, `batch_id = null`, `group_id = null`.
- Unknown tag at Save is 422 `groups[i].attributes` `invalid`; blank name 422 `groups[i].name` `required`; no non-empty group 422 `groups` `required`; wrong phase 409; not owned 404.
- Audit detail carries counts only (`gowns=N photos=M`, `photos=N`); `AuditRegistryTest` pending list no longer holds the two actions.
- Taxonomy removal now counts real usage: `GownAttribute` rows plus open-batch Groups naming the value.
