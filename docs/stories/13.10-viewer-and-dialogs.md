# Story 13.10: Gown viewer, edit and delete dialogs

As a Staff member,
I want the gown viewer and its edit and delete dialogs to match the prototype and fit the window,
So that I can see a gown, edit it and always reach Save.

**Assumptions**
- Prototype: `js/gallery.js` (viewer, `v-edit`, `v-del`), `css/screens.css` `.viewer`, `.stage`, `.thumbs`, `.kv`; pairs `viewer-{default,photo-3,edit-dialog,edit-error,delete-dialog}`. Desktop: `desktop/src/gallery/Viewer.tsx`, `EditGown.tsx`.
- VW-09 is a real bug: the Edit dialog content is 974 px (998 px with an error) in an 866 px box; the footer needs an inner scroll or a compact layout. VW-11 changes the facet editor to the prototype's per-facet `fieldset` with an inline checkbox group of every taxonomy option; keep the same save request. The tag chips + select model from story 11.7 is replaced, update its tests.
- VW-04 (Confidence row) and VW-12 (character counter) are desktop-only additions that help the user: keep them and mark `accepted deviation`, unless the user vetoes.
- VW-13: a missing name sets `aria-invalid` with the red outline and a toast "Name is required" (prototype); keep an inline text only if axe needs it (then it is visually hidden).
- Dates (VW-05) use the 13.3 formatter (D1 assumption (a)).

**Acceptance Criteria**

**Given** the viewer (VW-01, VW-02, VW-03, VW-14)
**When** it renders
**Then** the title row has the `New` pill and four action buttons on one right-aligned row above a two-column grid; the breadcrumb `Gallery` is accent blue 500 text-sm

**Given** the stage (VW-06, VW-07)
**When** photos are shown
**Then** the stage is a bordered surface (radius-lg, 520 px portrait) with circular prev/next arrows overlaid on its edges and no count text; thumbnails are 72 px wide 3:4 with a 2 px accent border on the current one

**Given** the details panel (VW-05, VW-08)
**When** it renders
**Then** it is a bordered card (padding 24) with an `h2` Details, a key/value list with a 96 px label column, and the Description block; `Added` reads `Nov 6, 2026`

**Given** the Edit dialog (VW-09, VW-10, VW-11)
**When** it opens, including the error state
**Then** its title reads `Edit "Aurelia"` with curly quotes; each facet is a `fieldset` with a legend and checkboxes for every option; the dialog fits 900 px high with Cancel and Save reachable, `dialog-scroll` and `dialog-overflow` are absent from the probe

**Given** the name is cleared and Save is pressed (VW-13)
**When** validation runs
**Then** the input has `aria-invalid` and the red outline, and a toast reads `Name is required`

**Given** the delete dialogs
**When** they open
**Then** they match the 13.3 dialog (480 px, right-aligned buttons)

**Given** the story's screens are captured on both sides
**When** `node scripts/capture.mjs --side both --only {only}` and `npm run shots:diff -- --only {only}` run
**Then** `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `dialog-scroll` or `dialog-overflow` for the desktop side of these screens (`text-ellipsis` only where the prototype truncates the same text), and the run logs no `UNMOCKED` request and no page or console error

**Given** every audit row listed above
**When** the story is done
**Then** the row's Status in `docs/planning-artifacts/ui-parity/audit.md` is `closed` with the fix commit and the after-screenshot path, or the row says `accepted deviation` with the decision it follows (D1 to D5 in the change proposal) and the reason

**Then** the Dev record has one line per pair: `match`, or the remaining difference and why it is fixture-only noise (SVG gown art, fixed clock, mock data). Pixel % is recorded in the Dev record as a trend and is not a gate
