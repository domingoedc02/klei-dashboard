# Story 21.3: Gallery viewer: full image and full-view lightbox

As a Staff member looking at a gown,
I want to see the whole photo without cropping and open it larger,
So that I can check the dress, not a cut-off part of it.

**Assumptions**
- Reported (screenshot 3, "1 of 3"): the detail image is cropped.
- `object-fit: contain` is already on `.viewer .stage img`. The crop comes from the stage: `.viewer .stage` is a fixed `height: 560px; overflow: hidden` (line 553, overriding `aspect-ratio: 4 / 3` at 339) and the image uses `max-height: 100%` on a grid item. **Unconfirmed:** repro first (task 1) and record the cause; the fix below follows from that.
- Full view = lightbox overlay (user decision), not a separate route.
- The shared lightbox is the one already in `Review.tsx` (`Lightbox({ batchId, photo, index, total, onMove, onClose })`), extracted so Review and Viewer use the same component. Extraction also closes two items deferred in 13.8: Next/Prev disable at the ends and drop focus; focus returns to the first opener, not the last photo viewed.
- Out of scope: pager overlay arrows (VW-06), 72 px 3:4 thumbs (VW-07), details card (VW-08). Those stay in story 13.10 (`status: ready`). **Sequence:** land 13.10 first or accept a merge on `Viewer.tsx` and `.viewer`/`.stage`/`.strip` CSS; 21.3 touches only the stage, one new button and the lightbox.
- Per-pane scroll for the viewer: photos pane and details pane scroll independently inside the sheet; no page scroll (21.1).

**Acceptance Criteria**

**Given** a gown photo of any aspect ratio (portrait, landscape, square), at 1440x900 and at 1100x700
**When** the viewer renders
**Then** the whole photo is visible inside the stage: no edge clipped, aspect ratio kept (`object-fit: contain`), centered, and the stage is no taller than its pane

**Given** the viewer
**When** the details content is taller than the window
**Then** the details pane scrolls on its own and the photos pane stays; the page does not scroll

**Given** the stage
**When** it renders
**Then** a "Full view" button (accessible name "Open full view of photo k of N") is reachable by keyboard and opens the lightbox on the current photo; it is hidden when the gown has no photo

**Given** the lightbox is open
**When** it renders
**Then** it is `role="dialog"` `aria-modal="true"` with an accessible name ("Photo k of N"), shows the full photo within the viewport (no scroll, no crop, `max-height` from the viewport), with a visible Close button, Previous and Next

**Given** the lightbox is open
**When** the user presses Esc or activates Close
**Then** it closes, and focus returns to the "Full view" button that opened it; Esc does not also trigger the Shell window Esc handler (`stopPropagation`)

**Given** the lightbox is open
**When** the user presses ArrowLeft/ArrowRight or activates Previous/Next
**Then** the photo changes within bounds, the "k of N" name and live text update, Previous is disabled on the first photo and Next on the last, and focus stays on a control inside the dialog (it does not fall to `body`); the viewer's selected photo and the strip stay in sync after closing

**Given** the lightbox is open
**When** the user presses Tab or Shift+Tab
**Then** focus stays inside the dialog (trap), and background controls are not reachable

**Given** the full image fails to load
**When** the lightbox shows it
**Then** the existing failed block with Retry is kept (cache-busting `?r=` retry), in both the stage and the lightbox

**Given** Review's photo lightbox
**When** the story is done
**Then** it uses the same extracted component with no behaviour change except the two 13.8 fixes, and the Review tests pass unchanged apart from import paths

**Given** `axe.run` on the viewer and on the open lightbox
**When** it runs
**Then** zero violations

**Given** the story's screens are captured on both sides
**When** `node scripts/capture.mjs --side both --only gallery-viewer` and `npm run shots:diff -- --only gallery-viewer` run
**Then** `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `frame-scroll`, `dialog-scroll` or `dialog-overflow` for the desktop side, with a new capture state for the open lightbox, and the run logs no `UNMOCKED` request and no page or console error
