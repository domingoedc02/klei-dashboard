# Story 21.2: Upload Review: fixed save bar and independent panes

As a Staff member reviewing a batch,
I want the "N gowns · M photos will be added to Gallery" bar fixed at the bottom of the app and the review content to scroll above it,
So that the bar never covers the tag selects or the Sleeve and Train fields, and Confirm and save is always in reach.

**Assumptions**
- Reported (screenshot 1): the bar (hint, Undo, Discard batch, "Confirm and save 26 gowns") overlaps the tag selects and the Sleeve/Train fields.
- Reverses part of story 13.7 (UR-01/UR-22: "sticky savebar pinned over scrolled content"). The bar is no longer `position: sticky` inside the one scrolling sheet; it is the last row of a column whose row above scrolls. Visual parity with the prototype stays: full-width of the pane, 16/32 px padding, top border.
- Scrolling model: the review screen fills the sheet. Group list (left) and editor (right) each scroll in their own pane; the save bar is outside both. The banner and any problem line stay above the panes, never inside a scroller.
- `Review.tsx` is only one state of the Upload route, so the sheet cannot be switched by route. **Open choice for Dev:** `.sheet:has(> .review)` (check the minimum WKWebView/WebKitGTK/WebView2 supports `:has`), or a flag the screen sets on the shell. Pick one, record it, and keep the sheet padding contract in `styles.test.ts` line 81 for every other screen.
- Replaces the `.rv-list { max-height: 600px }` cap (13.7, UR-03): the list height now comes from the pane.
- The probe exemption `under.r.bottom > bar.r.top` (`probe.mjs` ~line 85) hid this bug (13.8 rejected the finding). It must stop exempting bars that can overlap content.

**Acceptance Criteria**

**Given** a batch of 26 gowns and 67 photos, at 1440x900 and at 1100x700
**When** the review screen renders
**Then** the save bar is at the bottom edge of the content area, full width of the sheet, and the page has no vertical scroll

**Given** the editor content is taller than the pane
**When** the user scrolls it
**Then** only the editor pane scrolls; the group list, the heading, the banner and the save bar do not move

**Given** a long group list
**When** the user scrolls it
**Then** only the list scrolls; the editor and the bar do not move

**Given** any scroll position
**When** the tag selects, Sleeve, Train, description and Organize rows are scrolled to the bottom
**Then** the last field ends above the bar with no overlap and no hidden control (`probe.mjs` reports no `overlap` or `covered` against `.savebar`)

**Given** Tab moves focus to a field near the bar
**When** the browser scrolls it into view
**Then** it lands inside the editor pane, fully above the bar

**Given** the bar
**When** it renders
**Then** it keeps the copy and controls: "N gowns · M photos will be added to Gallery", Undo, Discard batch, "Confirm and save N gowns", with the existing enable rules and `locked` gating; the problem line (`role="alert"`) stays visible above the bar

**Given** the probe
**When** a bar overlaps scrolled content
**Then** the exemption no longer hides it: the exemption applies only to a bar that is the last row of a non-scrolling parent

**Given** `styles.test.ts`
**When** it runs
**Then** the review test (line 103) asserts the new contract: `.rv-list` scrolls by pane (no `max-height: 600px`), `.savebar` is a non-sticky last row with no negative margins, padding `var(--space-4) var(--space-8)` and the top border kept

**Given** the story's screens are captured on both sides

**Then** `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `frame-scroll`, `dialog-scroll` or `dialog-overflow` for the desktop side (`text-ellipsis` only where the prototype truncates the same text), and the run logs no `UNMOCKED` request and no page or console error

**Dev Notes**
- Files: `desktop/src/upload/Review.tsx` (`Review` root: `div.review > div.banner, div.rv, problem <p role=alert>, div.savebar`), `desktop/src/styles.css` (`.review` 243, `.rv` 246, `.rv-list` 247, `.editor` 258, `.savebar` 301-303, `.savebar .actions` 672, `.review > .banner/.error` 666-671), `desktop/scripts/shots/probe.mjs` (~61, 85, 102-104), `desktop/src/styles.test.ts` 103-114.
- Root cause: `.savebar { position: sticky; bottom: 0; margin: var(--space-2) calc(var(--space-8) * -1) calc(var(--space-12) * -1) }` lives inside the single scrolling `.sheet`. The negative bottom margin pulls it into the sheet's bottom padding, and sticky lets it float over unscrolled content, so it covers the last rows (tag selects, Sleeve, Train) whenever the editor is taller than what is left of the viewport. `.rv { align-items: start }` plus `.rv-list { max-height: 600px }` leave nothing to scroll independently.
- Depends on 21.1 for the frame invariant (no page scroll).
