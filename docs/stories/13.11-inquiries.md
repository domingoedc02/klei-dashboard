# Story 13.11: Inquiries: list, thread and composer

As a Staff member,
I want the Inquiries inbox to match the prototype, with Send always in view,
So that I can read a thread and reply without scrolling the whole page.

**Assumptions**
- Prototype: `js/inquiries.js`, `css/screens.css` `.inbox`, `.mini-tabs`, `.msg`, `.rte`; pairs `inquiries-{default,loading,empty,filtered-empty,thread-replied,thread-closed,composer-error,customer-card}`. Desktop: `desktop/src/inquiries/*.tsx`.
- IQ-02 is the P1: the composer sits in flow after the messages and the page scrolls, putting Send below the fold at 1440x900. The inbox is a fixed-height two-pane view (836 px at 1440x900, hairline pane borders, h1 `Inquiries` 20 px in the left pane head); the thread pane scrolls inside itself and the composer is pinned to its bottom.
- **Decision D1 (IQ-08), pending the user's answer.** Assumed option (a): list and thread times use the 13.3 formatter (`9:42 AM`, `Yesterday`, `Nov 3`, `Oct 28`, `Jun 14, 2027`, `Oct 2026`, `Just now`) and keep the date-format preference for absolute dates elsewhere.
- IQ-09: the prototype opens with `i1` selected, so `loading`, `filtered-empty` keep the thread and composer in the right pane. Desktop opens with nothing selected until a row is chosen; the capture hooks open `i1` first, and the product keeps its current behaviour (accepted deviation unless the user wants auto-select).
- IQ-15: reply subject is `Re: {subject}` as in the prototype. Check the existing send contract before changing; if the backend already prefixes, only the field display changes.
- IQ-16: the desktop signature preview block ("Added when you send") has a spec reason (FR-31). Keep, restyle quietly inside the composer, and mark `accepted deviation`.
- IQ-21: the customer card opens from any `[data-cust]` (list name, message avatar, sender link) and anchors to the click; link `View profile` is a full-width small secondary button.

**Acceptance Criteria**

**Given** the inbox frame (IQ-01, IQ-09)
**When** it renders at 1440x900
**Then** two panes with hairline borders at the prototype width, h1 `Inquiries` at 20 px inside the left pane head, and the right pane never scrolls the page

**Given** the list (IQ-03, IQ-04, IQ-05, IQ-06, IQ-07, IQ-13, IQ-19)
**When** rows render
**Then** no avatar; line 1 name + right-aligned time, line 2 subject, line 3 one-line preview; unread = name 700 and no dot; the selected row has a tinted surface and a 3 px accent left border; the mini-tabs are 12/600 pills with the active one dark; pills are New blue, Replied green, Closed grey; initials are the first letters of each word (`HW`); loading is five two-line skeleton rows

**Given** a thread (IQ-10, IQ-11, IQ-12, IQ-18)
**When** it renders, replied and closed
**Then** the head has h2 + `N message(s)` + the status pill at the far right with the status select below; each message is a bordered card with a grey header band; a closed thread shows the neutral `.banner` pinned at the pane bottom with a secondary `Reopen`

**Given** the composer (IQ-02, IQ-14, IQ-15, IQ-16, IQ-17)
**When** a thread is open
**Then** Send is visible without scrolling the page at 1440x900; the composer is a bordered card with To / Subject rows (64 px label, hairline) and one editor box; the subject defaults to `Re: Fitting availability for a June wedding`; the error state sets `aria-invalid` and uses the prototype message and alert icon

**Given** the empty states (IQ-20)
**When** `empty` and `filtered-empty` render
**Then** the heading is `text-xl` with the art centred in a 420 px block

**Given** the customer card (IQ-21, IQ-22)
**When** it is opened from a list name, a message avatar and a sender link
**Then** it opens from all three and shows a full-width `View profile` button and `Jun 14, 2027`

**Given** times and dates (IQ-08)
**When** a list renders
**Then** they follow the 13.3 formatter; if D1 is answered differently, the row is updated in this story and the Dev record names the answer

**Given** the story's screens are captured on both sides
**When** `node scripts/capture.mjs --side both --only {only}` and `npm run shots:diff -- --only {only}` run
**Then** `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `dialog-scroll` or `dialog-overflow` for the desktop side of these screens (`text-ellipsis` only where the prototype truncates the same text), and the run logs no `UNMOCKED` request and no page or console error

**Given** every audit row listed above

**Then** the row's Status in `docs/planning-artifacts/ui-parity/audit.md` is `closed` with the fix commit and the after-screenshot path, or the row says `accepted deviation` with the decision it follows (D1 to D5 in the change proposal) and the reason
