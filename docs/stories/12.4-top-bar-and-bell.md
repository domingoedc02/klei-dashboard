# Story 12.4: Top bar and bell

As a Staff member,
I want the top bar to match the wireframe and stay usable at the 1100px minimum window,
So that the search box keeps its width, the buttons are recognisable and the bell shows what is unread.

**Assumptions**
- Audit row G-24 (minor, static until 12.1 renders it). Also touches group C (selector collisions): `.tools` is defined twice (`desktop/src/styles.css:45` for the top bar, `:255` for Review); this story scopes the top-bar one so 12.5 can fix the Review one without a clash.
- Prototype: `.topbar` and `.icon-btn` (36px square, `css/shell.css:30-33`), `.icon-btn .dot` (8px at `top: 6px; right: 6px`, 2px border in the bar colour so it reads as a cut-out), `.profile-btn` (avatar + chevron, `css/shell.css:37`), `.menu` (`css/shell.css:39-45`), the bar content from `K.topbar` (`js/data.js:99-125`): search, `AI Assistant` as `btn btn-secondary btn-sm` with the spark icon, bell, profile; bell menu header + per-item unread dot (`.unread-dot`, 8px, `css/screens.css:40`).
- App today: `desktop/src/shell/Shell.tsx:277-298` renders the AI button as a plain `.btn` with no icon, the profile button as `Avatar` + the full name with no chevron and no accessible label beyond the name; `Bell.tsx:72-108` renders a bell button with a `.dot` (`styles.css:395-396`) and a menu with items as bare buttons. At 1100px a long name (`Alexandria Montgomery-Reyes`) squeezes the search box.
- Not changed (DESIGN.md wins): focus ring colour, `--space-control` 32px for buttons. The bell keeps its 32px tap target only if `DESIGN.md` says so; the prototype's 36px `.icon-btn` is used for the bell because it is an icon-only control (DESIGN.md: "icon buttons 36px", verify at `DESIGN.md` components section before coding; if it says 32px, keep 32px and note it in the Dev record).
- Reuse: `Icon` (`spark`, `bell`, `chevron-down` already in `shell/icons.tsx`), `Avatar`, existing `useClickAway`/Esc handling in `Shell.tsx:225-236`. No new component.
- Drawer wiring: the AI button gets `aria-expanded={!!drawer}` and `aria-controls="assistant-drawer"`; the `aside.drawer` in `DrawerHost` (`Shell.tsx:105`) gets `id="assistant-drawer"`. Esc and focus return already exist (`Shell.tsx:225`).
- Out of scope: search box behaviour (`SearchBox`), notifications API, sign-out flow.

**Acceptance Criteria**

**Given** an Admin or Staff signed in with the AI permission
**When** the top bar renders (prototype `js/data.js` `K.topbar`)
**Then** the AI button is `btn sm` with the spark icon and the text "AI Assistant", has `aria-expanded="false"` and `aria-controls="assistant-drawer"`, and flips to `aria-expanded="true"` while the drawer is open. Test: `Shell.test.tsx` clicks it and asserts both attribute states and that `#assistant-drawer` exists.

**Given** a signed-in user named "Alexandria Montgomery-Reyes"
**When** the bar renders at 1100x700
**Then** the profile button shows the avatar, the name truncated with an ellipsis within `max-width: 160px`, and a chevron-down icon; its accessible name is `Account menu, Alexandria Montgomery-Reyes` (visible text contained in the name); the search box keeps at least 360px. Test: `Shell.test.tsx` asserts `getByRole('button', { name: /Account menu/ })` and `aria-haspopup="menu"`; harness: search box width ≥ 360px at 1100.

**Given** the bell
**When** it renders
**Then** it is an icon button of the prototype size with a 2px-bordered 8px dot when anything is unread, and the dot is absent when nothing is unread. Test in `Bell.test.tsx`: dot present with 2 unread items, absent with 0.

**Given** the bell menu is open with read and unread notifications
**When** it renders
**Then** it has a header row (title "Notifications"), each unread item shows an 8px unread dot, read items do not, and the dot is `aria-hidden` while the item text carries "Unread" for assistive tech via `.sr-only`. Test: query `getByRole('menuitem', { name: /Unread/ })` count equals the unread fixtures.

**Given** the Review screen is open
**When** `.tools` styles apply
**Then** the top-bar rule is scoped as `.topbar .tools` so the Review rule at `styles.css:255` no longer changes the bar (harness: bar buttons stay right-aligned on the Review screen at 1100x700). `styles.test.ts` asserts the text `.topbar .tools` is present and a bare top-level `.tools { margin-left: auto` is not.

**Given** the keyboard
**When** the user tabs through the bar
**Then** order is search, AI Assistant, bell, profile; each shows a visible focus ring; Esc closes the bell menu and the profile menu and returns focus to their buttons (existing behaviour, asserted again). axe zero violations in `Shell.test.tsx`.

**Given** the harness
**When** `node infra/ci/shots.mjs --only bell-open` and `--only dashboard` run at 1100x700 and 1280x800
**Then** the clipped-text check (d) and overflow check (a) pass for the bar, and the bell menu is fully inside the viewport.

**Tasks**
- `desktop/src/shell/Shell.tsx` (`:97-111` drawer id, `:277-298` buttons), `desktop/src/shell/Bell.tsx` (`:72-108` header, unread dots), `desktop/src/styles.css` (`:40-45` scope `.topbar .tools`, `:395-396` bell, `.profile-btn` truncation, `.icon-btn`, `.unread-dot`).
- Tests: `Shell.test.tsx`, `Bell.test.tsx`, `styles.test.ts`. Existing tests that find the profile button by its name (`getByRole('button', { name: 'Ej Admin' })`-style queries) change to a regex on the new name; list the changed ones in the Dev record.
