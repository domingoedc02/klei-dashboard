# Story 2.1: Mail port, Invitation and email verification

As an Admin,
I want to invite a person by email and have them set a password and confirm their address on a web page,
So that new staff get access without me ever seeing their password.

**Assumptions**
- Only the create-invite endpoint (`POST /api/v1/admin/users`) is built here, so the flow is testable. List, edit, resend and delete come with the screen in Story 2.3.
- Pages A2 and A3 only. Invitation valid 7 days (architecture §6.1); the verify code or link valid 30 minutes (PRD FR-3).
- `[ASSUMPTION]` After a successful verify, the page says "Email verified. Open Klei Bridal and sign in." because the Deep Link needs a PKCE challenge that only the app can start. The wireframe's "straight to dashboard" is not possible on the Auth Web.
- Sign-in by an unverified User sends them to A3 instead of issuing a code.
- Mail goes to Mailpit `mailpit:1025` in dev and test. Production SMTP provider: OPEN QUESTION (operator, before go-live; does not block).

**Acceptance Criteria**

**Given** `MailPort.send(template, to, model)` with templates `invite`, `verify`, `reset`, `reply`
**When** a template is rendered
**Then** it is a classpath Thymeleaf text file, subjects and file names have CR/LF and path separators stripped, STARTTLS and certificate checks are required outside dev, and each template has a leak test asserting its output holds only its allowed variables (architecture §8.2).

**Given** an Admin posts `POST /admin/users {name, email, roleId}`
**When** the email is new
**Then** an `app_user` row is created with status Invited, an `auth_credential` row (`kind=invite`, `secret_bidx`, `expires_at_ct`, `invited_by_id`, `role_id`) is stored, one mail is sent asynchronously with a link whose token sits in the URL fragment, an Audit Entry `user_invited` is written, and the response is 201 whether or not the email already existed in another form (no enumeration to the Admin is needed here: an existing email returns 409 `conflict`).

**Given** the Invitation link
**When** A2 opens
**Then** `fragment.js` moves the token into a hidden field and clears the fragment; the page shows the read-only email, "Invited by {name} as {Role}", full name, password with a 4-bar strength meter and word, confirm password, the rule "At least 8 characters and one number" and **Create account**.

**Given** an expired or used link
**When** A2 opens or posts
**Then** it shows "This invite link has expired. Ask your admin to send a new one." with no form.

**Given** valid fields
**When** the form is posted with CSRF
**Then** the password is hashed with Argon2id and stored wrapped, the invite credential is consumed by deletion, a `verify` credential (6-digit code, HMAC in `code_ct`, plus a link token) is created, a verify mail is sent, and A3 is shown.

**Given** field errors
**When** posted
**Then** they show under the fields: mismatch "Passwords don't match.", rule failure text; password over 128 characters is refused.

**Given** A3
**When** the code is wrong, expired, or attempted more than 5 times in 15 minutes
**Then** it shows "That code is incorrect or has expired." and the credential locks after 5 attempts.

**Given** **Resend** on A3
**When** pressed
**Then** the previous credential is invalidated, a new one is sent, the button is disabled for 30 s with a countdown, and "A new code is on its way." shows.

**Given** a correct code or the link
**When** submitted
**Then** `verified_ct` is set, the credential is deleted, an Audit Entry `email_verified` is written, and the page shows "Email verified. Open Klei Bridal and sign in."

**Given** an unverified User with correct credentials on A1
**When** the form is posted
**Then** no auth code is issued and A3 is shown with a new code.

**Given** the mail output
**When** inspected
**Then** `invite` and `verify` contain only generic text, a link and (for verify) the code; the inviter and Role are shown on the page, not in the mail.

**Given** the leak suite
**When** extended
**Then** it invites a Sentinel name and email, completes A2 and A3 through the scripted web flow, and asserts no Sentinel in tables, S3, logs or Mailpit beyond the recipient address.

## Dev record

**Done**
- `MailPort` + `MailTemplate` (core); `SmtpMailAdapter` (app): Thymeleaf text templates `mail/{invite,verify,reset,reply}.txt`, 2-thread daemon pool, sent after commit, failures logged by template name and exception class only, recipient and header sanitising. Compose backend env now carries SMTP, from-address and Auth Web base URL.
- V6 `auth_credential` (all columns encrypted; `secret_bidx` unique; FKs `user_id`, `invited_by_id`, `role_id`). `CredentialService`: invite, peek, accept, issueVerify, resend (30 s), verifyCode (5 attempts), verifyLink.
- Auth Web: A2 `/invite` and A3 `/verify` (+ `/invite/open`, `/verify/link`, `/verify/resend`). Tokens ride in the URL fragment; `fragment.js` moves them into a POST body, so no server log sees them. Unverified sign-in at A1 mails a new code and shows A3.
- `POST /api/v1/admin/users` (`PERM_MANAGE_STAFF`): 201 `InvitedUser`, 409 on existing email, 422 on bad role or input.
- Leak suite: five `auth_credential.*_ct` entries, Mailpit inbox and raw sources scanned for sentinels; recipient and mailed tokens excluded by design.
- `docs/api/openapi.json` and `desktop/src/api/schema.d.ts` regenerated.

**Checks run**
- `cd backend && ./mvnw verify`: 73 integration + unit tests pass (InviteFlowIT 9, AuthWebIT 20, LeakSuiteIT 5, MailTemplateTest 4, ArchitectureTest 7, BackendIT table list and V6 updated).
- `cd desktop && npm test` 32 pass; `npm run types:check` clean.
- `node infra/ci/axe.mjs`: 12 Auth Web pages, 0 violations.
- `docker compose ... --profile dev up -d --build --wait && infra/ci/smoke.sh`: SMOKE PASS, including invite mail, A2 password, A3 code, bad code 400, invited User sign-in, no credential left, invitee email absent from `pg_dump`.
- Rust untouched; `cargo test` not re-run.

**Shortcuts**
- No mail retry or outbox: a failed auth mail is only logged; the User retries via resend or by signing in again.
- Verify attempts limited in memory (`RateLimiter`, per user) plus `attempts_ct`; link verification has no counter (256-bit secret).
- After verify the page says "Email verified. Open Klei Bridal and sign in." (no Deep Link: PKCE starts from the desktop app).
- A2/A3 landing states need JavaScript (noscript message) because the token is in the fragment.
- `reset` and `reply` templates exist but are unused until stories 2.2 and the Inquiries epic.
- Admin invite has no idempotency key; 409 on duplicate email covers it.
- axe not run on the `open` and `link` landing states.
- `smoke.sh` now needs a fresh database (counts rows before the invite step adds a User).
