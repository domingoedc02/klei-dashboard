# Story 12.5: Review layout fixes

As a Staff member reviewing a batch,
I want the group list, the editor and the save bar to sit apart and stay readable,
So that I can read every label, select a group and confirm without anything covering anything.

**Assumptions**
- Audit rows G-01, G-02, G-03, G-04 (interim), G-06, G-15, G-19, G-20. These are the five bugs the user reported on Review. Fixes are CSS plus small markup; the Actions menu is removed later by 12.6, so this story only stops the `.tools` collision.
- Prototype: `.rv` is `320px minmax(0, 1fr)` with `gap: var(--space-6)` (`css/screens.css:57`); `.rv-list` flex column, `gap: var(--space-2)`, `max-height: 600px`, `overflow-y: auto`, `padding: 2px` (`:58`); `.gl` card: 1px border, `--radius-md`, padding `--space-3`, hover surface, selected `border-color: accent` + `box-shadow: 0 0 0 1px accent` (`:59-61`); `.savebar` sticky with full-bleed negative margins (`:78`). Banner at `js/upload.js:55`.
- App root causes (static reading; 12.1 confirms): `.split` is `320px 1fr` (`desktop/src/styles.css:228`) so the editor's min-content (chips, select, 5 tag rows) stretches the track and the left column overlays it; `.grouplist .name` has no `flex: 1; min-width: 0` so the pill is pushed over the editor labels (Silhouette, Fabric, Neckline); `.pill` has no `flex: none`; `.grouplist .row` is defined at `:229` and again at `:598` (merge them); `.grouplist .row` has `border: 0`, `gap: var(--space-1)` between rows (`:226`) and `aria-current` is a flat `--color-active` fill (`:231`) with no ring, so cards read as one block and the selected fill bleeds; `.footer` is sticky inside the padded `.sheet` with no `z-index`, no bottom clearance and positioned `.photos li`/`.menuwrap` painting above it (`:257`), so "AI-written description" ends under it; `.tools` at `:255` and the top-bar `.tools` at `:45` collide; `.form` carries `margin-top: 16px` (`:131`) so the editor header floats; `.grouplist .text` (`:234`) is dead.
- Frame: after 12.2 the sheet pads `24px 32px 48px`. The footer must bleed to the sheet edges: `margin: 0 calc(-1 * var(--space-page-x)) calc(-1 * var(--space-page-bottom))` and `padding: var(--space-3) var(--space-page-x)`. The sheet pads its bottom by 48px, so a sticky `bottom: 0` footer would float 48px above the sheet edge; use `bottom: calc(-1 * var(--space-page-bottom))` so it docks flush to the sheet bottom.
- Copy and counts (G-06, **not a UI bug**): "3 photos → 3 gowns." is correct (`photosIn(cur.groups)` / `groups.length`, `Review.tsx:213-222`). The state the user saw is three 1-photo groups at confidence 0 ("Group N", Low): the clustering/sensitivity behaviour (`Clusterer.kt:14,19`, `GroupingService.kt:227,238`; Epic 10.4 calibration still `ready`). Backend is out of scope. UI-only change: when every group holds exactly one photo and there are 2+ groups, the banner appends **"Each photo landed in its own group. Raise AI sensitivity in Settings, then upload again."** with a link to `#/settings/ai`. Admin-only link text: if the user lacks the settings permission, show the sentence without the link. `[ASSUMPTION]` the Settings tab id is `ai` (`Settings.tsx:23-31`); confirm and use the real id.
- Count consistency: `uploaded` (`Review.tsx:89`, summed from the first load's `photoIds`) feeds the Discard dialog at `:191`, while the banner uses live staged photos. When a photo was discarded before opening Discard, "The N uploaded photos" should still be the original count. First task: confirm `uploaded` equals `batch.ids.length` from `Upload.tsx` for a fixture with an unassigned photo; if they differ, pass `uploaded={batch.ids.length}` from `Upload` into `Review` and use it. If equal, add the assertion only and note "no bug" in the Dev record.
- Toasts (G-15): `.toasts` is fixed bottom-right at z 40 (`styles.css:95`), so toasts after Merge/Undo cover "Confirm and save". Use `body:has(.review .footer) .toasts { bottom: calc(var(--space-6) + 72px); }` (WKWebView supports `:has`). Footer height token: `--footer-h: 72px` declared on `.review`.
- Processing grid (G-19, belongs to the same file): `.proc-grid` becomes `repeat(3, minmax(0, 1fr))`; 12.7 reshapes it further.
- Keyboard (G-20): `.chip button:focus-visible` gains `outline-offset: 2px` (`styles.css:186`); `.sheet { scroll-padding-bottom: 72px }` so a focused field is never left under the footer; the group list is a list of buttons (Tab order) and stays so; arrow-key navigation is explicitly **not** added (out of scope, 12.14 revisits).
- z-order: `.footer { z-index: 5 }`, `.photos li` and `.menuwrap` keep `position: relative` with `z-index: auto`, so the footer paints above them; the menu popovers (`.menu`, z 20) stay above the footer.
- Photo menu clipped by `.sheet` (G-20): the photo `Menu` is replaced in 12.6, so only record the clip as superseded.

**Acceptance Criteria**

**Given** the Review fixture (three 1-photo Low groups) at 1100x700
**When** the harness renders it
**Then** no "Low · check" pill rect intersects any editor label rect (Silhouette, Fabric, Neckline), the left column is exactly 320px wide, and the grid has no horizontal overflow (checks (a) and (b) pass). Test: `styles.test.ts` asserts `.split` uses `320px minmax(0, 1fr)`, `.split > *` has `min-width: 0`, `.grouplist .name` has `flex: 1` and `min-width: 0`, and `.pill` has `flex: none`.

**Given** a list of groups
**When** rendered (prototype `.gl`)
**Then** each card has a 1px `--color-sheet-edge` border, 8px between cards, and the selected card shows an accent border plus a 1px ring; the selected fill no longer bleeds into neighbours. `styles.test.ts`: exactly one `.grouplist .row` rule block exists (duplicates merged) and no `.grouplist .text` rule remains.

**Given** the Review editor scrolled to its end at 1100x700
**When** the harness checks the footer
**Then** the "AI-written description" label, the textarea and the count line sit fully above the footer (check (c) passes), the footer spans the sheet width edge to edge, and it paints above `.photos` and `.menuwrap` (z-index 5, `styles.test.ts`).

**Given** the footer
**When** it holds the summary text, Undo, Discard batch and Confirm
**Then** they wrap rather than overlap at 1100px (`gap: var(--space-3)`, `flex-wrap: wrap`) and Confirm stays last and visible.

**Given** the top bar and the Review editor both use `.tools`
**When** Review is open
**Then** the top bar buttons stay right-aligned (rule scoped in 12.4) and the editor header row shows the group name heading left and the Actions button right on one line, with `.editor.form { margin-top: 0 }`. (Interim: 12.6 deletes the Actions button.)

**Given** every group has exactly one photo
**When** Review renders
**Then** the banner reads "3 photos → 3 gowns. 3 groups with low confidence, worth a look." and then "Each photo landed in its own group. Raise AI sensitivity in Settings, then upload again."; with one group of 2+ photos present the hint is absent. Test in `Review.test.tsx` for both cases. The counts do not change.

**Given** the user merges two groups or presses Undo
**When** the toast appears on Review
**Then** it sits above the footer and does not intersect the Confirm button (harness screen `upload-review-toast`, an `act` hook in `fixtures.mjs`).

**Given** Processing
**When** the grid renders at 1100x700
**Then** the three columns each take a third of the content width and no column is wider than its siblings.

**Given** the Discard dialog after one photo was discarded
**When** it opens
**Then** the body states the original uploaded count. Test: `Review.test.tsx` discards a photo, opens Discard batch and asserts "The 3 uploaded photos" (value per fixture).

**Given** keyboard use
**When** Tab reaches the description textarea
**Then** it is fully visible above the footer (`scroll-padding-bottom`), and the chip remove button shows an offset focus ring. axe on Review stays at zero violations (existing runs).
