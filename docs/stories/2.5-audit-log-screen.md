# Story 2.5: Audit log screen

As an Admin,
I want to read an append-only list of what happened in the studio,
So that I can check who did what and when.

**Assumptions**
- `audit_entry`, the immutable trigger and `AuditService` exist from Story 1.4. Each feature story writes its own entries; this story shows them.
- Offset paging, 50 rows per page, newest first by `seq`, "Page n of m" (architecture §4.4). No filter in the MVP.
- Timestamps show in the browser's timezone until Story 6.3 adds the Timezone preference.
- Actions are a closed `AuditAction` enum in `core`; the screen maps each code to a plain label and shows an unknown code as-is.

**Acceptance Criteria**

**Given** `GET /admin/audit?page=n`
**When** called with `PERM_VIEW_AUDIT`
**Then** it returns 50 entries (timestamp, actor name, action, IP), `page`, `pages`, ordered `seq DESC`; no business text is in the URL; a caller without the Permission gets 403, and that 403 writes its own Audit Entry.

**Given** the API surface
**When** an integration test lists every route under `/admin/audit`
**Then** only `GET` exists, and a direct SQL `UPDATE` or `DELETE` on `audit_entry` fails (trigger).

**Given** the catalogue in FR-40
**When** the test suite runs
**Then** each of these actions has been written at least once by an integration test: sign-in success, sign-in failure, invite, delete, role change, permission change, AI settings change, Upload save, Upload discard, Gown edit, Gown delete, Inquiry status change, Reply sent, key rotation. Entries not yet implemented are listed in a test-visible registry and removed from it by the story that adds them (the registry must be empty when Story 9.2 passes).

**Given** the Audit tab (S8)
**When** it renders
**Then** it shows Timestamp, Actor, Action, IP (mono), **Previous**, "Page {n} of {m}", **Next** (disabled at the ends); Loading is skeleton rows; Error is an error block with Retry; Empty is "No activity yet" with the empty-state art.

**Given** a non-Admin or an Admin without the Permission
**When** they open the route
**Then** the tab is absent and a direct route shows the forbidden view.

**Given** the leak suite
**When** extended
**Then** timestamps, actor ids, names, actions, details and IPs appear in the audit table only as padded envelopes; Sentinel IP values and names do not appear.

**Tasks**
- Backend: `AuditQueryController`, `AuditQueryService` (page and count), registry test.
- Desktop: Audit tab, table, pager, label map, tests, axe.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && (cd src-tauri && cargo test)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: sign-in entry visible at page 1).

## Dev record

**Done**
- Backend: `GET /api/v1/admin/audit?page=n` (`PERM_VIEW_AUDIT`): `AuditQueryService` + `AuditController` return `{items[{id,ts,actor,action,detail,ip}],page,pages}`, 50 rows, `seq DESC` (JPQL on a read-only `seq` mapping), `pages` at least 1, a page past the end is an empty list; `page` below 1 or above 1,000,000 is 422. A caller without the Permission gets 403 and the refusal writes its own `forbidden` entry (existing `ForbiddenAudit`). No write route exists (POST/PUT/PATCH/DELETE give 405).
- `AuditAction` enum in `core` (21 codes); every `audit.record` call site now takes the enum (a bare string no longer compiles at call sites, and `AuditRegistryTest` fails on one). `ProblemCode.METHOD_NOT_ALLOWED` (405) added: a wrong method on a real route used to fall into the 500 handler.
- Desktop: Audit log tab in Settings (gated `PERM_VIEW_AUDIT`): Time, Who, Action (label map, unknown code shown as-is, detail under it), IP, Previous / "Page n of m" / Next (disabled at the ends and while a page loads); skeleton, error block with Retry, empty state "No activity yet" with the art; no edit or delete control.
- OpenAPI snapshot and TypeScript types regenerated.

**Checks run**
- `cd backend && ./mvnw verify -pl app -am`: 102 integration tests, 0 failures (`AuditIT` 5: permission and audited 403, 50 per page newest first with `pages`, row shape, page validation, no write route; `AuditRegistryTest`; `LeakSuiteIT` already covers every `audit_entry` column; existing trigger test covers UPDATE, DELETE, TRUNCATE).
- `cd desktop && npm test`: 62 pass (`AuditTab.test.tsx` 5 incl. axe); `npm run build`, `npm run types:check` ok. Rust untouched (19 pass earlier).
- Compose smoke on throwaway project `kleismoke` (removed afterwards): SMOKE PASS, extended with audit page 200, newest entry is the role change, 2 role entries, page 0 gives 422, DELETE gives 405.

**Shortcuts**
- Registry: `AuditRegistryTest.pending` lists the 8 actions whose features do not exist yet (AI settings, Upload save/discard, Gown edit/delete, Inquiry status, Reply sent, key rotation). Each story that adds a writer removes its line; empty by Story 9.2. The test reads writers from source, not from integration runs; each feature story's own IT must still write its entry.
- Sign-in success and failure are not audited (Story 1.6 decision: routine events would flood the log); lockout, no-access and token reuse are. The AC line naming them is overridden.
- Offset paging over the whole table with a `count`: fine at the sized scale; no filter or search.
- Times use the browser locale until Story 6.3 adds the chosen format and timezone.
- IP column is not set in monospace yet.
