# Story 13.5: Dashboard

As a Staff member,
I want the Dashboard to match the prototype in default, loading and empty states,
So that the day starts on a screen that reads the same as the design.

**Assumptions**
- Prototype: `js/dashboard.js`, `css/screens.css` `.stats`, `.widget`, `.bar`; pairs `dashboard-{default,loading,empty}`. Desktop: `desktop/src/dashboard/*.tsx` and `.dash-*` rules.
- DB-07 is the P1: the AI card in the review phase must show "Batch of 30 photos", "100%" and the full-width 8 px `.bar` above the "Grouped into 10 gowns · 3 need a quick look." line. It reads existing dashboard data; if the dashboard payload lacks the batch size, say so in the Dev record and stop (no API change in this epic).
- DB-06 ("3 appointments today") is a P3 spec question: `GET /dashboard` has no appointments. Assumed: keep date-only sub line and mark `accepted deviation` (no data source). Raise it in review if the user wants it.
- Dates (DB-10, DB-11, DB-09) use the 13.3 formatter (D1 assumption (a)).
- Layout target: 4 fixed stat columns gap 16; widget columns `1.4fr / 1fr` gap 16; the page fits the 900 px fold at 1440x900 (DB-21).

**Acceptance Criteria**

**Given** the stat tiles (DB-01, DB-02, DB-03, DB-04, DB-14)
**When** default and loading render
**Then** labels are uppercase 12/600 tracked .08em, tiles are `.card` padding 24 radius 12 no shadow, figures use display font 700 `--text-2xl`, grid is 4 columns gap 16, and loading keeps the labels and static sub-lines with 40 px x 50 % skeletons

**Given** the AI card in the review phase (DB-07, DB-08, DB-16)
**When** it renders
**Then** "Batch of 30 photos", `100%` and the pill-shaped 8 px `.bar` (not native `<progress>`) show above the grouped line; loading shows the blue `Checking…` pill, the bar skeleton and a 70 % text skeleton

**Given** Recent uploads (DB-09, DB-10, DB-15, DB-19)
**When** default, loading and empty render
**Then** rows have a 40 px thumb, name and meta, right-aligned date, 12 px padding and `--border-soft` dividers; the `View gallery` link stays in loading and in empty; loading is four skeleton rows

**Given** Unread inquiries (DB-11, DB-17)
**When** default and loading render
**Then** rows show the right-aligned time and the unread dot; `Open inbox` stays in loading; loading is three two-line skeleton rows

**Given** widget chrome and columns (DB-12, DB-13, DB-18, DB-21)
**When** the page renders at 1440x900
**Then** cards are padding 24 radius 12 with h2 at `--text-lg`, columns are `1.4fr / 1fr`, and the whole page fits without a page scroll

**Given** the empty state (DB-20)
**When** it renders
**Then** it uses `.empty.compact`: art 144 px, h2 `--text-lg`, padding 32/16, CTA below the text

**Given** the story's screens are captured on both sides
**When** `node scripts/capture.mjs --side both --only {only}` and `npm run shots:diff -- --only {only}` run
**Then** `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `dialog-scroll` or `dialog-overflow` for the desktop side of these screens (`text-ellipsis` only where the prototype truncates the same text), and the run logs no `UNMOCKED` request and no page or console error
