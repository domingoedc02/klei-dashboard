# Story 2.2: Password reset

As a Staff member who forgot a password,
I want to request a reset link and choose a new password,
So that I get back in without asking an admin.

**Assumptions**
- Pages A4 and A5. Reset link valid 30 minutes (PRD FR-5; architecture §6.1 aligned, user ok at Gate 5).
- Reuses `auth_credential` (`kind=reset`) from Story 2.1. No new table.

**Acceptance Criteria**

**Given** A4 (`/forgot`)
**When** any email is posted
**Then** the same message "If an account exists for {email}, you'll get an email in a minute." is shown, the mail is sent asynchronously and a dummy hash runs for unknown emails so response time does not differ; a send failure shows "We couldn't send the email. Try again."

**Given** a known email
**When** posted
**Then** one reset credential exists per User (a new request invalidates the old), a `reset` mail with link and generic text only is sent, and rate limiting is applied per email and per IP.

**Given** A5 (`/reset`) opened from the link
**When** the token is valid
**Then** the form shows new password with strength meter, confirm password, **Update password**; the token travels from the fragment into a hidden field.

**Given** an expired, used or unknown token
**When** A5 opens or posts
**Then** it shows "This reset link has expired. Request a new one." with a link to A4.

**Given** a valid reset
**When** posted
**Then** the password hash is replaced, the credential is deleted, all refresh families of that User are revoked and their `sid` values go to the revoked set, an Audit Entry `password_reset` is written, and the browser goes to A1 with "Password updated. Sign in."

**Given** the leak suite
**When** extended
**Then** a Sentinel email goes through A4 and A5 and nothing appears outside the allowlist; the reset mail holds only the link.

**Tasks**
- `ForgotController`, `ResetController`, templates `forgot`, `forgot-sent`, `reset`, flash message on `login`.
- `RefreshService.revokeAllFor(userId)` (added in 1.6; reuse), session registry revoke.

**Checks**
- `cd backend && ./mvnw verify`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: forgot, read mail from Mailpit, reset, sign in with the new password, old refresh token refused).
- Desktop tests: not applicable (Auth Web only).
- axe-core on A4 and A5.

## Dev record

**Done**
- `CredentialService.requestReset/peekReset/reset`; `RefreshService.revokeAllFor` (it did not exist; 1.6 only had the private `revokeFamily`). Reset replaces the hash, deletes the credential, revokes every refresh family and its `sid`, lifts the sign-in lockout, writes `password_reset`.
- `ForgotController` (A4) and `ResetController` (A5); templates `forgot` (form, sent) and `reset` (open, form, expired, done). The sent state is a mode of `forgot`, not a separate `forgot-sent` template.
- One reset credential per User; a new request replaces the old link. Only Active Users get mail; unknown, Invited and throttled-away addresses show the same page. Each request pays one Argon2id verify against a boot-time dummy hash.
- Throttle: 5 requests per email and 20 per address in 15 minutes (`RateLimiter`, key `reset:<bidx>`); the sixth shows "Too many requests. Try again in N minutes." (429).
- Leak suite: Sentinel `password4` and the reset token (`mailed`) go through A4 and A5; no new `_ct` column.

**Checks run**
- `cd backend && ./mvnw verify -pl app -am`: 80 tests, 0 failures (`ResetFlowIT` 7).
- `node infra/ci/axe.mjs`: 19 Auth Web pages, 0 violations (A4 form/error/sent, A5 form/error/expired/done added).
- Compose smoke on a throwaway project (`COMPOSE_PROJECT_NAME=kleismoke`, volumes removed afterwards): SMOKE PASS, including forgot (known and unknown 200), reset mail, A5 open and reset, replay 410, old access token 401, old refresh token 401, old password 401, new password signs in.
- Desktop and Rust untouched.

**Shortcuts**
- After reset the page says "Password updated. Sign in." with no link into A1: A1 exists only inside a PKCE flow the app starts, so the story's "goes to A1" is a message plus "Open Klei Bridal and sign in". Revisit with the Deep Link work.
- "We couldn't send the email. Try again." is never shown: mail goes out on the background pool and failures are only logged.
- Throttle is in memory and per instance (as sign-in); a reset request is never a hint about the account because the page is identical.
- A reset does not set `verified`; an unverified User who resets still meets A3 at the next sign-in. OPEN QUESTION only if the owner wants a reset to count as mailbox proof.
- A5 landing needs JavaScript (token is in the fragment); axe not run on the `open` landing.
- `smoke.sh` network name now follows `COMPOSE_PROJECT_NAME` so a throwaway stack can be tested without touching dev data.
