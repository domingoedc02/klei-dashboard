# Story 12.1: Screenshot harness

As a developer,
I want one command that renders every desktop screen at the two supported window sizes,
So that overlap, overflow and footer bugs show up before a story is called done (every Epic 11 story ended "Not verified: manual side-by-side").

**Assumptions**
- Audit: `docs/planning-artifacts/ui-fidelity-audit.md`, root-cause group E ("no visual verification"). jsdom runs with `css:false` (`desktop/package.json` `"test": "vitest run"`), so layout is untestable in vitest; this story adds the missing layer. It changes no product code.
- No new repo dependency (user decision 2026-11-11). Playwright runs through `npx`, pinned by version. The cached Chromium is revision **1248** (`~/Library/Caches/ms-playwright/chromium-1248`, `chromium_headless_shell-1248`), which belongs to Playwright **1.64.1** (its `browsers.json`). The `npx` cache holds a 1.64.0-alpha that wants revision 1247, which is not installed, so the command pins `playwright@1.64.1`.
- Command: `cd desktop && npx --yes playwright@1.64.1 --version` must print 1.64.1 without downloading a browser. The script is `infra/ci/shots.mjs` (beside `axe.mjs`; run as `node infra/ci/shots.mjs`). It imports `playwright-core` from the `npx` cache by resolving it with `createRequire` from `$(npm root -g)`/`npx` path. `[ASSUMPTION]` if resolution through `npx` is awkward, the script may instead be run as `npx --yes -p playwright@1.64.1 node infra/ci/shots.mjs`, which puts the package on `NODE_PATH`. First task: try the second form and keep whichever works; record it in the Dev record.
- The app is served by `cd desktop && npm run dev` (Vite, port 1420, `devUrl` in `tauri.conf.json`). Without Tauri, `bridge.request` calls `invoke('api_request', …)` (`desktop/src/bridge.ts:79-80`), which fails. The harness injects `window.__TAURI_INTERNALS__` through `page.addInitScript` using the same shape `@tauri-apps/api/mocks` `mockIPC` builds (`desktop/node_modules/@tauri-apps/api/mocks.js`, `mockIPC(cb, options)` at `mocks.d.ts:129`). `[ASSUMPTION]` the init script inlines the few lines `mockIPC` writes (`transformCallback`, `invoke`) rather than importing the module, because `addInitScript` runs before any bundle loads.
- The `invoke` handler answers `api_request` from a fixture table keyed by `METHOD path` (`GET /api/v1/me`, `GET /api/v1/uploads/current`, `GET /api/v1/uploads/{id}`, `GET /api/v1/taxonomy`, `GET /api/v1/gowns`, `GET /api/v1/inquiries`, `GET /api/v1/dashboard`, `GET /api/v1/notifications`, `GET /health/ready`, and the rest each screen loads). Any other `METHOD path` returns `{status: 200, body: null}` and logs it, so a screen never hangs. The shape is `ApiResponse` (`bridge.ts:23-28`: `status`, `body`, optional `refreshed`).
- Photos load from `klei-img://localhost/…` (`desktop/src/platform.ts:9-12`). The page is `http://localhost:1420`, so the harness routes `klei-img://**` to `infra/ci/tiny.jpg` (already in the repo) with `page.route`, or serves it from the init script by overriding `HTMLImageElement.src`. Pick whichever works; the fixture is one 1x1 JPEG scaled by CSS, which is enough for layout.
- Fixtures live in `infra/ci/shots/fixtures.mjs`, one export per screen state. The Review fixture must include the three groups from the user's screenshot: three 1-photo groups with `confidence: 0`, `band: 'low'`, names "Group 1..3", plus a second fixture with long names and 7 photos in one group (stress case for G-01/G-02).
- Screens (names are the PNG file names): `dashboard`, `upload-empty`, `upload-processing`, `upload-review`, `upload-review-long`, `gallery`, `gallery-empty`, `viewer`, `inquiries`, `inquiries-thread`, `client-profile`, `settings-profile`, `settings-signature`, `settings-preferences`, `settings-notifications`, `settings-staff`, `settings-roles`, `settings-ai`, `settings-usage`, `settings-keys`, `settings-audit`, `assistant-open`, `bell-open`, `sign-in`. Each is rendered at **1100x700** (the minimum window, `desktop/src-tauri/tauri.conf.json:18-21`) and **1280x800**.
- Output: `desktop/.shots/{screen}-{width}.png` (gitignored). Add `desktop/.shots/` to `.gitignore`. A `--only upload-review` flag renders one screen; no flag renders all.
- The script also writes `desktop/.shots/report.json` with, per screen and size, automatic layout checks run in the page: (a) **horizontal overflow**: `document.querySelector('.sheet').scrollWidth > clientWidth`; (b) **overlap**: for every pair of sibling-or-cousin elements inside `.split`, `.grouplist`, `.footer`, `.inq-panes`, `.viewer-body`, `getBoundingClientRect` intersections of text-bearing elements (a pill rect inside a label rect fails); (c) **footer cover**: the `.footer` (or `.savebar`) rect must not intersect the bottom edge of the last focusable control after scrolling `.sheet` to its end; (d) **clipped text**: any element with `scrollWidth > clientWidth` whose computed `overflow` is not `hidden`. The script exits 1 when any check fails. These checks are the machine-readable half of every later story's screenshot AC.
- The checks must **fail on the current code** for Review at 1100x700 (G-01, G-03). That is the proof the harness works; capture the failing `report.json` lines in the Dev record before 12.2 starts.
- Prototype comparison is by eye against the prototype's own screens, which the harness also renders so no one has to open Open Design: `--prototype` serves `'/Users/ej/Library/Application Support/Open Design/namespaces/release-stable/data/projects/98402068-55fa-4114-a99b-5b49051d7af2/index.html'` through `file://` and drives it with the same viewport (`#route` per screen from `js/main.js`/`js/core.js` `K.go`). Output `desktop/.shots/proto-{screen}-{width}.png`. `[ASSUMPTION]` only the screens the prototype has (the ones the audit table cites) are captured; the rest are skipped with a log line. The prototype fixes `.shell` height at 900px (`css/shell.css:2`), so proto shots use 1440x900 and are for comparison of structure and spacing only, not pixel diffs.
- Out of scope: pixel-diff baselines in CI (Story 12.14 decides whether to commit baselines), running in CI, any product code change.

**Acceptance Criteria**

**Given** a machine with the cached Chromium 1248
**When** `npx --yes playwright@1.64.1 --version` runs
**Then** it prints 1.64.1 and starts no browser download.

**Given** `npm run dev` is up on port 1420
**When** `node infra/ci/shots.mjs --only upload-review` runs
**Then** it writes `desktop/.shots/upload-review-1100.png` and `upload-review-1280.png` showing the Review screen with the banner "3 photos → 3 gowns." and the three Low groups, and no request reaches a network (the init script answers every `api_request`).

**Given** the Review fixture on the code before Epic 12 (Story 11.6 state)
**When** the harness runs at 1100x700
**Then** `report.json` lists a failing overlap check for the "Low · check" pill against the "Silhouette" label (G-01) and a failing footer-cover check (G-03), and the script exits 1.

**Given** any screen in the list
**When** `node infra/ci/shots.mjs` runs
**Then** every screen renders without a blank page, an uncaught error or a console error from the app (the script fails on `pageerror` and on `console.error`), and an unanswered `api_request` is logged as `UNMOCKED GET /path`.

**Given** `--prototype`
**When** it runs
**Then** it writes a `proto-*.png` for each prototype screen named in the audit table and logs the ones it skipped.

**Given** the harness script itself
**When** `infra/ci/shots.test.mjs` runs under `node --test`
**Then** the pure overlap function passes three hand-made rect pairs (disjoint, touching edges, overlapping) and returns the right verdicts. (Browser parts are checked by running the script, not by unit test.)

**Given** `git status`
**When** the harness has run
**Then** `desktop/.shots/` is ignored and no PNG is tracked; `desktop/package.json` and `infra/ci/package.json` are unchanged.

- Routes: set `location.hash` per screen (`#/upload`, `#/gallery`, `#/inquiries`, `#/settings/staff` …; `fromHash` in `desktop/src/settings/Settings.tsx` shows the sub ids) and wait for a per-screen ready selector (for Review: `ul[aria-label="Fabric tags"]`).
- `.gitignore`: add `desktop/.shots/`.
- Docs: add a "Screenshot check" section to `docs/ops.md` with the exact commands and the `--only` and `--prototype` flags.
