# Story 5.3: Edit a Gown

As a Staff member with Edit gown details,
I want to correct a gown's name, tags and description,
So that the Gallery stays accurate after upload.

**Assumptions**
- Reuses the tag combobox from Story 4.5.
- Photos are not added or removed here (not in the PRD).
- A Taxonomy rename must re-run `TermIndexer` for every Gown using that value; this story wires the `TaxonomyChanged` event from Story 3.2 to it.
- Edit conflicts use `If-Match`; the dialog shows the conflict dialog on 409.

**Acceptance Criteria**

**Given** `PATCH /gowns/{id}` with `If-Match` and `PERM_EDIT_GOWN`
**When** name, attributes or description change
**Then** the row is updated, `gown_attribute` rows are replaced for changed types, `TermIndexer` rewrites `gown_term` in the same transaction, `is_new` and `day_bidx` do not change, an Audit Entry `gown_edited` (no values) is written, and the response carries the new version.

**Given** an empty name or a value outside the Taxonomy
**When** sent
**Then** 422 with field codes; a stale version returns 409 `conflict`; a caller without the Permission gets 403.

**Given** the viewer
**When** the User holds the Permission
**Then** **Edit** appears; the dialog has name (required), five tag comboboxes, description, **Cancel**, **Save changes**; saving shows the toast "Changes saved" and updates the details pane without reload; Esc with changes opens "Discard changes?".

**Given** a Viewer
**When** G2 renders
**Then** Edit is absent.

**Given** a 409
**When** the dialog is open
**Then** it shows "This gown changed while you were editing. Reload to see the latest." with **Reload**, keeping the typed text in the dialog until reload.

**Given** a Taxonomy rename
**When** saved in Settings
**Then** every Gown using the value has its terms rewritten (integration test with 3 Gowns).

**Given** the leak suite
**When** extended
**Then** Sentinel edits leave no plaintext, including in `gown_term`.

**Tasks**
- Backend: `GownEditService`, event listener for `TaxonomyChanged`, tests.
- Desktop: Edit dialog, discard-changes dialog, optimistic UI, tests, axe.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && (cd src-tauri && cargo test)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: patch a name, stale version is 409).

## Dev record

**Assumptions**
- `PATCH /api/v1/gowns/{id}` needs `PERM_EDIT_GOWN` and an `If-Match` equal to the Gown `version` the viewer read (missing or non-numeric is 400, stale is 409). Body is the same `GroupEdit` as the review step; a field left out stays as it is, `attributes` replaces the whole tag set, a blank `description` clears it. Answer is the re-read `GownDetail` with the new `version`. `[ASSUMPTION]`
- Validation is `UploadGroupService.check`, so the 422 field codes match review (`name` required/too_long, `description` too_long, `attributes` invalid). The rejected value is never echoed.
- An edit that changes nothing is a 200 with the same version, no audit entry. A tags-only edit still bumps the version (forced increment); a name or description edit bumps it once.
- `is_new` and the creation-day index are not touched by an edit. Audit `gown_edited` detail lists the changed field names only (`fields=name,tags`), never values.
- Search words: a name, Silhouette or Fabric change rewrites that Gown's `gown_term` rows; other tag types and the description are not searchable (whole-word search accepted at Gate 3).
- Renaming a Taxonomy value rewrites the words of every Gown that uses a Silhouette or Fabric value, inside the rename's own transaction (`GownTermListener` on `TaxonomyChanged`).
- Edit dialog uses native selects per tag type, as review does (shared combobox still not built).

**Done**
- Backend: `GownEditService`, `PATCH` in `GownQueryController`, `TermIndexer.reindex`, `GownTermListener` (replaces `TaxonomyListeners`), `GOWN_EDITED` writer (removed from `AuditRegistryTest.pending`). `openapi.json` and `schema.d.ts` regenerated.
