# Story 18.4: Install, upgrade and rollback qualification

As the app owner, I want install, manual upgrade, reinstall and rollback outcomes recorded for each supported OS, so that a cutover decision rests on observable user and credential behavior.

**Assumptions**
- Qualification runs only after all required installers and native stories are complete; these are real packaged-app checks and are not replaced by documentation or mocks.
- Electron identity/profile/keychain entry must remain separate from Tauri; production credential migration is out of scope.

**Acceptance Criteria**

**Given** each supported OS/architecture package
**When** a fresh install is performed
**Then** launch succeeds; unsigned first-launch warnings are recorded; app identity/profile is distinct from Tauri; credential storage behavior is recorded without using or migrating a production token.

**Given** a test account with a stored credential
**When** the Electron app is manually upgraded and reinstalled using the documented installer
**Then** credential retention is verified; sign-out removes only the Electron credential entry; Tauri profile/credential state remains unchanged.

**Given** a newer package and a previous package
**When** rollback is rehearsed
**Then** the documented recovery returns to the previous working Tauri distribution or approved prior Electron installer, preserves original Tauri data, and records any Electron data/profile consequences.

**Given** each OS qualification run
**When** results are recorded
**Then** `docs/release-checklist-electron.md` includes OS/architecture and version, artifact SHA-256, fresh install, warnings, manual update, credential retention, profile separation, uninstall cleanup, rollback result, date and operator; each result is PASS, CONCERNS or FAIL with evidence.

**Given** an uninstall
**When** profile and OS credential cleanup are inspected
**Then** behavior is recorded per platform; no claim of cleanup or credential erasure is made unless observed, and any residual data is documented and handled under the approved data-retention decision.

**Tasks**
- `docs/release-checklist-electron.md`: create Electron-only matrix and evidence log; include fresh install, manual update, reinstall, rollback and uninstall cleanup steps.
- `electron/test/packaged-lifecycle.test.ts`: automate only non-destructive package metadata/smoke assertions; never claim this replaces real-OS qualification.
- Qualification operator: run controlled test-account procedures on macOS arm64/x64, Windows x64, Linux x64 AppImage and `.deb`; record artifacts, findings and PASS/CONCERNS/FAIL.

**Dev notes**
- Port no Rust code. Relevant baseline behavior references: `desktop/src-tauri/src/keychain.rs` keychain identity, `desktop/src-tauri/src/lib.rs::run` app identity/protocol lifecycle, `desktop/src-tauri/src/update.rs::gate` dirty protection; behavior references `desktop/src-tauri/src/update_tests.rs` and `desktop/src-tauri/src/session_tests.rs`.
- Existing `docs/release-checklist.md`, `docs/install-guide.md`, `desktop/src-tauri/tauri.conf.json` and `.github/workflows/release.yml` are read-only; Electron records must not be appended there.

**Testing**
- Run lifecycle smoke assertions and complete a signed-out/test-account qualification on every target OS/architecture; record exact package hash and OS version.
- Verify after uninstall/reinstall that Tauri still launches and retains its independent profile and credential entry; never use a deployed or personal production credential.
- Verify Electron update remains manual and only fixed release page opens; record observed Gatekeeper/SmartScreen warnings and cleanup residue.

**Prototype unchanged check**
- Require protected-path diff empty, including existing release guide/checklist, Tauri sources/config/icons, desktop renderer and `.github/workflows/release.yml`; review untracked allowlist.
- Run baseline-vs-Electron parity checks for startup and update at 1440×900, 1280×800 and 1100×700; UI remains unchanged except the documented manual-update exception; no historical parity outputs modified.
