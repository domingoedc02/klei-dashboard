# Story 9.4: Backup, restore and performance benchmark

As the operator,
I want a tested backup and restore and proof that the app meets its speed targets at design scale,
So that I can go live knowing data is recoverable and screens are fast.

**Assumptions**
- Dokploy's scheduled backups for compose apps are unverified (A10, R-19). `infra/ops/backup.sh` runs from Dokploy's scheduler if it supports it, else from host cron.
- Backup order: `pg_dump` first, then copy the bucket, to a destination outside the Dokploy host. Both are ciphertext. The script ends with an integrity report listing rows whose object is missing.
- RPO 24 h, RTO 4 h (architecture §9.3). The backup destination is OPEN QUESTION (operator, before go-live); the script takes it from `KLEI_BACKUP_TARGET`, and has no default.
- Backups and keys live apart: `infra/ops/restore.md` states that restore needs the KEK copies, `KLEI_BIDX_KEY` and `KLEI_JWT_KEY` from the offline copy.
- The benchmark seeds 5,000 Gowns (AR-22) with a seed tool inside the test profile, not in production code. The design scale of 10k Gowns, 100k Photos and 50k Inquiries is exercised once manually with `--scale full`, not on every PR `[ASSUMPTION]`.
- Seeds use the stub AI provider and tiny generated images; no real photos.

**Acceptance Criteria**

**Given** `infra/ops/backup.sh`
**When** run against the dev stack
**Then** it writes a `pg_dump` and then a bucket copy to `KLEI_BACKUP_TARGET`, exits non-zero on any failure, and prints the integrity report (zero missing objects on a healthy stack); it refuses to run if `KLEI_BACKUP_TARGET` is unset.

**Given** the backup files
**When** the leak suite's table check is run over the dump
**Then** no Sentinel appears (the same check as for live tables).

**Given** `infra/ops/restore.md`
**When** followed on a clean machine with the stack and the offline keys
**Then** the app starts, the bootstrap Admin signs in, a seeded Gown opens with its photo, and a Reply thread decrypts; the drill result is recorded as a dated line in the document. The drill runs once before go-live (release checklist).

**Given** a restore without the right KEK
**When** the app starts
**Then** startup check 3 fails with a clear message and no data is exposed or altered.

**Given** `infra/ci/perf.sh`
**When** run on the PR pipeline
**Then** it seeds 5,000 Gowns (with attributes, terms, four Photos each as tiny encrypted objects), 5,000 Inquiries with Messages, then measures and asserts p95 for: Gallery page of 48, filter change, global search, inquiry list page, open thread, open Gown viewer first photo, crypto overhead per page, `GET /dashboard`; targets per PRD NFR-2 (1.5 s, 1 s, 1 s, 1 s, 1 s, 1.5 s, 200 ms; dashboard follows Gallery); it prints a table and exits non-zero on a miss.

**Given** the UI latency targets
**When** the desktop tests run
**Then** a Vitest timing test asserts UI feedback is below 100 ms for key controls with mocked data; cold start to Sign-in screen is measured by the OS smoke job and recorded (not gated until three OS baselines exist) `[ASSUMPTION]`. Desktop idle memory (300 MB) is measured manually per OS and recorded in the release checklist.

**Given** the Upload target
**When** the smoke or perf run executes
**Then** a batch of 30 tiny photos against the stub provider reaches review within 3 minutes plus provider time.

**Given** `docs/ops.md`
**When** written
**Then** it starts with the sentence "Losing every KEK copy loses all data." and covers deploy (stop then start), rollback (restore plus previous image, forward-only migrations), environment variables, key custody, backup schedule, and restore drill steps.

**Tasks**
- `infra/ops/backup.sh`, `infra/ops/restore.md`, `docs/ops.md`.
- `infra/ci/perf.sh`, `infra/ci/seed/` (test-profile seeder), CI wiring for PR to main.
- Release checklist additions.

**Checks**

## Dev record

**Done**
- `infra/ops/backup.sh`: `pg_dump -Fc` first, then `aws s3 sync` of the bucket, into `$KLEI_BACKUP_TARGET/klei-<UTC>/` (written as `.partial`, renamed on success); integrity = `stored_object` ids from the dump missing from the bucket (`missing.txt`); exit 0 ok, 1 step failed, 3 object missing. No default destination. Keys never written.
- `docs/ops.md` (env table, key custody, deploy and rollback, backup schedule, restore drill, performance), `infra/ops/restore.md` (steps, startup failure messages, five checks, drill log), release checklist items for the perf gate, a backup within 24 h, the drill, cold start and idle memory.
- Wrong KEK on a restore: `DekStore.readAll` throws `KeyRingException("wrong_kek", KLEI_KEK_n)`; `KleiApplication.main` prints `klei startup stopped: code=<code> variables=<names>` and exits 1, never a value. Module test in `KeyRotationTest`; smoke boots the real image with a wrong `KLEI_KEK_1` and greps the line.
- Perf: `backend/app/src/test/kotlin/co/klei/app/perf/PerfIT.kt` (off unless `-Dklei.perf=true`; skipped in `verify`), `infra/ci/perf.sh` (PR gate; `--scale full` = 10,000 Gowns, 10 Photos each, 50,000 Inquiries), `.github/workflows/perf.yml`. Seeder writes through the app's own entities and services, so every column is encrypted. Results at 5,000 Gowns x 4 Photos and 5,000 Inquiries, p95 ms against budget: Gallery page of 48 17 (1500), cursor page 25, filters 14-16 (1000), search 4-8 (1000), Inquiry list 5 (1000), thread of 41 Messages 5 (1000), viewer first photo 10 (1500), Dashboard 22, Inbox badge 2, Bell 1, crypto 384 decrypts 0 (200). Carry-overs closed: Taxonomy rename reindex of about 1/3 of 5,100 Gowns 839 ms (no background job needed), delete 100 Gowns 77 ms.
- UI feedback under 100 ms: `desktop/src/shell/feedback.test.tsx` (filter chip pressed and Bell menu open while the request is still out).
- Smoke block 8: `backup.sh` on the live smoke stack exits 0 with `missing=0`; the dump read by `pg_restore -f -` holds none of the run's sentinels, no Admin email, no Taxonomy words; no bucket object starts with a JPEG header; a removed bucket object gives exit 3, `missing=1` and its id in `missing.txt`; wrong KEK stops the boot naming `KLEI_KEK_1`, value not printed. `KLEI_SMOKE_KEEP_BACKUP=<folder>` copies the clean backup out for a drill.
- Restore drill run once on throwaway project `kleirestore` from that backup (line in `restore.md`): restored, backend up in about a minute, Admin signed in, Gowns and a full photo read, Inquiries listed, Keys status all rows on KEK 1; stack removed.
- Final checks: 266 IT run (+ PerfIT skipped) / 121 unit, 346 desktop (27 files), tsc clean, cargo 54 unit + 4 contract, clippy clean, compose smoke PASS (project `kleismoke`, torn down).

**Assumptions**
- RPO 24 h and RTO 4 h as in architecture §9.3; backup destination, retention and the scheduler (Dokploy or host cron) are the operator's (OPEN QUESTION, no default). Holder of the offline keys (OQ-5) still blank in `key-custody.md`.
- The PR gate runs the 5,000 Gown scale, not the full 10,000 / 100,000 Photos / 50,000 Inquiries scale of NFR-2.
- Photos of one Gown share two sealed objects (a stored object is at least 64 KB padded).

**Not verified**
- `--scale full` has never run; `perf.yml` has never run on a hosted runner (slower, shared; a miss there is a prompt to look).
- Perf uses an in-memory object store, so S3 latency is not in the numbers; the Upload target (30 tiny photos to review in 3 minutes plus provider time) is covered for flow only.
- Cold start (< 3 s) and idle memory (< 300 MB) per OS are manual (release checklist). Real-OS look not checked.
- Drill ran against a throwaway stack on the dev host with small data; check 4 (thread with a Reply) skipped; no real backup destination, no Dokploy scheduler. The operator's first drill is still due.
- No two-KEK restore drill (rotated stack restored with an old KEK removed) beyond the module test.

**Shortcuts**
- `backup.sh` does no retention and no off-host push; the destination is expected to be a mount that does both.
- Backup is dump then bucket, not a point-in-time pair: an object saved between the two steps shows as `not-in-dump`, never as lost data.
- Perf budgets are the PRD targets; Taxonomy rename and delete 100 Gowns use a 5 s guard of this test's own (no PRD target).
