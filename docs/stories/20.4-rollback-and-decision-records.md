# Story 20.4: Rollback rehearsal and decision records

As the owner, I want the way back to Tauri rehearsed, and the cutover and retirement decisions written as separate records, so that I decide with evidence and can undo it.

**Assumptions**
- Rollback = keep distributing the Tauri installers (MFR-8). No Tauri file is changed, so rollback needs no repository action.
- Cutover means: the Electron installers become the ones offered to users. Retirement means: later, separately, stop maintaining the Tauri app. Neither is done by any story.
- The reviewer's verdict (PASS, CONCERNS, FAIL) and the owner's decision (approve, reject, defer) are separate fields in separate records.

**Acceptance Criteria**

**Given** a machine with the Electron preview in use
**When** the rollback is rehearsed
**Then** the steps (stop the preview, install the Tauri build from the baseline SHA, sign in, confirm data and Drafts intact, optionally remove the preview and its profile and credential entry) are performed on each OS and timed; evidence in `evidence/rollback.md`.

**Given** the evidence from 20.1, 20.2 and 20.3
**When** the reviewer writes `docs/planning-artifacts/electron-migration/decisions/cutover-readiness.md`
**Then** it gives a verdict per OS with evidence links, the open FAIL or CONCERNS list, and the gate checklist from MFR-8: all stories done, parity matrix green on every OS, NFR-2 measured, rollback rehearsed.

**Given** the owner's decision
**When** recorded in `decisions/cutover-decision.md`
**Then** it has the fields: decision, date, who decided, conditions, rollback triggers (for example, any report of lost or duplicated data, sign-in failure, start-up failure, or sustained NFR-2 breach), and the owner's signature line left for the owner; the document is created blank-ready and is **not** filled by an agent.

**Given** retirement
**When** considered
**Then** `decisions/retirement-decision.md` exists as a separate blank-ready record with the precondition "cutover decided and stable for a period the owner sets", and a statement that retirement never deletes or edits the Tauri app in this migration; deletion would need its own approved change.

**Given** the protected-path gate
**When** run at the end
**Then** it still passes with the baseline SHA.

**Tasks**
- `docs/planning-artifacts/electron-migration/evidence/rollback.md`.
- `docs/planning-artifacts/electron-migration/decisions/{cutover-readiness,cutover-decision,retirement-decision}.md`.
- Final run of the 14.1 gate; link its output.

**Dev notes**
- Authority: PRD MFR-8; spine AD-31. Owner is the user; reviewer is the BMAD reviewer role.
- OS-level cleanup of the preview (profile directory, credential entry) is documented in `electron/INSTALL-PREVIEW.md` (20.3).

A published app id is not changed afterwards.
