# Story 1.5: API security foundation

As a developer,
I want JWT verification, permission checks on every endpoint, the shared API conventions and a committed OpenAPI contract,
So that every later endpoint is authorized, shaped and typed the same way from its first line.

**Assumptions**
- Access token claims: `sub`, `perms[]`, `sid`, `epoch`, `kid`, `iat`; EdDSA; 15 minutes (architecture §6.1).
- Revocation and rate-limit state are in memory (A1).
- `GET /me` is the first protected endpoint, used to prove the stack.

**Acceptance Criteria**

**Given** a valid access token
**When** `GET /api/v1/me` is called
**Then** it returns `{id, name, email, role, permissions[]}` and the name and email are decrypted server-side.

**Given** a token that is missing, expired, signed by an unknown `kid`, has `iat` before server start, a revoked `sid`, or an `epoch` that differs from `permission_epoch`
**When** any endpoint is called
**Then** the response is 401 `unauthenticated` or `token_stale` (stale cases) as problem+json (AD-8).

**Given** an endpoint annotated `@PreAuthorize("hasAuthority('PERM_…')")` and a token without it
**When** called
**Then** 403 `forbidden`, and for a privileged endpoint an Audit Entry `forbidden` is written in its own transaction (AD-21).

**Given** ArchUnit
**When** a controller method has none of `@PreAuthorize`, `@PermitAll`, `@TokenAuthorized`
**Then** the build fails; no check uses a role name (AD-9).

**Given** an entity with `version`
**When** `PATCH` arrives without `If-Match`, or with a stale version
**Then** 400 `bad_request` or 409 `conflict` respectively, and success returns the new version (AD-18).

**Given** a create-style `POST` with `Idempotency-Key`
**When** repeated
**Then** the second call returns the first result and creates nothing (`idem_bidx`); a test endpoint in test sources proves it.

**Given** `ClientIp`
**When** `X-Forwarded-For` has more hops than `KLEI_TRUSTED_PROXY_HOPS`
**Then** only the trusted hop is used.

**Given** the build
**When** it runs
**Then** `docs/api/openapi.json` is regenerated by springdoc and the build fails if it differs from the committed file; `extensions` per `code` are in the spec.

**Given** the leak suite
**When** extended
**Then** it sends malformed JSON, a wrong token and an oversized body, and asserts error bodies and logs echo no input.

**Tasks**
- `TokenSigner` use, `JwtAuthFilter`, `SessionRegistry` (in memory), `PermissionEpoch` service, `MethodSecurity` config, `ProblemAdvice` codes table, `ClientIp`, `IdempotencyService`, `VersionedEntity` helper.
- `GET /me`; OpenAPI drift test; `docs/api/openapi.json` committed.
- Extend `SentinelCatalog` and the leak suite for error paths.

**Checks**
- `cd backend && ./mvnw verify`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (unauthenticated `GET /api/v1/me` returns 401 problem+json).
- Desktop tests: not applicable yet.
- NFR-1: leak suite error-path additions.

## Dev record

**Result.** `cd backend && ./mvnw clean verify` green, 111 tests (new: `TokenSignerTest` 7, `ClientIpTest` 4, `SecurityIT` 13, `OpenApiIT` 2, ArchUnit 7 incl. the role-name rule). Stack rebuilt with `--build`, `infra/ci/smoke.sh` PASS, now also asserting `GET /api/v1/me` without or with a bad token is a 401 problem+json.

**Deviations**
- Error-path leak assertions live in `SecurityIT`, not `LeakSuiteIT`; no new Sentinel column exists yet, so `SentinelCatalog` is unchanged.
- `IdempotencyService` returns the `BidxDomain.IDEM` blind index of the key. No table has an `idem_bidx` column yet (message and photo arrive later), so the test endpoint stores results in memory. Real owners add the column and look it up.
- `VersionedEntity` helper is `Versions.require(req, current)` plus `ProblemException`; stale `@Version` races map to 409 in `ProblemAdvice`.
- New `BodyLimitFilter`: non-multipart bodies over `klei.max-body-bytes` (default 1 MiB) get 413 `too_large`. The leak test found a 30 MB JSON body accepted before.
- `server.forward-headers-strategy` is now `none`; `ClientIp` reads `X-Forwarded-For` itself. `KLEI_TRUSTED_PROXY_HOPS` added to compose.
- Deny by default: unknown API path without a token is 401, with a token 404 (`BackendIT` changed).
- Key `KLEI_JWT_KEY` may be a 32-byte seed or 48-byte PKCS8 (what `gen-keys.sh` emits); `KeyRing` rejects other lengths.
- springdoc is off outside tests (`springdoc.api-docs.enabled=false`); probe and boom paths are not in the spec.
- `PermissionEpoch.bump()` exists but nothing calls it until Role editing (Story 2.x).

**Risk.** Revoked sessions and `startedAt` live in memory: a restart signs everyone out (accepted, A1). `extensions` schemas are empty objects until an endpoint raises a code with fields. `SecurityProbeController` is test-only; confirm no production endpoint ever lands under `/api/v1/probe`.
