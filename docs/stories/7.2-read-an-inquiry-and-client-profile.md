# Story 7.2: Read an Inquiry and Client profile

As a Staff member,
I want to open an inquiry, read the whole conversation and see who the client is,
So that I answer with the full picture.

**Assumptions**
- Opening marks the Inquiry read for the whole Workspace (A3). `GET /inquiries/{id}` does not mutate. The shell calls `POST /inquiries/{id}/read` after the thread has been visible for 1 second `[ASSUMPTION]`.
- Message bodies are plain text from the Client (stored as text) and sanitized HTML for our Replies (Story 7.3). The thread renders Client text as text, never as HTML.
- Attachments appear as chips (name, size). Download is out of scope for the MVP; chips show the file name only `[ASSUMPTION]`. OPEN QUESTION (non-blocking): should staff be able to download Client attachments? Intake is deferred, so Client attachments do not exist yet.
- Client editing is Story 7.4; this story shows the profile read-only.

**Acceptance Criteria**

**Given** `GET /inquiries/{id}` with `PERM_REPLY`
**When** called
**Then** it returns subject, status, client summary (id, name, email), Messages in time order (id, direction, author name or "Client", time, body, mail state, attachments) and `version`; an unknown id returns 404.

**Given** `POST /inquiries/{id}/read`
**When** the Inquiry is unread
**Then** `unread` becomes false (`unread_bidx` follows), `seq` does not change, and a repeat is a no-op returning 204.

**Given** I1 with an Inquiry selected
**When** the thread renders
**Then** it shows the thread header (subject, client name as an underlined link to I2, status select, **Close inquiry** button; both are inert until Story 7.4), messages with avatar initial, name, time, body, attachment chips; our replies show the sender name; the list row loses its unread dot.

**Given** a Closed Inquiry
**When** it is opened
**Then** the composer area shows "This inquiry is closed. Reopen it to reply." with **Reopen** inert until 7.4.

**Given** `GET /clients/{id}`
**When** called with `PERM_REPLY`
**Then** it returns name, email, phone, city, wedding date, source, note, created date, `version`, and that Client's Inquiries (id, subject, date, status).

**Given** I2
**When** it renders
**Then** it shows the breadcrumb "Inquiries / {name}", header with avatar, name, email, a two-column facts list (phone, city, wedding date, source, client since, note; a grey dash when empty), the table of this client's inquiries opening I1 on click, and "No other inquiries from {first name}" when there is none; Loading and Error states exist.

**Given** the leak suite
**When** extended
**Then** nothing new is stored; reading a thread leaves no plaintext on disk (Rust test from 4.2).

## Dev record

**Assumptions**
- Migration V18 adds five nullable encrypted Client columns (`phone`, `city`, `wedding_date`, `source`, `note`); 7.4 writes them. `SentinelCatalog` lists them with no writer yet.
- `GET /api/v1/inquiries/{id}` never mutates. `POST /api/v1/inquiries/{id}/read` (204, repeat 204) clears the one workspace-wide unread flag. `unread_ct`/`unread_bidx` are outside optimistic locking, so reading changes neither `version` nor `seq` and cannot stale a concurrent status change.
- The desktop marks read after the thread has been open for 1 s (`READ_AFTER_MS`), once, then asks the sidebar badge to re-read through a window event.
- Message bodies are rendered as text (`white-space: pre-wrap`), never HTML. Author name is looked up from the User; a deleted User shows as the Client or blank (Message keeps `author_user_id` null).
- Client profile shows the newest 200 Inquiries. "No other inquiries from {first}" shows when the list holds one row or none. Empty facts show a grey dash with sr-only "Not set".
- Routes: `#/inquiries/{id}`, `#/inquiries/client/{id}`. Both need `PERM_REPLY`; Viewer gets 403.
- Attachments and mail state are absent from the response; their columns arrive in 7.3.
