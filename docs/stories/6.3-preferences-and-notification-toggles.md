# Story 6.3: Preferences and notification toggles

As a Staff member,
I want to choose my date format, timezone, start page and which in-app notifications I get,
So that the app behaves the way I work.

**Assumptions**
- Email toggles and the digest are deferred (Gate 3). Only in-app toggles exist.
- `app_user.prefs_ct` holds all preferences as one `FieldCodec` JSON with `v`.
- Language is shown disabled as "English (US)" with the helper "More languages are not available yet."
- Start page options: Dashboard and Gallery (need `PERM_VIEW_GALLERY`), AI Upload (`PERM_UPLOAD_IMAGES`), Inquiries (`PERM_REPLY`); an option the User cannot use is hidden. Default Dashboard (FR-4).
- Timezone list is the platform list of IANA names from the webview (`Intl.supportedValuesOf('timeZone')`), default the system zone.
- Date format options: `MM/DD/YYYY`, `DD/MM/YYYY`, `YYYY-MM-DD`.
- Toggles: New inquiry (hidden for a User without `PERM_REPLY`), AI finished, Team activity. All default on.
- "Press Enter to send" default off; it is read by the composer (Story 7.3) and the Assistant (Story 8.3).

**Acceptance Criteria**

**Given** `GET/PUT /me/preferences` with `If-Match`
**When** called
**Then** values are validated against fixed sets (the timezone against a server-side IANA list), stored in one encrypted blob, and the response carries the new version; an unknown start page returns 422.

**Given** S3 and S4
**When** a control changes
**Then** it autosaves, the toast "Preference saved" shows, and on failure the control reverts with "Couldn't save. Try again."; Loading and Error states exist.

**Given** the shell loads after sign-in
**When** `/me` and preferences are read
**Then** the shell opens the chosen start page (once per sign-in), formats dates and times in the chosen format and timezone everywhere (a single `formatDate` helper), and replaces the Audit log's browser timezone use from Story 2.5.

**Given** a notification type toggled off
**When** `NotificationPort` is called (Story 8.1)
**Then** the type respects the setting; a test is added in 8.1; this story ships a `NotificationPreferences` reader with its own unit test.

**Given** the Sidebar
**When** the start page is Inquiries and the User loses `PERM_REPLY`
**Then** the start page falls back to Dashboard, or to the first sidebar item the User can open when Dashboard is also unavailable.

**Given** the leak suite
**When** extended
**Then** preferences are only an envelope in `prefs_ct`.

**Tasks**
- Backend: `PreferencesService`, controller, IANA validation, tests.
- Desktop: Preferences and Notifications tabs, `formatDate` helper, start-page redirect, tests, axe.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && (cd src-tauri && cargo test)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: put and read preferences).

## Dev record

**Assumptions**
- Migration is V16 (`app_user.prefs_ct`), not the older number the story text names.
- All preferences are one encrypted JSON blob (`Prefs`, with `v` and a `rev` counter inside), kept outside `@Version` so a rename (bumps `AppUser.version`) and a prefs save never 409 each other.
- API version = `rev`; 0 = never saved (defaults). `If-Match` required (400 missing, 409 stale); bad zone/format/page 422 `invalid`, missing field 422 `required`.
- `GET /api/v1/me` also returns `preferences`, so the desktop applies them with no extra read.
- Null timezone = this computer on the client and UTC on the server.
- Start page options are hidden by Permission; a held-nothing page falls back to Dashboard. Redirect after sign-in runs once per Shell mount and only when the hash is empty.
- Email toggles and digest stay deferred (Gate 3). Preferences are personal: no audit action. Language fixed to English (US), disabled.

**Done**
