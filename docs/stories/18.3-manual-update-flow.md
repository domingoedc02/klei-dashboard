# Story 18.3: Fixed-page manual update

As a Staff member, I want the app to check whether a newer version exists and open the download site page (18.5), so that I can download and install updates myself without the app executing an installer.

**Assumptions**
- Electron manual-update flow is the expressly approved Electron-only exception to FR-43/AD-15. It does not download packages, verify signatures, install packages or restart.
- Manifest URL and release-page URL are derived from one build-time constant `KLEI_DOWNLOAD_BASE_URL`: the download site's base URL including its secret path token (story 18.5). Manifest is `<base>/latest.json`, page is `<base>/`. The build fails when it is missing, not HTTPS (development may use `http://127.0.0.1:8090/<token>`) or its token is shorter than 43 characters. It is never committed; release builds read it from a secret (19.4). The renderer can neither read nor supply it, and logs and errors never print it.
- `install_update` is a compatibility name only; `update_unverified` is unused by Electron.

**Acceptance Criteria**

**Given** `check_update`
**When** called at startup, on the existing schedule or manually
**Then** it requests one fixed HTTPS manifest URL with a 30-second timeout, no redirects, a strict response-size cap and strict semver validation; it sends only app version, OS and architecture, and returns `{status:'none'}` or `{status:'available',version}`. Invalid manifests fail safely without exposing their URL or stopping the app.

**Given** the version-only manifest is unchanged or contains no newer version
**When** check completes
**Then** it returns `{status:'none'}`; when a newer valid semver is present it returns `{status:'available',version}` without exposing the manifest URL to renderer.

**Given** `KLEI_DOWNLOAD_BASE_URL` is missing, not HTTPS or has a short token
**When** the build runs
**Then** it fails with a message that does not print the value.

**Given** `install_update` is invoked while dirty
**When** main checks dirty state
**Then** it refuses with kind `update_refused` and exact message `You have unsent work. Finish or discard it first.`; it never opens the browser.

**Given** `install_update` is invoked while clean
**When** main handles it
**Then** it calls `shell.openExternal` only with the release-page URL derived from the fixed build-time base URL and resolves after opening; it accepts no renderer-supplied URL, and performs no download, verification, installation or restart.

**Given** the original update banner and Settings action render
**When** an update is available or user asks to check
**Then** Electron-owned alias/override copy truthfully says **Download update**, opens the fixed release page, and preserves non-blocking check failures, Later, dirty guard and focus/accessibility behavior. If `install_update` resolves, its pending/installing state resets and button remains usable.

**Tasks**
- `electron/src/main/update.ts`: fixed manifest/release constants, bounded HTTPS fetch, redirects disabled, timeout, strict semver comparison and dirty guard.
- `electron/src/main/commands.ts`: implement existing `check_update`/`install_update` command names; accept no URL parameter and open only fixed release constant.
- `electron/src/renderer-compat/Update.tsx`: Electron-owned alias/override for banner and Settings wording, retaining the original renderer files unchanged.
- `electron/scripts/gen-config.mjs` (from 16.1): generate the base-URL constant and apply the build check above.
- `electron/test/update.test.ts`: test manifest limits, redirect rejection, URL/semver validation, request privacy, available/none/failure cases, dirty refusal, fixed external URL and hostile-renderer URL injection rejection.
- `electron/test/renderer-update.test.tsx`: test resolving `install_update` clears installing state; check accessible truthful label and dirty/error flows.

**Dev notes**
- Port Rust `desktop/src-tauri/src/commands.rs::{check_update,install_update}` and `desktop/src-tauri/src/update.rs::{check,gate,DIRTY}` only as a behavioral reference; deliberately do not port `download`, `Ready::install`, package/signature verification, `UNVERIFIED` handling or restart.
- Behavior spec for legacy flow and dirty guard: `desktop/src-tauri/src/update_tests.rs::{a_newer_version_is_announced_and_the_request_carries_only_version_and_platform,an_unreachable_host_fails_without_naming_the_address,unsent_work_stops_the_install_before_any_request}`; UI resolving-command behavior test belongs in Electron because original `desktop/src/shell/Update.test.tsx` currently models a never-resolving install success.
- Renderer compatibility targets: `desktop/src/shell/useUpdate.tsx`, `desktop/src/shell/Shell.tsx`, `desktop/src/shell/Update.test.tsx`; all are read-only.

**Testing**
- Run Electron update unit/UI tests; assert `shell.openExternal` receives only the fixed configured URL and hostile IPC payloads cannot alter host/path.
- Test timeout, over-limit body, redirect, malformed semver, network failure and dirty state. Verify `update_unverified` is not emitted or displayed in Electron.
- End-to-end packaged test confirms button label is **Download update**, browser opens once, app remains running and state resets after command resolution.

**Prototype unchanged check**
- Require baseline protected-path diff empty and no unexpected untracked files.
- Compare Settings/banner placement, focus, toasts and accessibility against baseline at 1440×900, 1280×800 and 1100×700; only the explicitly approved Electron update wording/action differs; no original renderer or historical parity artifacts change.
