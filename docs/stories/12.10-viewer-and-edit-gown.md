# Story 12.10: Viewer header, keyboard safety and Edit gown title

As a Staff member,
I want the gown title and actions above the viewer, and the photo to stay put while I type in the Edit dialog,
So that long names do not squash the details panel and arrow keys never change the photo behind a dialog.

**Assumptions**
- Audit rows G-07 (arrow keys change the photo behind the open Edit dialog) and G-08 (title and four actions live inside the 360px aside).
- Prototype: `js/gallery.js:48-56` crumbs, then a page head (h1, **New** pill, **Edit**, **Download .zip**, **Copy description**) above `.viewer`; Details is a `card` with `kv` rows. `css/screens.css:95` `.viewer { grid-template-columns: minmax(0, 1fr) 360px }`, `:96-97` `.stage` 560 / 520, `:98-100` overlay chevron nav buttons, `:101-103` `.vthumbs`. `js/gallery.js:100` dialog title is Edit “name”.
- App today (`desktop/src/gallery/Viewer.tsx`): `:50` the keydown handler ignores only `INPUT`, `SELECT`, `TEXTAREA`, so ArrowLeft/Right still move the photo while the `role="dialog"` Edit dialog (mounted by `Shell.tsx:76`) is open and focus is on a button or chip; `:69` title is `'Edit gown'`; `:150-151` the h1 sits inside `<aside className="details">`. `styles.css`: `:294` `.viewer-body`, `:493` stage height 560 (overflows a 700px window once the head and crumbs are added).
- **Kept:** the Edit gown dialog keeps its select + chips tag UI and its unsaved-changes guard. ux-spec asks for five comboboxes; select + chips scales better. Accepted deviation, unchanged by this story. Only the title changes, to Edit “{gown name}” (curly quotes, name truncated with ellipsis past 40 characters).
- Stage height must fit 700px: stage `min(560px, calc(100vh - 340px))` at the 700 window is about 360px minimum; the story picks `clamp(360px, 62vh, 560px)` and the screenshot check confirms no vertical page overflow beyond the sheet scroll.
- 11.7 stays `done`; this story corrects it.

**Acceptance Criteria**

**Given** the Edit gown dialog is open
**When** focus is on a button or chip and ArrowLeft or ArrowRight is pressed
**Then** the viewer's selected photo does not change.
**Given** no dialog, menu or input has focus
**Then** ArrowLeft and ArrowRight still move to the previous and next photo.
Test: `Viewer.test.tsx` `it('ignores arrow keys while a dialog is open')` and the existing arrow-key test at `:56` still passes.

**Given** a gown with a 60-character name
**Then** the h1 and the actions render in a page head above `.viewer-body`, under the crumbs, not inside the aside; the **New** pill shows when the gown is new; the name does not shrink the Details panel (width stays 360px).
Test: `Viewer.test.tsx` `it('renders the title and actions above the viewer body')` asserts `h1` is not inside `.details` and the New pill is present for a new gown; update `:79`, `:152`.

**Given** Edit is chosen
**Then** the dialog is named Edit “{name}” (accessible name) and a name over 40 characters is cut with an ellipsis; the select + chips controls and the unsaved-changes guard are unchanged.
Test: update `Viewer.test.tsx:202` from `'Edit gown'` to `getByRole('dialog', { name: 'Edit “Aurelia”' })`; `it('truncates a long gown name in the Edit title')`.

**Given** the stage at 1100x700
**Then** the stage plus thumbnails fit without pushing the Details panel below the fold (stage height is the clamp above).
Test: `styles.test.ts` `it('viewer stage height is clamped')` asserts the `clamp(` rule.

**Given** `node infra/ci/shots.mjs --only viewer` (the 12.1 screenshot command)
**When** run at 1100x700 and 1280x800
**Then** `report.json` shows no failure for `viewer`; the PNGs show the page head above the viewer, Details beside it, thumbnails visible, and match the prototype `gallery/viewer` screen. The Edit dialog itself is covered by the vitest assertions above (12.1 has no `viewer-edit` key).
