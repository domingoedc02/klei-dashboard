# Story 4.4: Tagging and descriptions

As a Staff member,
I want each group to arrive with a suggested name, tags and description,
So that I only review and correct instead of typing.

**Assumptions**
- Adds `describe(images, taxonomy, tone)` to `AiProviderPort`. One call per Group: up to 4 thumbnails, the allowed Taxonomy values and the tone. Returns attributes and a description.
- If "Use advanced AI model" is on and a second vision model is set, that model is used; otherwise the vision model.
- Only values from the Taxonomy are accepted. The model may answer with anything; the server maps it to a known Taxonomy value (case-insensitive exact match) and drops the rest. Names the model suggests are trimmed to 80 characters.
- Confidence for the group blends clustering similarity (Story 4.3) and the share of attributes that mapped; the formula is a small pure function with tests `[ASSUMPTION]`.
- No client data is sent: Photos of one Group, Taxonomy values, tone (architecture §8.1).
- Disclosure of what leaves the system (PRD §7) is already in the AI settings screen; the Upload screen adds one line under the processing steps: "Photo thumbnails are sent to your AI provider." `[ASSUMPTION]`

**Acceptance Criteria**

**Given** phase `processing` after grouping
**When** steps 3 and 4 run
**Then** for each Group one `describe` call returns attributes by type (multiple values allowed), a name suggestion and a Description; steps update progress `{step:3|4, done, total}`; at most 3 groups run at once.

**Given** a provider answer with an unknown tag
**When** mapped
**Then** the unknown value is dropped, the known ones kept, and the confidence is lowered; a unit test covers an answer with only unknown tags (the Group keeps empty attributes and Low confidence).

**Given** a tone setting of Warm, Editorial or Factual
**When** the prompt is built
**Then** the tone appears in the system text; a unit test asserts the prompt holds the taxonomy list and no filenames or ids other than opaque photo numbers.

**Given** one Group's call fails or times out
**When** the retry also fails
**Then** the batch stops at that step with the error block and Retry; Groups already described keep their results and are not called again.

**Given** the job finishes
**When** phase becomes `review`
**Then** every `upload_group` has name, attributes, description and confidence, all encrypted; the notification text from 4.3 is created once.

**Given** `ai_usage`
**When** each describe call ends
**Then** a row (purpose `describe`) is written with the model, size and outcome; prompt and response are stored encrypted; no photo bytes are stored in the row.

**Given** the leak suite
**When** extended
**Then** a stub that returns Sentinel text in the description and name leaves no plaintext in tables, logs or S3.

**Tasks**
- `DescribeService`, `PromptBuilder`, `TaxonomyMapper`, `ConfidenceScorer`, stub mappings for describe, startup recovery unchanged.
- Desktop: processing line for steps 3 and 4, disclosure line, tests.

## Dev record

**Assumptions**
- `describe` returns the provider's own words (`Described`); the Taxonomy decision stays in app code (`TaxonomyMapper`), so the port carries no Taxonomy rules.
- Model is `visionModelAdv` when "Use advanced AI model" is on and one is set, else `visionModel`. No vision model set means `not_configured` at step 3.
- Group confidence is `0.7 x cluster similarity + 0.3 x share of named values the Taxonomy accepted`; an answer that names nothing accepted can no longer stay High.
- Status shape is unchanged (`step` 3 and 4 already fit), so `openapi.json` and `schema.d.ts` did not change.

**Done**
- Core: `AiProviderPort.describe` with `DescribeImage` and `Described`. App: `OpenAiCompatibleAdapter.describe` on `/chat/completions` (same `/v1` rule as embeddings), usage row per call with purpose `describe`; `AiConfig` now carries vision models, advanced, temperature, max tokens.
- `PromptBuilder` (tone, allowed values, only "Photo n of m"), `TaxonomyMapper`, `ConfidenceScorer`.
- `GroupingService`: step 2 writes groups only; step 3 describes up to 3 groups at a time, up to 4 thumbnails each, one retry except `not_configured`, `refused`, `unauthorized`; a failed group stops the batch with an error block and keeps finished groups; step 4 moves the Batch to `review` and raises the Notification once, after the last group. Retry skips groups that already have a description.
- Desktop: disclosure line "Photo thumbnails are sent to your AI provider.", Tagging step and bar, causes for `bad_response`, `http_error`, `too_large`.
- Infra: wiremock `chat.json`; smoke asserts three describe usage rows, no description in the usage list, no gown name or description in `pg_dump`.

**Checks run**
- `cd backend && ./mvnw -q verify -pl app -am`: 147 integration, 54 unit, 0 failures (new: `DescribeRulesTest` 6, `GroupingIT` +2, leak suite extended with a gown name and description Sentinel).
- `cd desktop && npm test`: 103 passed. `npx tsc --noEmit`, `npm run types:check`: clean. `cargo test`: 34 + 3 passed.
- Compose smoke on the throwaway `kleismoke` project: SMOKE PASS; project removed with `down -v`.

**Not verified**
- Real provider vision model with data-URI images and JSON-only answers (S-1); the parser tolerates code fences and chatter but a model that refuses JSON ends as `bad_response`.
- Description quality per tone on real gowns.

**Shortcuts**
- Provider text beyond 2000 characters of description is cut, not rejected.
- Photos for a group are the first four by upload time, not the four most distinct.
- Concurrency of 3 is a fixed pool shared by all batches; no setting.
- A failed group stops the whole batch (per story); no partial review.
