# Story 1.1: Compose infrastructure stack

As an operator,
I want one `docker compose up` that starts PostgreSQL, the object store and Mailpit with secrets taken from a git-ignored `.env`,
So that every later story has a real, repeatable stack to run against.

**Assumptions**
- The `backend` service is added by Story 1.2 (first story with something to build). This story ships the compose file with the three infrastructure services and a `backend` stub comment.
- Repo root has no git history yet; this story creates `.gitignore` and the folder layout from architecture §3.

**Acceptance Criteria**

**Given** a clean checkout with no `.env`
**When** `docker compose -f infra/docker-compose.yml up` runs
**Then** it fails at once with a message naming the missing variable (compose `${VAR:?…}`), and no container starts with a default secret.

**Given** `infra/.env` created from `infra/.env.example` with keys from `infra/ci/gen-keys.sh`
**When** `docker compose -f infra/docker-compose.yml --profile dev up -d --wait` runs
**Then** `postgres` (`postgres:18.6`), `objectstore` (`chrislusf/seaweedfs:4.52`, command `server -dir=/data -s3 -volume.max=0`) and `mailpit` (`axllent/mailpit:v1.33.0`) report healthy.

**Given** the stack is up
**When** the object-store credentials from `.env` are used with a SigV4 client
**Then** create-bucket, put, head, get, list and delete succeed on `objectstore:8333`, and the same calls with wrong credentials are denied.

**Given** the compose file
**When** its networks are inspected
**Then** `postgres` and `objectstore` sit only on `internal` (`internal: true`), no port of them is published except loopback in the `dev` profile, and Mailpit exists only in the `dev` profile.

**Given** volumes `pgdata` and `objdata`
**When** the stack is stopped and started again
**Then** data written before stop is still there.

**Given** the repository
**When** `.gitignore` is read
**Then** it ignores `infra/.env`, `*.pem`, `*.key`, build outputs of Maven, Node and Cargo, and `infra/.env.example` is committed with placeholders only.

**Given** `infra/ci/gen-keys.sh`
**When** it runs
**Then** it prints a full set of `KLEI_KEK_1`, `KLEI_KEK_ACTIVE=1`, `KLEI_BIDX_KEY`, `KLEI_JWT_KEY`, DB password and S3 keys, each from `openssl rand`, pairwise distinct, and writes nothing to disk.

**Given** `infra/ci/smoke.sh`
**When** it runs against the stack
**Then** it checks the three services, the S3 round trip above and exits non-zero on any failure.

**Tasks**
- Create `.gitignore`, `README.md` (run instructions only), folders `backend/ desktop/ infra/ docs/`.
- Write `infra/docker-compose.yml` (and `docker-compose.dev.yml` for dev ports and the Mailpit profile) with healthchecks: `pg_isready`; SeaweedFS `GET :9333/cluster/status`; Mailpit `/readyz`.
- Set `-volume.max=0` and `-volume.minFreeSpace`; S3 credentials from `KLEI_S3_ACCESS_KEY` and `KLEI_S3_SECRET_KEY` via `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`.
- Write `infra/.env.example` (all variables in architecture §9.2, no values), `infra/ci/gen-keys.sh`, `infra/ci/smoke.sh` (curl `--aws-sigv4`).
- Record the production digest-pin step in `infra/README` (release checklist), not implemented here.

**Checks**
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh`
- `mvn verify`: not applicable yet. Desktop tests: not applicable yet.
- NFR-1: no data stored yet; the smoke test asserts no secret has a default.

**Dev and QA record (2026-11-08)**
