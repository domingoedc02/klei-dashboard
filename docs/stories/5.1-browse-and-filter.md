# Story 5.1: Browse and filter the Gallery

As any signed-in User,
I want to browse gowns newest first and narrow them by silhouette, fabric and date,
So that I can find a gown quickly.

**Assumptions**
- Page size 48, "Show more gowns" button, no infinite scroll (UX G1). Cursor `before=<seq>`.
- Filters are Taxonomy ids and a day window. Date window values: All time, Last 7, 30, 90 days. `DayBucket.lastN(n)` in UTC (A2).
- Cards show the first four Photos (position order) as a mosaic of thumbnails.
- `total` and "N of M" use two counts with the same predicates (architecture §4.4).
- Gallery read needs `PERM_VIEW_GALLERY` (on for all default Roles); a Viewer sees no select-to-delete (Story 5.5).
- Performance: the 5,000-Gown benchmark (AR-22) is Story 9.4; this story only keeps queries on indexed columns and a test asserts the query plan uses indexes on a 500-row seeded set.

**Acceptance Criteria**

**Given** `POST /gowns/query {silhouette[], fabric[], days, before, limit}`
**When** called with `PERM_VIEW_GALLERY` (403 `forbidden` without it)
**Then** it returns `{items, next, total, matching}` newest first by `seq`, limit at most 100 (UI 48), each item holding id, name, Silhouette and Fabric labels, Photo count, up to four thumb Photo ids, date added and `isNew`; combined filters AND together; `days` outside {0,7,30,90} returns 422.

**Given** filter values
**When** the query runs
**Then** it uses `EXISTS` on `gown_attribute.taxonomy_value_id` per chosen group and `day_bidx IN DayBucket.lastN(n)`; no plaintext timestamp or text is used in SQL (NFR-1); an `EXPLAIN` test on 500 rows shows index use.

**Given** G1
**When** it renders
**Then** it shows title "Gallery", Silhouette and Fabric selects (multi-select from the Taxonomy), Date added select, **Clear filters** when any is active, "{N} of {M} gowns, latest upload first" at the right, the card grid and **Show more gowns** when `next` exists.

**Given** a card
**When** it renders
**Then** it shows the 2x2 mosaic with 2px gaps (missing slots grey), name, "Silhouette, Fabric", Photo count, date added in the User's format, and the "New" pill only on the one New gown; thumbnails load through `klei-img://`.

**Given** states
**When** loading, error, empty and no-match occur
**Then** loading shows 8 skeleton cards, error replaces the grid with an error block and keeps the filters, empty shows "Your gallery is empty" with the empty-state art and **Upload photos** (a sentence only for Viewer), no-match shows "No gowns match these filters" with **Clear filters**.

**Given** the User opens a card and returns
**When** the breadcrumb is used
**Then** filters and loaded pages are restored from memory in the shell's route state.

**Given** the leak suite
**When** extended
**Then** nothing new is stored; the suite also asserts the query endpoint has no business text in its URL.

**Tasks**
- Backend: `GownQueryController`, `GownQueryService`, `GownCardView` (`@Immutable` view entity per AD-19), counts, tests.
- Desktop: Gallery screen, filter bar, card, mosaic component (also used by the Dashboard and search), pager, route-state store, tests, axe.

## Dev record

**Assumptions**
- Reads need `PERM_VIEW_GALLERY` only. Filters are one id per type from the screen (the endpoint accepts up to 50 ids per type: OR inside a type, AND across types and the date window). `[ASSUMPTION]`
- An id that is not a value of that type (a Fabric id sent as Silhouette, an unknown id) matches nothing, never everything.
- `days` outside {0,7,30,90}, `limit` outside 1..100, `before` below 1, or more than 50 ids is 422 naming the field; a malformed id is 400.
- The gown-scoped photo read (`GET /api/v1/gowns/{id}/photos/{pid}?size=thumb|full`, 404 when the Photo is not on that Gown) ships here because the cards need it; Story 5.2 reuses it. `klei-img://localhost/g/{gown}/{photo}[/full]` is its Tauri path.
- Card order of thumbnails is Photo `created_at` then id (the Photo upload order).
- Coming back from a Gown restores filters and loaded pages from a module-level store keyed by User id; Save clears it. Edit and delete (5.3, 5.5) must call `forgetGallery()` too.

**Done**
- Backend: `GownQueryService` (`query`, `image`, `filter` validation), `GownQueryController` (`POST /api/v1/gowns/query`, `GET /api/v1/gowns/{id}/photos/{pid}`), response types `GownCard`, `GownPage`. SQL sees only ids, `seq` and the creation-day HMAC; names and labels are decrypted after the page rows are chosen. `total` and `matching` are two counts with the same predicates.
- Desktop: `gallery/Gallery.tsx` (selects from the taxonomy, Clear filters, "N of M gowns", 8 skeletons, error block with Retry, "Your gallery is empty" with Upload photos for those allowed to upload, "No gowns match these filters", mosaic cards, Show more gowns), `gallery/memory.ts`, `platform.ts` `gownThumbUrl`/`gownFullUrl`, Rust `thumbs.rs` `g/` prefix with tests, Shell route.
- Smoke: Gallery steps after Save: anonymous 401, list returns the 3 Gowns with cards, 7-day window matches 3, unknown tag matches 0, `days=5` is 422, one thumbnail 200 with JPEG type and `no-store`.
