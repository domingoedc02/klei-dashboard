# Story 21.5: Re-baseline the protected-path gate

As the project owner,
I want the migration baseline moved to the commit that carries the Epic 21 fixes,
So that `electron-protect` passes again and still catches any later change to the Tauri app.

**Assumptions**
- The gate (`electron/scripts/protected-paths.mjs`, workflow `.github/workflows/electron-protect.yml`, story 14.1) fails on any diff under `desktop`, `backend`, `infra`, `prototype`, `docs/api`, `docs/install-guide.md`, `docs/release-checklist.md`, `.github/workflows` against baseline `51949da2a0f8347c5f1f56fc5d87d8ada6e60643` ("13.8: Upload Review: select, Move, Merge, Split").
- Stories 21.1 to 21.4 change `desktop/src` and `desktop/scripts`, which are under `desktop`. **Until this story lands, each of those PRs fails `electron-protect`.** Merge order: 21.1 to 21.4, then 21.5 on the same branch or the last PR; do not merge 21.1 to 21.4 to `main` on a red gate.
- `desktop/src` is also the Electron renderer source (alias in `electron/vite.config.mjs`), so these fixes ship in both apps. The original Tauri app's behaviour changes only through these UI fixes; no `backend/`, `desktop/src-tauri/` or contract change from 21.1 to 21.5, except Story 21.6 (no-limit upload), which changes `backend/app` (clusterer, batch ceiling, one `limit` field in `docs/api/openapi.json`) and `desktop/src-tauri/src/uploads*.rs`; 21.6 lands first and the new baseline commit holds it.
- Decision: the project owner approves moving the baseline. This is a decision record, not a silent edit: the old baseline stays in the history of `BASELINE.md`.
- New baseline = the commit that holds the last change to a protected path (Stories 21.1 to 21.4 and 21.6, committed together on 2026-11-14), not the 21.5 commit itself (the gate must pass on the commit that contains the new constant). Dev records the 40-character SHA.
- Open question for the owner: do rollback evidence (`docs/planning-artifacts/electron-migration/evidence/rollback.md`, `parity-matrix.md`) and the 20.4 rehearsal keep pointing at the old Tauri baseline build (a rollback to the pre-fix UI) or the new one? Default here: **the new baseline**, since the Tauri app now carries the fixes; the old SHA stays recorded as "previous baseline".

**Then** it prints `protected paths unchanged` and exits 0
