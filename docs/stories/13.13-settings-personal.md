# Story 13.13: Settings: frame and personal tabs

As a Staff member,
I want Settings, Profile, Signature, Preferences and Notifications to match the prototype,
So that I can change my details in a layout that reads like the design.

**Assumptions**
- Prototype: `js/settings.js`, `css/screens.css` `.set-col` (max-width 720), `.set-tabs`, `.srow`, `.switch`; pairs `settings-{profile,signature,preferences,notifications}-default`, `settings-profile-staff-role`, `settings-2fa-on`, `settings-signature-away-on`. Desktop: `desktop/src/settings/*.tsx`.
- ST-01 is a P1 real bug: in Notifications the event label and help text run together ("New inquiryWhen a client submits…"), probe `glued-text` x3. Fix the markup so label and help are separate blocks. Update `PreferencesTab.test.tsx:89` and the Notifications test.
- **Decision D4 (ST-02, ST-42), pending the user's answer.** Assumed option (a), the recommendation: the Away card moves into Signature (Admin only), under the Email signature card, with the prototype field order; the Admin `Away message` sub-tab is removed. `ux-spec.md` S2 already places it there.
- **Decision D2 (ST-04), pending the user's answer.** Assumed option (a), the recommendation: the email stays read-only (`ux-spec.md:152`); the prototype's editable field needs a backend re-verify flow, out of this epic. The label and layout still match the prototype (`Email *`, side by side with `Full name *`); the row is `accepted deviation`. If the user answers (b), stop and open a backend story.
- ST-41: Save buttons are disabled until the form is dirty on the desktop and always enabled in the prototype. Keep the dirty rule (prevents empty saves), `accepted deviation`.
- ST-19/ST-20: the grid is 2x2 in prototype order and wording (Language, Time zone, Date format, Start page after sign-in). Time zones show friendly labels (`Pacific Time (US & Canada)`); the stored value stays the IANA id. Language has one disabled option on the desktop (no translations exist) against four enabled in the prototype: `accepted deviation`. The prototype date-format options (`Nov 7, 2026`, `7 Nov 2026`, `11/07/2026`) differ from `format.ts` (DD/MM/YYYY, YYYY-MM-DD, MM/DD/YYYY): this is the D1 conflict, so the option list follows the D1 answer and until then stays as built.
- The Usage and Keys tabs have no prototype twin.

**Acceptance Criteria**

**Given** the Settings frame (ST-05, ST-06, ST-07, ST-08, ST-10)
**When** any Settings tab renders
**Then** the tab bar is the prototype's (600 weight, accent underline), the `Admin only` badge is a dark filled pill with white text, the h1/lede scale is `text-xl` with the lede 4 px below, and the content is a `.set-col` of max-width 720 px made of bordered section cards

**Given** the Profile tab (ST-11, ST-12, ST-13, ST-14, ST-04)
**When** it renders
**Then** Upload photo / Remove with the hint "JPEG, PNG or WebP, up to 2 MB."; `Full name *` and `Email *` side by side (email read-only per D2 assumption (a)); the Password card has the prototype fields and no strength meter; two-factor is a card with an `srow` (title + help left, pill + button right)

**Given** the Signature tab (ST-16, ST-17, ST-18)
**When** it renders
**Then** an `Email signature` card with a switch, the 2x2 grid Sign-off / Display name * / Job title / Phone, then Preview, then Save; the admin Studio block follows the prototype order

**Given** the Away card (ST-02, ST-42, D4 assumption (a))
**When** an admin opens Signature
**Then** the Away card is under the signature card with the prototype field order, and the Admin `Away message` sub-tab no longer exists

**Given** the Preferences tab (ST-19, ST-20, ST-21)
**When** it renders
**Then** a 2x2 grid Language, Timezone, Date format, Start page, friendly timezone labels, and a switch for Press Enter to send with the prototype hint

**Given** the Notifications tab (ST-01, ST-22, ST-23, ST-24)
**When** it renders
**Then** each event has its label and help as separate blocks (no `glued-text` in the probe), the Email / In-app columns use blue switches, headers are uppercase `EVENT / EMAIL / IN-APP`, and the Email digest card heading and label match

**Given** a staff-role user opens Settings (ST-15)
**When** the tabs render
**Then** Admin is hidden and the pair `settings-profile-staff-role` matches

**Given** the story's screens are captured on both sides
**When** `node scripts/capture.mjs --side both --only {only}` and `npm run shots:diff -- --only {only}` run
**Then** `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `dialog-scroll` or `dialog-overflow` for the desktop side of these screens (`text-ellipsis` only where the prototype truncates the same text), and the run logs no `UNMOCKED` request and no page or console error

**Given** every audit row listed above
**When** the story is done
**Then** the row's Status in `docs/planning-artifacts/ui-parity/audit.md` is `closed` with the fix commit and the after-screenshot path, or the row says `accepted deviation` with the decision it follows (D1 to D5 in the change proposal) and the reason

**When** the lead reads the montage in `ui-parity/diff/`
**Then** the Dev record has one line per pair: `match`, or the remaining difference and why it is fixture-only noise (SVG gown art, fixed clock, mock data). Pixel % is recorded in the Dev record as a trend and is not a gate
