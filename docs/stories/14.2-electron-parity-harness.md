# Story 14.2: Electron-owned parity harness

As the reviewer, I want a repeatable harness that captures every existing screen state from the original renderer and, later, from Electron, so that "zero visual regression" is a diff and not an opinion.

**Assumptions**
- The existing capture code is reused read-only: `desktop/scripts/shots/{screens,fixtures,probe,common,tauri-shim}.mjs` and `desktop/scripts/shots/desk/*.mjs`. They are imported, never edited.
- `desktop/scripts/capture.mjs` and `desktop/scripts/shots/desktop.mjs` are **not** run: they write to `docs/planning-artifacts/ui-parity/` and start Vite inside `desktop/` (cache in `desktop/node_modules/.vite`).
- Only the baseline side can be captured in this story. The Electron side is wired here and switched on in 20.1 once 15–17 exist.
- Viewports: 1440×900 (as the existing harness), plus native 1280×800 and 1100×700 for window-level checks.

**Acceptance Criteria**

**Given** the harness is started with `--side baseline`
**When** it runs every entry of `SCREENS` that has a `desk` driver
**Then** PNGs land in `electron/parity-out/baseline/<id>-<state>.png` and per-screen probe JSON in `electron/parity-out/baseline/probe.json`; nothing is written outside `electron/`.

**Given** two runs on the same machine
**When** their PNGs are compared
**Then** they are byte-identical (fixed clock `NOW`, `FREEZE_CSS`, `reducedMotion: 'reduce'`, `settle()`, Inter fonts, pointer parked); any differing file fails the determinism test and is listed, and the harness is not used for parity until the cause is removed.

**Given** a baseline and an Electron output directory
**When** `compare` runs
**Then** it reports for every pair: dimensions, pixel-diff count, geometry findings from the probe, copy findings, and a list of missing or extra states; any missing state is a failure.

**Given** the harness source
**When** it is scanned
**Then** it contains no call to `flush()` from `probe.mjs`, no use of `OUT` from `common.mjs`, and no `spawn('npx', ['vite'` with `cwd` under `desktop/`.

**Given** keyboard, focus, toast and accessibility checks (NFR-7)
**When** they are defined
**Then** they are separate assertions listed in `electron/test/parity/a11y-checks.md`, not folded into screenshot normalisation.

**Tasks**
- `electron/test/parity/harness.mjs`: import `SCREENS`, `name` from `desktop/scripts/shots/screens.mjs`; `makeHandler`, `routes`, `NOW`, `imgSvg` from `fixtures.mjs`; `installShim` from `tauri-shim.mjs`; `probe` from `probe.mjs`; `settle`, `VIEWPORT`, `FREEZE_CSS` from `common.mjs`. Use own output directory and own in-memory record list.
- `electron/test/parity/serve-renderer.mjs`: serve the renderer build from `electron/build/renderer/` (from 14.4) on a random port; until 14.4 lands, accept `--renderer-url`.
- `electron/test/parity/compare.mjs`: pair files by name, run pixel and probe comparison, write `electron/parity-out/report.json`.
- `electron/test/parity/electron-side.mjs`: Playwright `_electron.launch` driver, state-by-state, against a mock API (fixture table served over HTTP on loopback); stays disabled until 20.1.
- `electron/test/parity/a11y-checks.md`: focus order, Escape, toast live region, reduced motion, from the existing `probe.mjs` checks.
- `electron/test/parity/harness.test.ts`: the static scan above, plus a unit test for `compare` on two tiny fixture PNGs.
- `electron/.gitignore` entry for `parity-out/` (own file; root `.gitignore` is not edited).

**Dev notes**
- `common.mjs` reads the Inter fonts from `backend/app/src/main/resources/static/fonts` at import. That is a read.
- `screens.mjs` imports `./desk/index.mjs`; both are pure data and driver functions. Check for import-time side effects when the story starts.
- The existing fixture handler answers `invoke` commands, not HTTP. The Electron side needs a mock HTTP API that returns the same `routes()` table; keep its behaviour identical or the comparison is meaningless. Record any gap as a risk in the story notes.
- The prototype under `prototype/v0.1.0` is a visual reference only and is not captured by this harness.

**Testing**
- Run `electron/test/parity/harness.test.ts`, then a baseline run twice and `compare` on the two outputs (expect zero differences).
- Existing mocked-Chromium screenshots cannot certify native behaviour; native checks are 17.x, 18.4 and 20.1.

**Prototype unchanged check**
- Require the protected-path gate from 14.1 to pass, and `git status` to show no change under `docs/planning-artifacts/ui-parity/` and `desktop/`.
- Capturing the original renderer must not alter it; compare the baseline run against the committed `docs/planning-artifacts/ui-parity/desktop/*.png` only by reading.
