# Story 1.7: Desktop shell and sign-in

As a Staff member,
I want the desktop app to open my browser to sign in, return by Deep Link, and keep me signed in using my system keychain,
So that I can use the app without ever typing a password into it.

**Assumptions**
- Scaffold is hand-written in the layout of architecture §3: React 19, Vite, TypeScript, Vitest; Tauri 2.12.x; plugins deep-link 2.6.3, single-instance 2.5.5, keyring crate 4.2.0, reqwest 0.13.5.
- Backend and Auth Web URLs are build-time constants (FR-6); dev builds point at localhost.
- Spike S-2 (Deep Link on Linux, loopback fallback) and S-4 (CSP with Tauri IPC) are done as tasks here; their findings go to `docs/architecture.md` §12 as a one-line update.
- Screens in this story: signed-out, Deep Link wait/failure, keychain unavailable, session expired, and a placeholder signed-in view that shows `GET /me`. The full shell is Story 1.8.

**Acceptance Criteria**

**Given** the webview
**When** its CSP is read
**Then** it has `connect-src 'none'` and no remote script, font or image source, and a test fails if the Tauri config loosens it (AD-10).

**Given** the closed Rust command set
**When** the registered commands are listed
**Then** they are exactly `api_request`, `sign_in`, `sign_out`, `upload_files`, `export_gowns`, `check_update`, `install_update`, `set_dirty` (later ones return "not implemented" now) and a Rust test fails on any extra.

**Given** the signed-out screen
**When** the user presses **Sign in**
**Then** the shell creates a `code_verifier`, S256 challenge and `state`, opens the system browser at the Auth Web `/authorize`, and shows "Finish signing in in your browser" with a 5-minute timeout (A-UX12).

**Given** the browser returns `klei://auth/callback?code&state`
**When** the shell receives it (single-instance forwards a second launch)
**Then** it checks `state`, exchanges `{code, verifier}`, keeps the access token in memory, stores the refresh token in the OS keychain, and shows the signed-in view; a wrong `state` shows "Sign-in didn't finish. Try again." with **Retry**.

**Given** a platform where the scheme cannot register (Linux AppImage without desktop integration)
**When** sign-in starts
**Then** the loopback form `http://127.0.0.1:<port>/callback` is used, the shell listens for one request and closes (spike S-2 result recorded).

**Given** a 401 `token_stale`
**When** any `api_request` fails that way
**Then** the shell refreshes once, retries once, else shows "Session expired" and deletes the keychain entry; unsent state in React memory is kept.

**Given** no usable keychain
**When** the app starts
**Then** it shows "Can't reach your system keychain. Klei Bridal needs it to keep you signed in." and persists nothing (fail closed, NFR-4).

**Given** **Sign out**
**When** pressed
**Then** `POST /auth/logout` is called, the keychain entry is deleted, and the signed-out screen shows.

**Given** the shell
**When** a Rust test inspects file writes
**Then** nothing is persisted outside the keychain; no token appears in the bundle, localStorage, sessionStorage or IndexedDB.

**Given** `KLEI_SMOKE=1`
**When** the built app launches
**Then** it shows the signed-out state and exits 0 after the window is ready (used by the OS smoke job).

**Tasks**
- `desktop/` Vite + React shell; `src-tauri` commands `api_request`, `sign_in`, `sign_out`; token state; keychain wrapper; deep-link and loopback handlers; CSP; `tauri.conf.json` with the single update URL constant left empty until 9.3.
- Vitest tests for the signed-out, wait, failure, keychain and session-expired screens; Rust tests for command set, PKCE, state check, keychain wrapper (mock backend).
- CI: desktop pipeline and the three-OS build/smoke matrix from architecture §9.4.
- `openapi-typescript` generation step and drift check (AR-14).

**Checks**
- `cd desktop && npm ci && npm test && (cd src-tauri && cargo test && cargo clippy -- -D warnings)`
- `cd backend && ./mvnw verify`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh`
- Manual per OS (release checklist, S-2): open a `klei://` link, confirm the app receives it.
- NFR-1: Rust test for no disk writes; secrets scan of the built bundle for the verifier and tokens.

## Dev record

Done 2026-11-08.

**Built.** `desktop/` React 19 + Vite + Vitest; `desktop/src-tauri/` Rust shell (`error, pkce, keychain, config, loopback, session, commands, lib`). Eight-command set closed by `build.rs` app manifest and `capabilities/default.json`. Access token in memory; refresh token only in the OS keychain, fail closed. Single-flight refresh, one retry, then `session_expired` and keychain cleared. Loopback fallback on Linux or `KLEI_LOOPBACK=1`. `.github/workflows/desktop.yml`: three-OS matrix, tests, types drift, clippy, binary build, `KLEI_SMOKE=1` launch, bundle token scan.

**Checks run (macOS).**
- `cd desktop && npm test`: 11 pass (axe-core included).
- `cd desktop/src-tauri && cargo test`: 15 unit + 3 contract pass; `cargo clippy --all-targets -- -D warnings` clean.
- `npm run types:check`, `npm run build`: pass.
- `npx tauri build --debug --no-bundle` then `KLEI_SMOKE=1 ./target/debug/klei-desktop`: exit 0. Exit comes from the webview's own `api_request` getting `signed_out`, so IPC works under the CSP. 60 s failsafe exits 1.

**Spikes.** S-4 closed. S-2 half closed (see `docs/architecture.md` section 12).

**Skipped, risk.**
- Windows and Linux builds not run locally; first CI run is their proof.
- `klei://` link per OS is a manual release-checklist step (S-2).
- Logout is best effort: offline sign-out empties the keychain, the server session ends by expiry.
- Smoke uses an in-memory keychain; real keychain only covered by manual check.
- Icons are placeholders; release builds need `KLEI_API_URL` and `KLEI_AUTH_URL`.
- Live check against the compose backend not run; contract proven by the mock backend and backend `AuthWebIT`.
- Backend untouched, `./mvnw verify` not re-run.
