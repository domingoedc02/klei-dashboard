# Story 12.6: Review inline Move, Merge and Split panel

As a Staff member reviewing a batch,
I want to select photos in a group and move, merge or split them from a panel on the page,
So that I do not hunt for them in "Actions" and "⋯" menus, and the screen matches the wireframe.

**Assumptions**
- Audit row G-05 and G-20 (photo menu clipped by `.sheet`). User decision 2026-11-11: **match the prototype's inline panel and drop the Actions menu**. Frontend only. The commit request, the staged-edit model (`Draft`, `apply`, Undo stack, leave guard, version) from Story 11.6 are unchanged; only the way a user picks the photos and targets changes.
- Prototype: `js/upload.js:40-68` (render) and `:97-132` (acts `up-cur`, `up-sel`, `up-move`, `up-split`, `up-merge`, `up-regen`); CSS `css/screens.css:57-78` (`.rv`, `.rv-list`, `.gl`, `.strip`, `.thumbs`, `.th`, `.tick`, `.tags-grid`, `.conf`) and `:152-168` (`.org`, `.org-row`, `.combo`).
- Target structure (prototype order inside the right-hand `section.card`): (1) Name field with "(auto-named, editable)" and, to its right, "Confidence N%" + 64px bar + pill; (2) h3 "Photos in this group (N)" with the muted hint "Select photos to move or split"; (3) thumbnail grid of toggle buttons; (4) `role="group"` "Organize this group" with three rows: **Move selected photos to**, **Merge this whole gown into**, **Split selected photos into a new gown**; (5) tags grid; (6) description field with ghost small Rewrite.
- List card (prototype `.gl`): name (truncate) + pill on one line, up to five 40px thumbnails, then `N photos · {silhouette} · {fabric}` (first tag of each type; parts that do not exist are left out). The confidence bar leaves the list card (it moves to the detail header). Heading above the list: **"Gown groups"** (was "N groups found"). List: `max-height: 600px; overflow-y: auto; padding: 2px`.
- Decisions inside the scope (Ej may veto at review):
  - **Combobox → native `select`.** The prototype uses a search combobox; the app has none and the brief says reuse existing components. Native `select` (as in the old Picker, `Review.tsx:406-420`) is accessible, needs no new component, and groups per batch are few. Accepted deviation, same family as the Edit gown tag UI.
  - **"New group" option on Move is dropped.** Split already creates a new gown (with tags and description copied, `made()` at `Review.tsx:44-46`); the prototype's Move lists existing gowns only. Test `moves a photo to a new group…` (`Review.test.tsx:234`) becomes a Split test.
  - **Discard photo stays**, as a fourth button "Discard selected" in the same panel (11.6 behaviour, commit body `discarded`). The prototype has no discard of single photos. Undo stays (Story 11.5/11.6 assumption).
  - **Photo lightbox stays** (11.6 AC, `Review.test.tsx:130`, `:146`). Each thumbnail gets a small corner button `aria-label="Open photo N of M"` (same label as today, `Review.tsx:343`) that opens the existing `Lightbox`; the thumbnail itself toggles selection.
- Selection is local UI state in `Editor` (`string[]` of photo ids), not part of `History`. Derive `picked = photos.filter((p) => sel.includes(p))` so Undo or a group switch can never leave a stale id; `Editor` is already keyed by `group.id` (`Review.tsx:252`), so selection resets when another group is chosen. Clear after any op.
- Staged ops take a list: `Op` becomes `move { photos: string[]; to: string }`, `split { photos: string[] }`, `merge { from; into }` (unchanged), `discard { photos: string[] }`; `apply` loops, still pure, one Undo step per press. Toast text: `Moved N photo(s) to {name}`; `Split into a new gown. Check its tags.` (unchanged); `Photo discarded` for one, `N photos discarded` for several; `Merged into {name}` (unchanged).
- Enable rules (prototype `up-move`/`up-split`/`up-merge`): Move needs ≥1 selected and a target; Merge needs a target (no selection needed); Split needs ≥1 and fewer than all selected, with the help text "Leave at least one photo in this gown." when all are selected; Discard needs ≥1 selected. Move and Merge selects are disabled with placeholder "No other gowns yet" when `others` is empty. Selection summary under the thumbnails is `aria-live="polite"` ("2 photos selected.").
- Removed code: `Menu` (`Review.tsx:362-403`), `Picker` (`:406-420`), `pick` and `groupOptions` in `Editor` (`:287-290`), the `.tools` Actions row (`:294-298`), the `.photos` list and `Menu` per photo (`:340-355`), CSS `.menuwrap`, `.menubtn`, `.photos .menuwrap*`, `.tools` (`styles.css:~245-255`; `.menu` itself stays, the profile and bell menus use it), the `.photos*` rules replaced by `.thumbs`/`.th`. `Icon` names `move`, `merge`, `split` exist (`shell/icons.tsx`).
- Tag UI stays as built (chips + native select per taxonomy type, `Review.tsx:305-325`); only its container becomes the prototype's 3-column grid (`repeat(3, minmax(0, 1fr))`, gap `--space-3`). Five types wrap 3 + 2. Accepted deviation from the combobox boxes.
- Width check at 1100x700: sheet content 796px; list 320 + gap 24 leaves 452px; card padding 24 leaves 404px; six thumbs at gap 8 are about 60px each; three tag columns about 126px. The harness asserts these do not overflow.
- Out of scope: arrow-key navigation inside the group list (12.14), drag and drop between groups, multi-select across groups.

**Acceptance Criteria**

**Given** the Review screen
**When** it renders (prototype `js/upload.js:55-60`)
**Then** the list heading is "Gown groups"; each card shows the name (ellipsis when long) and the confidence pill on one line, up to five 40px thumbnails, and `N photos · Silhouette · Fabric` (parts missing are omitted: `2 photos` when untagged); no confidence bar is in the card; the list scrolls inside itself above 600px. Test: `Review.test.tsx` rows text equals `['Group 1Low · check2 photos', …]` without a bar, `.confbar` is absent from `.grouplist`, and a 12-group fixture has `.rv-list`-style `overflow-y: auto` (`styles.test.ts`).

**Given** a selected group
**When** the detail renders (prototype `:62-63`)
**Then** it shows the Name field and "Confidence 40%" with a bar `role="img" aria-label="AI confidence 40 percent, Low"` and the pill (with `title="40% confidence"`) to its right, aligned to the field baseline. Test: asserts the img role, the label, and that `getByLabelText('Name')` still edits the name as staged.

**Given** a group with N photos
**When** the thumbnails render
**Then** the heading reads "Photos in this group (N)", the hint "Select photos to move or split" sits at its right, and the photos are a six-column `minmax(0, 1fr)` grid of toggle buttons: `aria-pressed="false"`, `aria-label="Photo k"`, a 20px tick box that shows a check when selected, and an accent border when pressed. Test: click toggles `aria-pressed`; Space on a focused thumb toggles; the live line reads "1 photo selected."

**Given** one or more photos selected and another group exists
**When** the user chooses a target in "Move selected photos to" and presses **Move**
**Then** the photos leave the group, the target group gains them, the toast says "Moved 1 photo to Group 2", no request is sent, selection clears, and **Undo** puts them back in one step. Test: replaces `Review.test.tsx:220` (menu path becomes thumb + select + button); `sent` stays `[]`.

**Given** no photo selected
**When** the panel renders
**Then** Move and Split and Discard selected are disabled, the Move help reads "Select photos above first, then choose a gown.", and the Split help reads "Select photos above first. They become a separate gown." Test per control.

**Given** a target chosen in "Merge this whole gown into"
**When** the user presses **Merge**
**Then** all photos join the target, the target keeps its name, this group disappears, the toast says "Merged into Group 2", and Undo restores both groups. The help line reads "Moves all N photos into the gown you pick and removes this group." Test: replaces `Review.test.tsx:257` (Group actions menu path removed).

**Given** a selection smaller than the group
**When** the user presses **Split into new gown**
**Then** a new gown "{name} II" holds the selected photos with the source's tags and description, becomes the selected group, the toast says "Split into a new gown. Check its tags.", and Undo merges it back. When every photo is selected the button is disabled and the help reads "Leave at least one photo in this gown." Test: replaces `:246` and absorbs `:234` (the New group path is gone; assert the "New group" option no longer exists).

**Given** photos selected
**When** the user presses **Discard selected**
**Then** one photo toasts "Photo discarded" and several toast "2 photos discarded"; a group left empty goes with them; the empty state "No photos left. Undo the last change or discard the batch." and a disabled Confirm appear when none remain; Undo restores. Tests: replaces `:270` and `:283`.

**Given** the Actions menu and the photo "⋯" menus
**When** Review renders
**Then** no button named "Group actions" or "Photo N actions" exists, `Menu` and `Picker` are not in the bundle (`grep -n "function Menu\|function Picker" desktop/src/upload/Review.tsx` returns nothing), and `.menuwrap`, `.menubtn` are not in `styles.css`. `styles.test.ts` asserts the CSS absence.

**Given** a thumbnail
**When** the corner "Open photo k of M" button is pressed
**Then** the existing Lightbox opens (Esc returns focus to that button, arrows step), and pressing the corner button does not toggle selection. Existing tests at `:130` and `:146` pass unchanged apart from any selector for the opener.

**Given** the tags area
**When** the taxonomy is loaded
**Then** the types appear in a three-column grid of `.tagfield` blocks, each with its label, chips (remove buttons keep `aria-label="Remove {value} from {Type}"`) and the Add select; at 1100x700 no tag select or chip row is clipped (harness check (d)).

**Given** the description
**When** it renders
**Then** the label "AI-written description" has a ghost small **Rewrite** button on its right, the textarea follows, the count `N / 2,000` and the help "Edit freely. Your changes are kept when you save." sit below, and the textarea is fully visible above the footer when scrolled into view (12.5 footer rules).

**Given** the panel
**When** `axe.run` runs on Review in each state (nothing selected, two selected, merge target chosen, empty state)
**Then** zero violations. Selects have labels, thumbnails have names, the organize group has a name.

**Given** the harness
**When** `node infra/ci/shots.mjs --only upload-review --only upload-review-long --only upload-review-selected` runs at 1100x700 and 1280x800
**Then** all checks pass (no overlap, no overflow, footer clear) and the screenshots show list, header, thumbnails, the three organize rows and the tag grid in the prototype's order. `upload-review-selected` is a fixture that selects two thumbnails and picks a Move target.
