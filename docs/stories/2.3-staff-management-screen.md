# Story 2.3: Staff management screen

As an Admin,
I want to list, invite, edit, re-invite and delete staff in the app,
So that I control who can use the dashboard.

**Assumptions**
- Settings frame (title "Settings", tabs) is built here for the first time: Profile, Signature, Preferences, Notifications and the Admin tabs appear as tabs; non-built tabs are hidden until their story lands.
- "Last active" is written at most once per hour per User.
- Delete is a hard delete of the `app_user` row; uploads and replies stay and keep the `author_user_id` or `created_by` reference as a plain UUID that no longer joins `[ASSUMPTION]`: those FKs are `ON DELETE SET NULL`, and the UI shows "Former staff member". Migration touches only tables that exist at this point (`audit_entry` stores actor id and name in ciphertext, no FK).
- OPEN QUESTION: should deleting a User who owns an active Upload Batch discard the batch? Default: yes, discarded with the User row in the same transaction; the batch table does not exist until Epic 4, so Story 4.1 carries this rule.

**Acceptance Criteria**

**Given** `GET /admin/users`
**When** called with `PERM_MANAGE_STAFF`
**Then** it returns name, email, Role, Status (Active or Invited), last active, avatar flag, and `version`; a caller without the Permission gets 403.

**Given** `PATCH /admin/users/{id} {name, email, roleId}` with `If-Match`
**When** applied
**Then** the row is updated, a stale version returns 409 `conflict`, the permission epoch is bumped when the Role changes, the User's refresh families are revoked on a Role change, and an Audit Entry is written.

**Given** `POST /admin/users/{id}/resend` on an Invited User
**When** called
**Then** the earlier Invitation is invalidated, a new mail is sent, and the toast "Invite re-sent to {email}" shows in the app; on an Active User it returns 409.

**Given** `DELETE /admin/users/{id}`
**When** called
**Then** the User loses access on the next request (families revoked, `sid` revoked, epoch bumped), the row is removed in one transaction, and an Audit Entry is written.

**Given** the last Admin
**When** delete or demote is attempted
**Then** it returns 409 `conflict` under a lock on the Admin `role` row, and the UI shows the control disabled with the tooltip "A studio needs at least one admin."

**Given** the Staff table (S5)
**When** it renders
**Then** it shows Name with avatar initial, Email, Role pill, Status pill, Last active, **Invite staff**, and row actions Edit, Resend invite (Invited only) and Delete; Loading is skeleton rows; Error is an error block with Retry; Empty is "Only you so far. Invite your first staff member." with **Invite staff**; the empty-state art is used.

**Given** the dialogs
**When** opened
**Then** Invite/Edit staff has name, email, Role select and validation; Delete reads "Delete {name}? They lose access right away. Their uploads and replies stay." with Cancel focused and a danger button.

**Given** a non-Admin
**When** they navigate to the route
**Then** the Settings frame does not show Admin tabs and a direct route shows the forbidden view.

**Given** the leak suite
**When** extended
**Then** Sentinel names and emails created through edit, invite and delete leave no plaintext.

## Dev record

**Done**
