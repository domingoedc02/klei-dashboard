# Story 10.4: Calibrate defaults from evaluation data

As the operator,
I want the default sensitivity and the Confidence bands set from my own gown photos,
So that High means "almost certainly one gown" in this studio, not in a guess.

**Assumptions**
- Pure constants and doc edits. No new code path, no new setting, no migration. No model training.
- Inputs: the Story 10.1 table, run after Stories 10.2 and 10.3 so the numbers reflect the shipped formula and verify step. The operator supplies the data; a Dev agent does not.
- Targets (tunable, `[ASSUMPTION]`): at the chosen default, at least 95 % of groups scored High hold one gown only, pair recall at least 0.8, and the Medium band holds no more than 20 % pure-wrong groups. If the data cannot meet them, record the best trade-off and why.
- `THRESHOLDS` (0.55 / 0.65 / 0.75 / 0.82 / 0.88), the default sensitivity 3 (`AiSettingService.kt:180`) and the band cut-offs 90 / 80 (`confidenceBand`, PRD glossary line 83) are the only values that may change.
- OPEN QUESTION (C-1): with fewer than 5 known gowns the data is too thin to move a default. Default: change nothing and record "insufficient data" in the Dev record.
- An existing studio keeps its stored sensitivity (`ai_setting.sensitivity_ct`). A new default affects new installs and the reset action only.

**Acceptance Criteria**

**Given** the Story 10.1 report after Stories 10.2 and 10.3
**When** the operator picks a default sensitivity
**Then** the story's Dev record names the chosen value, the table row it came from, and the pure-group share at High for that row.

**Given** a changed default sensitivity
**When** `AiSettingServiceTest` or `AiAdminIT` reads settings on a fresh install
**Then** the default equals the new value, and an already-saved sensitivity is unchanged.

**Given** changed band cut-offs
**When** `ClustererTest.bands` and `Review.test.tsx` run
**Then** both pin the new cut-offs on each side (value, value minus 1), and `docs/prd.md` glossary line 83 states the same numbers.

**Given** changed `THRESHOLDS`
**When** `ClustererTest` runs
**Then** `threshold(1..5)` returns the new table, clamps 0 and 6, and the AI tab labels (Very loose to Very strict, `AiTab.tsx:31`) still read in the same order.

**Given** no value changes because of insufficient data (C-1)
**When** the story closes
**Then** no code file is touched and the Dev record says so.

**Given** the leak suite
**When** extended
**Then** no change (constants only).

**Tasks**
- `backend/app/src/main/kotlin/co/klei/app/upload/Clusterer.kt`: `THRESHOLDS`, `confidenceBand` (only if the data says so).
- `backend/app/src/main/kotlin/co/klei/app/ai/AiSettingService.kt`: default sensitivity (only if the data says so).
- `ClustererTest.kt`, `AiAdminIT.kt`, `desktop/src/upload/Review.test.tsx`: update pins.
- `docs/prd.md` glossary Confidence (line 83) and FR-9; `docs/epics/epics.md` 4.3 "Clustering" line if the table changes; `docs/ops.md` tuning paragraph from Story 10.1 with the recommended default.

**Checks**

- `cd desktop && npm test`
- Manual, operator only: re-run Story 10.1 with the new constants and paste the table.
