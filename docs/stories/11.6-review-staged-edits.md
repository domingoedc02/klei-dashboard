# Story 11.6: Review with staged edits and Confirm and save

As a Staff member,
I want my review edits to stay on my screen until I press Confirm and save,
So that nothing changes in the batch or the Gallery before I decide.

**Assumptions**
- Prototype wins (user decision, 2026-11-10): the banner reads "**{n} photos → {m} gowns.** … Nothing is saved until you confirm." Today every edit is written at once and Undo is the inverse call (`Review.tsx`, `rearrange`, `undo`). That model goes away.
- All edits (move, split, merge, discard, rename, tags, description) are held in client state and sent as one request: `POST /api/v1/uploads/{id}/commit` with the full final state per group plus the `version` each group had when loaded. The server applies it in one transaction and then runs the Save of Story 4.7. One call, all or nothing.
- Reuse over rewrite: `commit` calls the existing rules in `RearrangeService` and `SaveBatchService` (`backend/app/src/main/kotlin/co/klei/app/upload/RearrangeService.kt`, `.../gown/SaveBatchService.kt`); it adds no second implementation of merge, split or move.
- Undo becomes a local undo stack (no network). The 8 s toast is dropped; Undo is a button in the save bar.
- A reload or crash loses staged edits `[ASSUMPTION]`. Mitigation: a leave guard on route change and window close ("Leave without saving?"). Persisting staged edits is out of scope. This is a known downgrade from Story 4.5.
- "Rewrite" (prototype, ghost button next to "AI-written description") calls a new `POST /api/v1/uploads/{id}/groups/{groupId}/rewrite`, which reuses `GroupingService.describeOne` for that group, 1 AI call per click, purpose `DESCRIBE`, thumbnails only, nothing stored until `commit`. The result fills the editor and is staged.
- OPEN QUESTION (R-1): does "Rewrite" keep the user's edited tags? Default: it returns a description only; tags stay as staged.
- Epic 10 may split or re-score groups before Review. Review only reads the groups the batch already holds.

**Acceptance Criteria**

**Given** the Review screen with groups
**When** it renders
**Then** the banner reads "{n} photos → {m} gowns. … Nothing is saved until you confirm.", each group row shows its confidence bar and pill (High, Medium, "Low · check") and a strip of up to 5 thumbnails, and the save bar reads "{m} gowns · {n} photos will be added to Gallery" with **Discard batch** and **Confirm and save {m} gowns**.

**Given** a Staff member moves, splits, merges, discards, renames, retags or edits a description
**When** the action completes
**Then** only client state changes: no request is sent, the toast reads "Moved {k} photo(s) to {name}", "Merged into {name}" or "Split into a new gown. Check its tags.", and the save bar **Undo** reverts the last staged action; Undo can step back to the loaded state.

**Given** staged edits
**When** the Staff member presses **Confirm and save {m} gowns**
**Then** one `POST /uploads/{id}/commit` carries the final groups and their loaded `version`s, the server applies all of it and saves the gowns in one transaction, the batch ends, and the Gallery shows the new gowns.

**Given** another tab or device changed a group after this screen loaded
**When** `commit` carries a stale `version`
**Then** the server returns 409 `conflict`, writes nothing, and the screen shows "This batch changed elsewhere. Reload to see the latest." with **Reload**; staged edits are kept in memory until the Staff member reloads.

**Given** `commit` fails halfway on the server (any exception)
**When** the transaction rolls back
**Then** the batch is unchanged (still `review`), the screen shows "Couldn't save. Try again." and staged edits stay.

**Given** staged edits exist
**When** the Staff member changes route or closes the window
**Then** a dialog "Leave without saving?" / "Your changes to this batch will be lost." with **Keep reviewing** (autofocus) and **Leave** appears; with no staged edits there is no dialog.

**Given** **Discard batch**
**When** pressed
**Then** the dialog reads "Discard this batch?" / "The {n} uploaded photos and every AI group will be removed. This can’t be undone." with **Keep reviewing** (autofocus) and **Discard batch** (danger); on confirm the batch is deleted (Story 4.7) and the toast reads "Batch discarded".

**Given** **Rewrite** on a group
**When** pressed
**Then** one `DESCRIBE` call runs for that group, the button shows busy, the new description fills the editor and is staged; a provider error shows "Couldn't rewrite. Try again." and keeps the old text; one `ai_usage` row is written with the label "group {id}" and no filename.

**Given** the leak suite
**When** extended
**Then** `commit` and `rewrite` leave no Sentinel from names, descriptions or filenames in logs or in `ai_usage`, and the `commit` body is never logged.

**Tasks**
- Backend: `UploadController` add `POST /uploads/{id}/commit` and `POST /uploads/{id}/groups/{groupId}/rewrite`; `CommitService` calling `RearrangeService` rules and `SaveBatchService` in one `@Transactional`; version check per group; `openapi.json` and `schema.d.ts` (`types:check`).
- Desktop: `desktop/src/upload/Review.tsx` replace the per-edit `call`/`undo` plumbing with a reducer and an undo stack; save bar; leave guard (hook into `useRoute` in `desktop/src/shell/`); banner, toasts and dialog copy exactly as above; Rewrite button.
- Remove dead code: debounce autosave (`DEBOUNCE_MS`), inverse-call undo, the 8 s Undo toast.
- Tests: `CommitServiceIT` (all-or-nothing, stale version 409, rollback on forced failure, equals the result of the same edits through the old endpoints); `Review.test.tsx` (staged move, split, merge, discard, undo stack, leave guard, conflict, rewrite error); leak suite extension.

**Checks**
- `cd backend && ./mvnw verify`
- `cd desktop && npm test && npm run types:check && (cd src-tauri && cargo test)`
- `node infra/ci/axe.mjs` on the Review screen, including the leave dialog.
- Manual: edit, reload without saving (guard fires), then edit and save (Gallery shows the result).
