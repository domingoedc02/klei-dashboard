# Story 11.8: Inquiries list, thread and composer match the prototype

As a Staff member,
I want the inbox, the thread and the reply box to look and read like the approved prototype,
So that the screens I signed off are the screens I use.

**Assumptions**
- Prototype wins. Desktop-only behaviour is kept: paging ("Show more inquiries"), polling, unread-after-delay, draft autosave and Discard, close-permission gating, 409/404 toasts, the over-limit and sanitiser rules.
- The prototype composer has no numbered list; the desktop has one. `[ASSUMPTION]` keep the numbered list (it works, the sanitiser allows it) and add it to the icon toolbar.
- The prototype auto-prefixes links with `https://` or `mailto:`. The desktop is stricter (rejects with a message). `[ASSUMPTION]` keep strict validation, add the auto-prefix for bare domains and addresses, and keep the message for anything else.
- Hover card: mouse and focus only, as the prototype notes; keyboard users open the profile from the focusable name. Needs one existing endpoint, `GET` of the client already loaded with the thread (Story 7.2); no new API unless the thread payload lacks phone, city and wedding date (check first).
- The word is "Customer" in the UI (user decision); code, API and DB keep `client`.
- First task: confirm the rows marked **verify** (message card markup, composer layout, empty-send message, 10 MB message, thread header count and pill) against `Thread.tsx`, `Composer.tsx` and `prototype/v0.1.0/js/inquiries.js`.
- Needs Story 11.1.

**Acceptance Criteria**

**Given** an empty list
**When** it renders with a filter that hides everything
**Then** it shows compact art (144 px), "No {filter} inquiries", "Try another filter to see more messages." and **Show all**; with no inquiries at all it shows "No inquiries yet", "Website inquiries land here as soon as they arrive." and **View website form**.

**Given** no thread selected
**When** the right pane renders
**Then** it shows art, "Select an inquiry", "Pick a message on the left to read and reply." and **Open first message**.

**Given** a closed inquiry
**When** the thread renders
**Then** an info banner with icon reads "This inquiry is closed. Reopen it to reply." and **Close inquiry** / **Reopen** carry their icons; the status pill and "{n} message(s)" show in the header.

**Given** a customer name in a message
**When** the mouse rests on it for 250 ms or it receives focus
**Then** a 300 px hover card shows avatar, name, email, Phone, City, Wedding, Inquiries count and **View profile**; it closes after 150 ms off, and on Esc; the name has a dotted underline.

**Given** the composer
**When** it renders
**Then** the toolbar is icon-only 28 px buttons (Bold, Italic, Underline, Bullets, Numbered list, separator, Link, Attach), each with an accessible name; the placeholder reads "Write your reply…"; the hint reads "Enter to send · Shift+Enter for a new line" (Enter-to-send on) or "Ctrl/⌘ + Enter to send", followed by " · Signature added on send" when a signature is set.

**Given** the link bar
**When** opened
**Then** it shows the placeholder "https://example.com" and **Apply**; "example.com" becomes `https://example.com`, "a@b.co" becomes `mailto:a@b.co`, and anything else shows "Use a link that starts with http://, https:// or mailto:." (existing sanitiser test stays green).

**Given** an empty body
**When** Send is pressed
**Then** an alert with icon reads "Write a message before sending." and focus returns to the editor.

**Given** an attachment over 10 MB
**When** chosen
**Then** a toast reads "{name} is over 10 MB" and nothing is added.

**Given** a reply is sent
**When** it succeeds
**Then** the toast reads "Reply sent to {first name}" (unchanged).

**Given** the axe run
**When** it covers list, empty states, thread, hover card and composer
**Then** no serious or critical issues; the hover card is not the only way to reach the profile.
