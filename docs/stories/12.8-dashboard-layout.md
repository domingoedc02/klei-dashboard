# Story 12.8: Dashboard layout matches the prototype

As a Staff member,
I want the Dashboard stats on one row, the widgets to show dates and the AI batch, and the empty and loading states to hold their shape,
So that I read my workspace at a glance and nothing jumps while it loads.

**Assumptions**
- Audit rows G-09 (stat row wraps 3+1 at 1100), G-21 (stat card has border and shadow), G-22 (widget rows, AI card, skeleton, empty art). Group A (min-content grid) for G-09.
- Prototype: `css/screens.css:29` `.grid-4 { grid-template-columns: repeat(4, minmax(0, 1fr)); gap: var(--space-4) }`, `:31-33` `.widget`, `.widget-head`, `.big-num`; `css/base.css:65` `.card` is border only, padding `--space-6`; `js/dashboard.js:6` skeleton row (40x53 thumb + two lines), `:12-18` Recent and Unread cards with a date label on every row, `:25-28` four stat cards, `:31` AI header pill (Idle / Checking… / Ready for review), `:32-35` AI body ("Batch of N photos" + percent + `.bar`, "Grouped into N gowns · K need a quick look", **Review groups** button).
- App today: `.dash-stats` is `repeat(auto-fit, minmax(200px, 1fr))` (`desktop/src/styles.css:557`) and wraps to 3+1 at 1100; `.dash-stat` has padding `--space-4`, a border and the raised shadow (`styles.css:558`), which breaks DESIGN.md "no border plus shadow on the same surface". `Dashboard.tsx`: `:34` stat skeleton, `:45` Empty `<img width={96}>`, `:53` Recent, `:83` Inbox, `:109` Ai, `:72` and `:100` `dash-meta` (no date), `:189` widget skeleton is three 44px bars (the loaded row is taller, so the page shifts), `:211` and `:220` the asides render only when they hold data.
- API fields already exist: `GownCard.addedAt`, `InquiryItem.lastMessageAt`. No backend change.
- Empty-art decision (open point from 12.3, resolved here): **DESIGN.md wins.** DESIGN.md: "Widgets never use an image"; whole-view empties may use the 160px line-art. Dashboard widgets are widgets, so their empty state is a text-only dashed box (title, one line of help, one **primary** CTA). Prototype uses art with `K.empty({compact})`; that is an accepted deviation, recorded in `docs/ux-spec.md`. The whole-dashboard "empty workspace" (no gowns at all) is a whole view and keeps its art, at the 12.3 size (144px, `width: auto`) instead of `width={96}`.
- Kept from DESIGN.md (do NOT revert): stat number 32/600, no eyebrow caps, no appointments line.
- Epic 11 story 11.4 stays `done`; this story corrects it.

**Acceptance Criteria**

**Given** the Dashboard at 1100x700 and 1280x800
**When** it has loaded
**Then** the four stat cards sit on one row of equal width (`grid-template-columns: repeat(4, minmax(0, 1fr))`, gap `--space-4`; prototype `screens.css:29`), no card wraps, and `.sheet` has no horizontal overflow.
Test: `Dashboard.test.tsx` `it('lays the four stats out as one four-column grid')` asserts the `.dash-stats` rule in `styles.css` uses `repeat(4, minmax(0, 1fr))` (read with the `styles.test.ts` helpers, since jsdom runs with `css: false`).

**Given** a stat card
**Then** it has a 1px border, no `box-shadow`, padding `--space-6` (prototype `base.css:65`), and the number stays 32px / 600.
Test: `styles.test.ts` `it('stat cards use a border and no shadow')` for `.dash-stat`.

**Given** Recent gowns and Unread inquiries with data
**Then** each row shows its date on the right, from `addedAt` and `lastMessageAt`, formatted by the existing `formatDate` (prototype `dashboard.js:12-18`).
Test: `Dashboard.test.tsx` `it('shows a date on every recent gown and unread inquiry row')`.

**Given** the AI batch widget
**Then** the header pill reads Idle, Checking… or Ready for review (prototype `dashboard.js:31`); with a batch the body reads "Batch of N photos", the percent and a `.bar`, then "Grouped into N gowns · K need a quick look", then **Review groups** (prototype `dashboard.js:32-35`); with no batch it reads Idle with an **Upload photos** primary CTA.
Test: `Dashboard.test.tsx` `it('renders the AI batch card with count, percent and Review groups')` and `it('renders Idle when there is no batch')`.

**Given** the Dashboard is loading
**Then** it shows four stat skeletons and three widget skeletons whose rows use the 12.3 `.skeleton.row` shape (40x53 thumb + two lines, four rows), so the loaded layout does not shift.
Test: update `Dashboard.test.tsx:267` `it('shows four stat skeletons and three widget skeletons…')` to count rows per widget and assert the `.skeleton.row` class.

**Given** a widget with no data (no recent gowns, no unread inquiries)
**Then** it renders a dashed text-only empty block with one primary CTA and **no `<img>`** (DESIGN.md "widgets never use an image"); the widget heading and its "View all" link stay visible.
**Given** a workspace with no gowns at all
**Then** the whole-view empty keeps its line-art at the 12.3 size, with no `width` attribute.
Test: update `Dashboard.test.tsx:146` `it('an empty workspace reads…')`; add `it('widget empties carry no image')` asserting `within(widget).queryByRole('img')` is null.

**Given** `node infra/ci/shots.mjs --only dashboard` (the 12.1 screenshot command)
**When** run at 1100x700 and 1280x800
**Then** `report.json` has no failed check for `dashboard`, and the PNGs show one stat row, dated rows, the AI card with its bar, side by side with the prototype `dashboard` screen.
