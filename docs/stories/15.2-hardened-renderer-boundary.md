# Story 15.2: Hardened renderer boundary, `app://` and CSP

As the owner, I want the renderer to run sandboxed, isolated and unable to navigate or open windows, served from a private scheme under the same CSP as Tauri, so that a compromised page cannot reach Node, the network or the disk.

**Assumptions**
- webPreferences: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webSecurity: true`, `allowRunningInsecureContent: false`, `webviewTag: false`, `spellcheck` as the original behaves, `devTools` only in unpackaged development.
- The renderer is served from a privileged custom scheme `app://klei/` (standard, secure, supports fetch). The scheme name is final here, unless 14.3 spike 6 amends it.
- The renderer origin is `app://klei`. Windows image alias is added by 17.5, not here.
- CSP value is the Tauri one: `default-src 'self'; img-src 'self' klei-img: data:; connect-src 'none'; style-src 'self'; script-src 'self'; font-src 'self'`, delivered as a response header on every `app://` response; no `<meta>` copy is added (the original `desktop/index.html` stays unchanged).

**Acceptance Criteria**

**Given** the main window
**When** its `webPreferences` are inspected
**Then** they equal the assumptions above exactly, and a unit test fails if any key is missing or weakened.

**Given** a request for `app://klei/` or any path under it
**When** the protocol handler answers
**Then** it serves only files under the built renderer directory (`electron/build/renderer/`), rejects `..`, encoded traversal, absolute paths and symlink escapes with 404, serves `index.html` for the root only, sets correct `Content-Type`, and sets the CSP header and `X-Content-Type-Options: nosniff`.

**Given** the page tries `fetch('https://example.com')`, `XMLHttpRequest`, `WebSocket`, `EventSource` or a `<form>` post
**When** it runs
**Then** CSP `connect-src 'none'` blocks it and the violation is observable in a test.

**Given** `will-navigate`, `will-redirect`, `window.open`, `target=_blank` and `setWindowOpenHandler`
**When** a navigation leaves `app://klei/` (including `file:`, `http:`, `https:`, `data:`, `javascript:`, `blob:`)
**Then** it is cancelled, popups are denied, and no URL is passed to `shell.openExternal` from the renderer path.

**Given** permission requests (camera, microphone, geolocation, notifications, clipboard-read, USB and others)
**When** `setPermissionRequestHandler` and `setPermissionCheckHandler` run
**Then** everything is denied, including clipboard; the allow list is an empty fixed array in code. Story 17.6 may add one entry only if its packaged-app test proves the original needs it, and records the proof there.

**Given** a `<webview>`, `<iframe>` to another origin, or `will-attach-webview`
**When** attempted
**Then** it is denied.

**Tasks**
- `electron/src/main/window.ts`: add webPreferences and handlers listed above.
- `electron/src/main/protocol.ts`: `registerSchemesAsPrivileged` (before `ready`), `app://` handler with path confinement.
- `electron/src/main/csp.ts`: the CSP constant and header application (also used by 17.5).
- `electron/test/boundary.test.ts`: webPreferences equality, path confinement table, CSP string equality with `desktop/src-tauri/tauri.conf.json` (read at test time), navigation and popup denial, permission allow list.
- `electron/test/hostile-renderer.test.ts` (shared with 15.4).

**Dev notes**
- Reference only: `desktop/src-tauri/tauri.conf.json` `app.security.csp`, `desktop/index.html`, `desktop/src/platform.ts`.
- The renderer build is produced by 14.4; during development, `electron/build/renderer/` may be a placeholder page. Hash routing means no path rewrite.
- Do not enable `nodeIntegrationInWorker`, `nodeIntegrationInSubFrames`, `enableRemoteModule` or `allowpopups`.
- Do not disable Chromium security features to make a test pass.

**Testing**
- Run `electron/test/boundary.test.ts` (unit) and a real-Electron hostile-renderer run in CI (19.2) once it exists.

**Prototype unchanged check**
- Require the 14.1 gate. Compare that the loaded original renderer's first screen matches the baseline harness capture at 1280×800 and 1100×700, and that no CSP violation is logged on the supported screens.
