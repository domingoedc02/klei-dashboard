# Story 12.2: Frame, tokens and layout primitives

As a Staff member,
I want every screen to sit in one page frame with the prototype's padding and width, and one rule that stops grids from spilling,
So that no screen needs its own fix for the same overflow.

**Assumptions**
- Audit rows G-10, G-16, G-17, G-18, G-28 and root-cause groups A (grid min-content blowout), B (frame and scroll chain), D (dead responsive rules). Foundations come first so 12.5 onward fix screens, not the frame.
- Prototype: `.view` is the only scroller (`css/shell.css:49`) and `.page` carries the padding `var(--space-6) var(--space-8) var(--space-12)` (24 / 32 / 48) with `max-width: 1200px` (`css/shell.css:50`); `.page-head` is a flex row with `gap: var(--space-4)` and `margin-bottom: var(--space-6)` (`css/shell.css:51`). The prototype's `.shell` is a fixed 900px high grid (`css/shell.css:2`), which is a wireframe artefact; the app keeps its own `.app` grid (`desktop/src/styles.css`, not changed here).
- App today: `.sheet` is `padding: var(--space-content-pad)` all round (24px) with `overflow: auto` and no `max-width` (`desktop/src/styles.css:57-60`); `.upload` caps itself at `max-width: 880px` (`styles.css:188`). Banners (`update`, `offline`) render inside `<main className="sheet">` (`desktop/src/shell/Shell.tsx:314-323`) and use a negative top margin (`styles.css:63-65`).
- Tokens come from DESIGN.md through `node infra/ci/gen-tokens.mjs`; never hand-edit `backend/app/src/main/resources/static/tokens.css` (the app imports it at `desktop/src/styles.css:1`). Existing layout tokens: `--space-content-pad: 24px`, `--space-sidebar: 240px`, `--space-topbar: 64px`, `--space-control: 32px`, `--space-sheet-inset: 0px`.
- DESIGN.md wins on polish, so these are **not** changed: focus ring `#0063bf`, meta text `--color-faint #716c66`, info pill ink `#0063bf`, h1 tracking -0.033em, stat figure 32/600, no uppercase eyebrow labels, no "N appointments today" line. `desktop/src/styles.test.ts` locks them and must stay green.
- New layout tokens (add to DESIGN.md frontmatter, then regenerate): `space-page-x: 32px`, `space-page-bottom: 48px`, `container-max: 1200px`. Scrim and motion tokens (G-18): `color-scrim` (`rgb(0 0 0 / 0.35)`, the prototype's value is in `css/base.css`/dialog overlay; the app uses `rgb(20 19 18 / 0.4)` hardcoded at `styles.css:87`), `motion-fast: 150ms`, `motion-base: 200ms`, `ease-standard: cubic-bezier(0.2, 0, 0, 1)` (prototype `index.html` `:root` lines 124-126). `[ASSUMPTION]` keep the app's warm-black scrim hue and only add the token; opacity moves to .35 to match the prototype. If `styles.test.ts` pins the scrim, update the pin in the same change.
- The grid rule (group A): every `grid-template-columns` that uses a bare `1fr` or `repeat(n, 1fr)` inside the sheet becomes `minmax(0, 1fr)`; grid and flex children that hold text get `min-width: 0`. Known instances: `.split` (`styles.css:228`), `.proc-grid` (`styles.css:473`), `.recovery` (`styles.css:~620`), and the stat grid (`styles.css:557`, owned by 12.8). This story only adds the frame and the generic rule; each screen story applies it to its own grid. The generic helper is a one-line utility `.grid-fit { display: grid; min-width: 0; } .grid-fit > * { min-width: 0; }` added under `/* 12.2 */`.
- Dead breakpoints (G-16): the minimum window is 1100px wide (`tauri.conf.json:18-21`), so `@media (max-width: 760px)` (`styles.css:262`), `(max-width: 900px)` (`styles.css:315`, `:347`) and the 960px/other rules at `:482`, `:573` never fire. Delete them and move any layout they carried into the base rule when the stacked form is what the 1100 window needs; the Review rule is Story 12.5's. Where a screen really needs a narrow variant at 1100, add one `@media (max-width: 1180px)` rule inside that screen's story.
- `ErrorBlock` (`desktop/src/shell/ui.tsx:20-28`): `lastGood` is never passed (grep shows no caller), so delete the prop and its `Last updated` line; the Retry control becomes a `.btn` (the prototype uses a button, `K.empty` action). Callers keep working because they pass `what` and `onRetry` only. (G-28)
- Dialog max-height (`styles.css:308`): `calc(100vh - var(--space-8, 48px))` never uses its fallback because `--space-8` is 32px; the intent was 48px. Use `calc(100vh - 3 * var(--space-4))`.
- Banners (G-17): move `update`/`offline` banners out of `<main>` to a row above it, inside `.app`, so the sheet scrolls under them and no negative margin is needed. The `role="alert"`/`role="status"` stay. `Shell.test.tsx` queries by role/text, not by parent, so tests keep passing; check.

**Acceptance Criteria**

**Given** `.sheet` with content
**When** the harness renders any screen at 1280x800
**Then** the sheet has `padding: 24px 32px 48px` and its first child is no wider than 1200px (prototype `css/shell.css:50`), and at 1100x700 the content box is the sheet width minus 64px.

**Given** the Upload screen at 1280x800
**When** the frame ships
**Then** `.upload` is no longer capped at 880px (the page cap of 1200 applies) and the drop zone fills the content width.

**Given** a bare `1fr` grid inside `.sheet` is replaced by `minmax(0, 1fr)`
**When** a child's min-content is wider than its column
**Then** the column stays at its track size and the child truncates or wraps instead of pushing the grid wider. Test: a `styles.test.ts` assertion reads `styles.css` text and fails if a `grid-template-columns` value contains a bare `1fr` or `repeat(N, 1fr)` outside a `minmax(0, 1fr)` (allow-list: `.recovery` until its owner story fixes it).

**Given** the update-ready and offline banners
**When** either shows
**Then** it renders above the scrolling sheet, never inside it, with no negative margin, and the sheet still scrolls fully. Test in `Shell.test.tsx`: `screen.getByRole('status')` is not a descendant of `main#view`.

**Given** the token pipeline
**When** `node infra/ci/gen-tokens.mjs` runs after the DESIGN.md edit
**Then** `tokens.css` contains `--space-page-x`, `--space-page-bottom`, `--container-max`, `--color-scrim`, `--motion-fast`, `--motion-base`, `--ease-standard`, and `styles.css` uses `var(--color-scrim)` for `.scrim` and `var(--motion-base)` for the drawer slide (`styles.css:91`), with no hardcoded `160ms`.

**Given** `prefers-reduced-motion: reduce`
**When** a drawer opens or a skeleton renders
**Then** nothing animates (existing 11.1 behaviour is preserved).

**Given** the dead media queries
**When** the story ships
**Then** `grep -n "max-width: 760px\|max-width: 900px\|max-width: 960px" desktop/src/styles.css` returns nothing, and `styles.test.ts` asserts no `@media (max-width: …)` below 1100px exists.

**Given** `ErrorBlock`
**When** a screen fails to load
**Then** it shows "Couldn't load {what}." and a **Retry** `.btn`; `lastGood` is gone and `tsc --noEmit` passes; existing tests that click "Retry" by role still pass (`getByRole('button', { name: 'Retry' })`; where a test used the `link` class, update it).

**Given** the harness
**When** `node infra/ci/shots.mjs` runs at 1100x700 and 1280x800
**Then** the overflow check (a) passes on every screen except those owned by later stories, which are listed in the Dev record with their story id.

**Given** axe on Shell
**When** `Shell.test.tsx` runs
**Then** zero violations.
