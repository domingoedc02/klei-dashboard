# Story 1.3: Crypto core and Hibernate listener

As an operator,
I want one `CryptoService` and a transparent column mechanism that encrypts every stored value with AES-256-GCM under a wrapped key,
So that feature code never touches a crypto primitive and no plaintext reaches a column.

**Assumptions**
- Listener, not `AttributeConverter` (accepted OQ-4). If the proof AC "listener round trip" cannot pass, stop and ask the user before using the recorded fallback (row id inside the frame, checked in `@PostLoad`).
- Proof tables `crypto_probe` and `crypto_probe_2` exist only in test sources (Flyway test location), never in production migrations.
- Production tables created here: `data_key` only.

**Acceptance Criteria**

**Given** `KLEI_KEK_1`, `KLEI_KEK_ACTIVE=1`, `KLEI_BIDX_KEY`, `KLEI_JWT_KEY` (also as `_FILE`)
**When** the app starts
**Then** `KeyRing` refuses to boot if a key is missing, not 32 bytes, duplicated, or equal to the DB or SMTP password, and the error names the variable only.

**Given** an empty database
**When** the app starts twice concurrently
**Then** exactly one `data_key` row (`generation`, `wrapped_dek`, `kek_version`) exists (insert `ON CONFLICT DO NOTHING`, then re-read) and both instances unwrap the same DEK.

**Given** `CryptoService.encrypt(plain, ColumnRef, rowId)`
**When** called twice with the same input
**Then** the blobs differ (fresh 96-bit random nonce), both decrypt to the input, each has the shape `[version:1][dek_id:16][nonce:12][ciphertext+tag]` and the AAD is `version|dek_id|table|column|rowId`.

**Given** a blob moved to another row id, another column or another table
**When** decrypted
**Then** it fails with `CryptoException(code)` and the message holds neither blob nor AAD.

**Given** plaintexts of 0, 1, 31, 32, 255, 256, 257 and 5,000 bytes
**When** framed and encrypted
**Then** blob lengths fall on the padding steps (32-byte steps to 256, then next power of two) so equal-class values have equal length (AD-3).

**Given** `FieldCodec`
**When** String, Instant, Boolean, Int, Long, enum and a `@Serializable` class with `v` are round-tripped
**Then** each returns an equal value and the canonical forms match architecture §5.2.

**Given** `BlindIndex.of(domain, value)` with `BidxDomain` and `Terms.of`, `DayBucket`
**When** `" Marie  CURIE "` and `"marie curie"` are indexed in one domain
**Then** the hashes are equal; the same value in two domains differs; `Terms.of` follows the rules in §4.2 (split, canon, drop over 64, dedupe, cap 32); a test compares the enum to the table in `docs/architecture.md` §4.2 and fails on any difference.

**Given** an entity with `@EncryptedEntity`, `@Encrypted var name: String` (transient) and `internal var nameCt: ByteArray?`
**When** it is inserted, loaded, updated in one field, and saved unchanged (listener round trip on `crypto_probe`)
**Then** the column holds ciphertext only; load decrypts into `name`; updating one field changes only that column's bytes; an unchanged save changes none; `@BlindIndexed` fills `_bidx` in the same step.

**Given** the schema test
**When** it scans all tables after Flyway
**Then** every column is one of: `id`/`*_id` uuid, `seq`, `version`, `generation`, `*_ct`, `*_bidx`, `wrapped_dek`, `kek_version`, and any other column fails the build (AD-5).

**Given** ArchUnit rules
**When** a repository runs JPQL or native `INSERT`/`UPDATE` on a table with `_ct` or `_bidx` columns outside a `@RawCiphertext` repository, or an entity has `toString()` or data-class equality over decrypted fields
**Then** the build fails (AD-19).

**Given** `ObjectCipher`
**When** a 1 byte, 64 KB and 25 MB buffer are encrypted with AAD `obj|<bucket>|<objectId>`
**Then** bodies decrypt back, lengths pad to 64 KB steps, and a wrong AAD fails.

**Tasks**
- `crypto` module: `KeyRing`, `DekStore`, `CryptoService`, `FieldCodec`, `ObjectCipher`, `BlindIndex`, `BidxDomain`, `Terms`, `DayBucket`, `SecureTokens`, annotations, `EncryptionListener` (PostLoad, PreInsert, PreUpdate, `Interceptor.findDirty`), `MigrationCrypto`.
- `V2__data_key.sql`; test-only probe migrations.
- Schema allowlist test; ArchUnit rules from AD-19.
- `docs/architecture.md` §4.2 table is the oracle for the enum test.

**Checks**
- `cd backend && ./mvnw verify`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (backend boots with generated keys).
- Desktop tests: not applicable yet.
- NFR-1: this story is the proof; the AC set above is the review checklist.

## Dev record

**Result.** `cd backend && ./mvnw verify` green (crypto 35, app unit 11, app IT 18). `infra/ci/smoke.sh` PASS on rebuilt stack; smoke now also asserts one wrapped `data_key` row (generation 1, KEK 1, 60 bytes).

**Deviations**
- Listener is a Hibernate `Interceptor` (`onLoad`, `onPersist`, `findDirty`) registered via `hibernate.session_factory.interceptor`, not JPA `@PostLoad`/`@PreUpdate`. Round trip passed, so the AttributeConverter fallback was not used.
- `@BlindIndexed` sits on the `*Bidx` field, not the plaintext field.
- New problem code `crypto_failure` (500) for any `CryptoException`; log holds the code only.
- ArchUnit AD-19 rules use `allowEmptyShould(true)` until Story 1.4 adds production entities and `@Query` methods; negative fixtures prove they bite.
- Crypto self-test and DEK load run in an `ApplicationRunner` after Flyway.

**Risk.** Interceptor mutates Hibernate state arrays; a Hibernate upgrade must re-run `ListenerRoundTripIT`. Rotation (`KeyRotation.rewrapBatch`) is unit-level only; no operator job yet.
