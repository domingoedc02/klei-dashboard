# Story 8.2: Global search

As a signed-in User,
I want to type a word in the top bar and jump to a matching gown or inquiry,
So that I can find things without browsing.

**Assumptions**
- Whole-word, case-insensitive match only (accepted at Gate 2). No prefix, substring or fuzzy match. The popover helper reads "Search matches whole words."
- `Terms.of(q)` is the only tokenizer; all words must match (`count(DISTINCT term_bidx) = n`). More than 8 words are cut at 8 `[ASSUMPTION]`.
- Gown terms come from name, Silhouette and Fabric (Stories 4.7 and 5.3); Inquiry terms from Client name and subject (7.1).
- Search is `POST /search {q}` because a search term is business text and must stay out of URLs.
- Gowns need `PERM_VIEW_GALLERY`; Inquiries need `PERM_REPLY`. A caller with neither gets 403 `forbidden`; with one, only that kind.
- Debounce 200 ms; a request older than the latest is dropped.

**Acceptance Criteria**

**Given** `POST /search {q}`
**When** called with `PERM_VIEW_GALLERY` or `PERM_REPLY`
**Then** it tokenizes with `Terms.of`, hashes each word with `BlindIndex.of(GOWN_TERM|INQUIRY_TERM)`, runs one grouped query per kind, returns at most 6 results in total (Gowns first, then Inquiries), decrypts only those rows, and never puts the term into SQL text or logs; a query with no word characters returns an empty list.

**Given** a caller without `PERM_REPLY`
**When** the query matches Inquiries
**Then** no Inquiry result is returned, and the response shape is unchanged.

**Given** the search box (X2)
**When** Cmd/Ctrl+K or `/` is pressed outside an input
**Then** the box focuses; typing opens a popover with results grouped Gowns then Inquiries, Gown rows (mosaic, name, "Silhouette, Fabric") and Inquiry rows (client, subject); arrow keys move, Enter opens, Esc closes.

**Given** a result is chosen
**When** it is a Gown
**Then** the viewer opens (G2); when it is an Inquiry, I1 opens with that thread selected.

**Given** no match
**When** the popover shows
**Then** it reads "No results for “{q}”" with **Clear search**; loading shows three skeleton rows; a failed request shows "Search is unavailable. Try again."

**Given** a Gown renamed in Story 5.3 or a Taxonomy value renamed
**When** searched afterwards
**Then** the new word matches and the old word does not (integration test).

**Given** the search with 5,000 Gowns (AR-22 seed from Story 9.4)
**When** the benchmark runs
**Then** p95 meets the PRD NFR-2 target; this story adds the query shape and index and a 500-row index-use test.

**Given** the leak suite
**When** extended
**Then** a Sentinel search term leaves no plaintext in logs, the access log or the URL, and `term_bidx` values are envelopes of the right shape.

**Tasks**
- Backend: `SearchController`, `SearchService`, `V17__term_indexes.sql` (indexes on `term_bidx`), tests.
- Desktop: search box and popover, keyboard handling, result navigation, tests, axe.

## Dev record

**Assumptions**
- No new migration: `gown_term` (V14) and `inquiry_term` (V17) already index `term_bidx`. The Tasks line above says `V17__term_indexes.sql`; not needed.
- `q` is at most 200 chars and 8 words (cut, not refused); missing `q` is 422 `q` `required`; punctuation only is 200 with an empty list.
- 6 results in total, Gowns first. Inquiry hit: title = Client name, subtitle = subject. Gown hit: title = name, subtitle "Silhouette, Fabric", up to 4 thumbnail ids.
