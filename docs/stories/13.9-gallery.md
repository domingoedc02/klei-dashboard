# Story 13.9: Gallery

As a Staff member,
I want the Gallery grid, filters, bulk bar and empty states to match the prototype,
So that finding and selecting gowns looks and works like the design.

**Assumptions**
- Prototype: `js/gallery.js`, `css/screens.css` `.gcard`, `.mosaic`, `.bulk`, `.filters`; pairs `gallery-{default,loading,empty,no-match,selected,delete-dialog}`. Desktop: `desktop/src/gallery/*.tsx`.
- GL-01 is the P1: the card is a bordered `.card` (padding 12) with an inset 2x2 mosaic tile of about 250 px and the text inside the card, not a borderless full-bleed 366 px portrait mosaic with text below.
- Dates (GL-02) use the 13.3 formatter (D1 assumption (a)): `Nov 6, 2026`.
- GL-03: Sort is an inert prototype control (disabled chip). Keep the desktop's real behaviour if sort exists; otherwise render the prototype's disabled chip. Check `Gallery.tsx` first and record which.
- GL-12: facets are joined with a comma (`Mermaid · Tulle, Lace`).
- `viewer-loading` and the desktop `gallery` states not in the prototype are judged against DESIGN.md.

**Acceptance Criteria**

**Given** a gown card (GL-01, GL-08, GL-12)
**When** the grid renders
**Then** the card is bordered with padding 12, an inset 2x2 mosaic (about 250 px), the text inside the card, the `New` pill solid accent blue with white text inset 20 px, and facets read `Mermaid · Tulle, Lace`

**Given** the filter row (GL-03, GL-04, GL-05, GL-06)
**When** it renders
**Then** labels are muted, options read `All silhouettes` / `All fabrics`, Sort shows as in the prototype, `Clear filters` is a ghost button shown only while a filter is active, and the header `Upload photos` button carries the upload icon

**Given** cards are selected (GL-07, GL-13)
**When** the bulk bar shows
**Then** the bar has the grey surface fill, 1 px border and radius-lg; a selected card has a 2 px accent ring around the whole card and a 20 px checkbox inset top-left

**Given** loading (GL-09)
**When** the grid is pending
**Then** eight bordered cards with a square tile and 60 % / 40 % text bars

**Given** empty and no-match (GL-10, GL-11)
**When** they render
**Then** empty shows the subtitle "No gowns saved yet", keeps the header Upload button, has no filter row and an `h2` at `text-xl`; no-match uses the same empty block with a primary `Clear filters`

**Given** a card date (GL-02)
**When** it renders
**Then** it reads `Nov 6, 2026` (D1 assumption (a))

**Given** the story's screens are captured on both sides
**When** `node scripts/capture.mjs --side both --only {only}` and `npm run shots:diff -- --only {only}` run
**Then** `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `dialog-scroll` or `dialog-overflow` for the desktop side of these screens (`text-ellipsis` only where the prototype truncates the same text), and the run logs no `UNMOCKED` request and no page or console error

**Given** every audit row listed above
**When** the story is done
**Then** the row's Status in `docs/planning-artifacts/ui-parity/audit.md` is `closed` with the fix commit and the after-screenshot path, or the row says `accepted deviation` with the decision it follows (D1 to D5 in the change proposal) and the reason

**Given** each prototype/desktop pair of the story
**When** the lead reads the montage in `ui-parity/diff/`
**Then** the Dev record has one line per pair: `match`, or the remaining difference and why it is fixture-only noise (SVG gown art, fixed clock, mock data). Pixel % is recorded in the Dev record as a trend and is not a gate
