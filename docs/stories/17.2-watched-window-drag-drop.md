# Story 17.2: Watched-window drag and drop

As a Staff member on AI Upload, I want native window drops to identify files without exposing paths to the renderer, so that I can add photos safely and see the same drag feedback.

**Assumptions**
- Electron main owns `Uploader`-equivalent state and only forwards drop information while the Upload screen has an active watch.
- Electron has no inbound native file-drop window event like Tauri's `DragDropEvent`. Chromium delivers drops as DOM `dragenter`/`dragleave`/`dragover`/`drop` events; `webUtils.getPathForFile(File)` is the documented way to obtain a path from a dropped `File` and is callable only in preload. The original renderer has no HTML5 drop handlers (inventory), so preload attaches its own listeners in the isolated world. Original renderer code never sees the `DataTransfer` files, paths or names.
- Preload always calls `preventDefault` on file drags (as Tauri's native handler swallowed them) so Chromium never navigates to a dropped file; main additionally denies navigation (15.2).
- Preload sends paths to main on a private channel, validated against the trusted frame (15.4); only counts and drag state flow back to the renderer-visible bridge.

**Acceptance Criteria**

**Given** Upload calls `watch`
**When** files enter, leave or are dropped on the app window
**Then** the renderer receives `{type:'drag',over:true|false}` and `{type:'dropped',count:N}`; no file path, name or byte reaches renderer IPC.

**Given** no active watch
**When** a native drop occurs
**Then** paths and pending drop state are discarded and no event is sent.

**Given** an active watch and a native drop
**When** Upload calls `dropped` within 10 seconds
**Then** main consumes those paths exactly once; after `DROP_TTL` (10 seconds) the paths expire and are not uploaded.

**Given** Upload calls `unwatch`
**When** a drop is pending
**Then** watcher and pending paths are cleared; later drop events are ignored until a new watch.

**Tasks**
- `electron/src/preload/drop.ts`: capture DOM `dragenter`/`dragleave`/`dragover`/`drop` on `window` for file drags only (`dataTransfer.types` contains `Files`); always `preventDefault`; map `File` to path with `webUtils.getPathForFile`; send `{over}` and `{paths}` to main on private channels never exposed through `contextBridge`.
- `electron/src/main/uploads.ts`: implement watch, unwatch, drag notification, one-shot drop claim and 10-second TTL; accept private drop messages only from the trusted main frame (`senderFrame` check from `electron/src/main/ipc.ts`).
- `electron/src/preload/bridge.ts`: expose typed watch/unwatch and count/over events only.
- `electron/test/drop.test.ts`: verify watch gating, one-time claim, 10-second expiry, unwatch clearing, untrusted-sender rejection and path non-disclosure.
- Packaged-app runtime check (per OS, recorded in 20.1): real file drag from the OS file manager reaches `dropped` with correct count; sub-frame or non-file drags are ignored.

**Dev notes**
- Port Rust `desktop/src-tauri/src/uploads.rs::{Uploader::watch,Uploader::unwatch,Uploader::drag,Uploader::drop_files,Uploader::take_drop}`. The trigger differs: Tauri receives `WindowEvent::DragDrop` in `desktop/src-tauri/src/lib.rs::run`; Electron derives the same Enter/Leave/Drop from DOM events in preload. Documented difference, not parity claimed until the packaged check passes. Electron docs: `webUtils.getPathForFile`.
- Rust behavior to keep: a drop with no watcher is discarded (`drop_files` returns early); `take_drop` yields paths once and only while `elapsed < DROP_TTL`.
- Behavior spec: `desktop/src-tauri/src/uploads_tests.rs::a_drop_nobody_watches_is_forgotten`; Rust has no explicit TTL-expiry test, so add a deterministic Electron clock test for the 10-second contract.
- Target files are planned under `electron/`; do not alter `desktop/src/upload/Upload.tsx` or `desktop/src-tauri/`.

**Testing**
- Run `electron/test/drop.test.ts`; assert exact event payloads, one claim only, expiration at the 10-second boundary and absence of file paths in renderer-visible messages.
- Verify unmounting the Upload view calls unwatch and prevents subsequent upload from stale pending paths.
