# Story 16.1: Runtime configuration and `api_request`

As a signed-in User, I want every screen's API call to go through main with the same path rules, headers and timeouts, so that screens behave as they do in the Tauri app.

**Assumptions**
- Backend and Auth Web URLs are build-time constants (architecture §2, FR-6). Electron reads `KLEI_API_URL` and `KLEI_AUTH_URL` at build time into a generated constant, defaults `http://127.0.0.1:8080` and `http://127.0.0.1:8081` for development only, with a trailing `/` stripped. A packaged build without them fails the build.
- Timeouts (from `desktop/src-tauri/src/config.rs` and `session.rs`): request 10 s; upload 120 s; sign-in 300 s; retry delay 3 s; slow paths `/api/v1/admin/ai/test` and `/api/v1/admin/ai/models` 200 s.
- HTTP uses Node's built-in `fetch` (Undici) with `redirect: 'manual'`, with an `AbortSignal.timeout`. No new dependency is introduced for HTTP.

**Acceptance Criteria**

**Given** a call `{ method, path, body, ifMatch, idempotencyKey }`
**When** `method` (case-insensitively) is not GET, POST, PUT, PATCH or DELETE
**Then** it fails `bad_request` "method not allowed" and no request is sent.

**Given** a `path`
**When** it does not start with `/api/v1/`, contains `..` or `//`, contains a byte outside 0x21–0x7E, or contains `\`
**Then** it fails `bad_request` "path must stay under /api/v1/", and no request is sent. The one exception is `/health/ready`, which must be GET (otherwise `bad_request`), sends no token, needs no sign-in, and is not retried.

**Given** `ifMatch` is a non-negative integer
**When** the call is sent
**Then** header `If-Match` carries its decimal digits and nothing else can ride along; a non-integer is `bad_request`.

**Given** `idempotencyKey`
**When** it is longer than 128 bytes or contains a byte outside 0x21–0x7E
**Then** it fails `bad_request` "bad idempotency key"; a clean key goes out as `Idempotency-Key` on JSON calls only.

**Given** `body` is `null` or absent
**When** the call is sent
**Then** no body or content-type is sent; otherwise the body is JSON.

**Given** the server answers
**When** the body parses as JSON
**Then** the renderer receives `{ status, body, refreshed }`; a non-JSON or empty body gives `body: null`; non-2xx statuses are returned as data, not thrown (existing screens read them).

**Given** a network failure
**When** the request times out, cannot connect, or fails otherwise
**Then** the error kind is `timeout`, `offline` or `failed`, with the Rust messages "request timed out", "server unreachable", "request failed".

**Given** a redirect response (3xx)
**When** received
**Then** it is not followed; the status is returned as data.
