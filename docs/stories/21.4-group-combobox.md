# Story 21.4: Group combobox with photo counts (Move, Merge)

As a Staff member with a batch of 26 gowns,
I want to type part of a gown's name and pick it from a filtered list that shows how many photos it holds,
So that I do not scroll a 25-item native dropdown to find the right group.

**Assumptions**
- Reported (screenshot 4): the native dropdown for "Move selected photos to" lists every gown with no search and no counts.
- **Reverses story 13.8's accepted deviation** (UR-15: "native `select` instead of the prototype combobox", help copy "Choose a gown."). Reopen UR-15 and close it again with this story. The prototype combobox (`js/upload.js` 97-132, `.combo`) is the visual reference; `upload-review-combo-open` must now show an open list.
- Applies to the two group pickers only: "Move selected photos to" (`mvto`) and "Merge this whole gown into" (`mgto`). The tag selects (`#g-{type}`) stay native.
- No new dependency. Reuse the ARIA combobox pattern of `desktop/src/shell/SearchBox.tsx` (`aria-autocomplete="list"`, `aria-controls`, `aria-activedescendant`, `role="option"`, `aria-selected`, ArrowDown wrap, `sr-only role="status"` count) and the `.search-pop` / `.search-hit` CSS as the starting point. Build one small `GroupCombobox` in `desktop/src/upload/`; do not generalise beyond these two uses.
- Option text: `{name} · {plural(photoCount, 'photo', 'photos')}`, e.g. "Lace Corset Overskirt Gown · 4 photos"; "1 photo" is singular (`plural` in `Review.tsx` line 27).
- Candidates: every group except the current one (same set the native select shows today via `others`). Filtering: case-insensitive substring on the name, trimmed; empty input lists all. Count shown is the group's live count (`photoIds.length`), so it updates after Move and after Undo.
- Existing state kept: `mvto` / `mgto` hold the chosen group id; cleared after an op (`setMvto('')`, `setMgto('')`); focus parks on `#g-photos` after an op; `locked` gating; the Move/Merge/Split enable rules from 13.8.
- Stale selection: if the chosen group disappears (merged, discarded, Undo), the picker clears.

**Acceptance Criteria**

**Given** the Organize panel
**When** it renders
**Then** "Move selected photos to" and "Merge this whole gown into" each have a text input (`role="combobox"`, label via `htmlFor`, help via `aria-describedby`) with a Move or Merge button as today; the labels and help lines are unchanged except "Choose a gown." becomes "Type a gown name to search."

**Given** the input
**When** the user focuses it and presses ArrowDown, or types
**Then** a listbox opens (`role="listbox"`, `aria-expanded="true"`, `aria-controls` points to it); every option is `role="option"` with the text "{name} · {N photos}"; the list scrolls inside its own max-height and is not clipped by the editor pane

**Given** the user types "lace"
**When** the list filters
**Then** only gowns whose name contains "lace" (any case) remain, in the original order, with counts; matching is by name only; a polite `sr-only role="status"` line reads "N gowns match" (or "No gown matches")

**Given** no match
**When** the list renders
**Then** it shows a non-selectable "No gown matches" row and the Move/Merge button stays disabled

**Given** the list is open
**When** the user presses ArrowDown or ArrowUp
**Then** the active option moves with wrap, `aria-activedescendant` follows, the option has `aria-selected="true"`, and DOM focus stays in the input; Home/End are left to the input

**Given** an active option
**When** the user presses Enter or clicks it
**Then** the group is chosen, the input shows its name, the list closes, and the Move or Merge button becomes enabled (subject to the existing rules: Move needs at least one selected photo and a target); Enter with no active option and an exact (case-insensitive) single name match chooses that match; otherwise it does nothing

**Given** the list is open
**When** the user presses Esc
**Then** the list closes, the input keeps its text, focus stays in the input, and the Shell/dialog Esc handler does not fire (`stopPropagation`); Tab closes the list and moves on; blur or an outside click closes it

**Given** a target is chosen and the user edits the text
**When** the text no longer equals the chosen group's name
**Then** the choice is cleared and the button is disabled again

**Given** a Move or Merge succeeds, or Undo runs
**When** the panel re-renders
**Then** the input is empty, the list is closed, counts in any reopened list reflect the new totals, and focus handling stays as today (parks on `#g-photos`)

**Given** `locked` (a rewrite or save is running)
**When** the panel renders
**Then** both inputs and buttons are disabled (the native `select:disabled` look is kept via `.org input:disabled`)

**Given** pointer and touch use
**When** the user clicks an option
**Then** it is chosen on `mousedown`/click without the input blurring first and closing the list early (`onMouseDown preventDefault` on options)

**Given** widths 1440x900 and 1100x700
**When** the Organize panel renders
**Then** the input fills `.org-ctl` next to its button, the list is as wide as the input, long names truncate with ellipsis in the option row but the full name is in `title`, and the list does not go off-screen (it flips above the input when there is no room below, or its max-height keeps it inside the pane)

**Given** `axe.run` on Review with the list closed, open with a filter, and with no match
**When** it runs
**Then** zero violations

**Given** the story's screens are captured on both sides
**When** `node scripts/capture.mjs --side both --only upload-review` and `npm run shots:diff -- --only upload-review` run
**Then** `upload-review-combo-open` shows the open list with counts; `geometry.json` shows no `overlap`, `covered`, `glued-text`, `text-clipped`, `offscreen-x`, `page-h-scroll`, `frame-scroll`, `dialog-scroll` or `dialog-overflow` for the desktop side (`text-ellipsis` only where the prototype truncates the same text), and the run logs no `UNMOCKED` request and no page or console error
