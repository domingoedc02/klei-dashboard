# Story 4.6: Rearrange Photos

As a Staff member,
I want to move, split, merge and discard photos,
So that every group holds exactly one gown.

**Assumptions**
- Reversible until Save (FR-11) is met by keeping every change in the database and by an Undo toast for the last action: Undo is a client-side inverse call (move back, re-merge by split of the saved id set), not a server history. Discarded Photos are soft-removed (`discarded` flag in `photo.state_ct`) and their objects are deleted only at Save or Discard batch (Story 4.7). `[ASSUMPTION]`
- A Group left with zero Photos is removed in the same transaction. The target Group's name and attributes win on merge.
- Embeddings stay in place while rearranging; no re-grouping runs.
- Moves use a menu, not drag-and-drop (UX U1 menus). Drag-and-drop is out.

**Acceptance Criteria**

**Given** a Photo menu
**When** **Move to…** is chosen
**Then** a picker lists the other Groups plus "New gown"; `POST /uploads/{id}/photos/{pid}/move {groupId|null}` moves it, creates a Group named "New group" for null, removes the source Group if empty, and the toast reads "Photo moved. Undo."

**Given** selected Photos in a Group
**When** **Split into new gown** is chosen
**Then** `POST /uploads/{id}/groups/{gid}/split {photoIds}` creates a new Group with those Photos (a split of all Photos is refused with 422), and the new Group is selected.

**Given** a Group menu
**When** **Merge into…** is chosen
**Then** `POST /uploads/{id}/merge {sourceId, targetId}` moves all Photos to the target, keeps the target's name and attributes, removes the source, and the toast reads "Groups merged. Undo."

**Given** **Discard photo**
**When** chosen
**Then** the Photo is marked discarded and hidden, the Group count updates, a Group with no Photos disappears, and the toast reads "Photo discarded. Undo."; the object is not deleted yet.

**Given** Undo within 8 seconds
**When** pressed
**Then** the inverse is applied and the earlier layout returns; after the toast ends, Undo is gone but the user can still move a Photo back by hand.

**Given** concurrent edits
**When** a stale `If-Match` arrives
**Then** 409 `conflict` and the screen reloads the batch.

**Given** another User's batch id
**When** any rearrange endpoint is called
**Then** 404.

**Given** the leak suite
**When** extended
**Then** nothing new appears in plaintext (`state_ct` is an envelope).

**Tasks**
- Backend: `RearrangeService` (move, split, merge, discard), `V11__photo_state.sql`, rules for empty-Group removal.
- Desktop: Photo menu, picker dialog, Group menu, Undo toast action, tests, axe.

**Checks**
- `cd backend && ./mvnw verify` (tests for empty-Group removal, merge naming, split refusal)
- `cd desktop && npm test && (cd src-tauri && cargo test)`
- `docker compose -f infra/docker-compose.yml --profile dev up -d --wait && infra/ci/smoke.sh` (extend: move one photo, groups 3 to 3 or fewer as expected).

## Dev record

**Assumptions**
- Migration is `V13__photo_state.sql` (V11 was taken); `photo.state_ct` is a nullable envelope holding `discarded`, null while the Photo is shown.
- A Group made by Move-to-new or Split is named "New group", confidence 70 (Low band, so it asks for a look), last position. The wireframe used 70 for splits.
- `If-Match` is the version of the Group the Photos leave (move, split, discard, merge source). Restore needs none because it only adds a Photo. A stale version, a batch not in review or a vanished Group reloads the batch on the screen.
- Undo is client-side inverse calls; each answer lists every Group again with a `focus` id. Undo of a merge is a split with a seed (name, tags, description) so the source returns with its text but a new id; Undo of the last-photo discard or move restores into a new Group with the old text for the same reason.
- Discarded Photos stay in the database and the object store until Save or Discard batch (Story 4.7 must delete their objects). They are hidden from `GET /uploads/current`, the status groups, and the group edit answers; their thumbnails stay readable by id.
- The photo `⋯` button sits on each thumbnail in the editor grid; the group menu has one item, Merge into…. Selecting several photos for Split is not built: Split moves the one photo whose menu was used (the endpoint takes a list). `[ASSUMPTION]`

**Done**
