# Story 11.12: Away message and closure schedule

As an Admin,
I want to set a message that goes to people who write in while the studio is closed, and say when the studio is closed,
So that clients hear from us at once even when nobody is at the desk.

**Assumptions**
- Reinstates FR-32, which was `DEFERRED` at Gate 3 and not rendered (`ux-spec.md` lines 154, 164, 232). The user chose "build all, full stack" on 2026-11-10; PRD FR-32 and ux-spec are edited by this story.
- AW-1 CONFIRMED by the user (2026-11-10): this feature emails real clients automatically. The PRD listed automatic sending to clients as a NON-GOAL (no public intake, every reply is a Staff action); that rule is lifted for this one message. One away message per client per closure window, sent through `MailPort` as a new template `AWAY`, only to a client who just created an inquiry; never in reply to a reply.
- The business time zone is a studio setting. `[ASSUMPTION]` it is the Admin's own preference time zone from Preferences (Story 6.3); if unset, UTC. OPEN QUESTION (AW-2): a studio-wide zone setting instead. Default: Admin's zone.
- Schedule modes (prototype, `settings.js`): **once** (first day, optional last day, whole days), **weekly** (chosen days, all day), **daily** (closes at, reopens at; may wrap midnight). Summary strings as in the prototype.
- One row, one Admin editor. No per-user away messages.
- "Required message" when the switch is on (prototype).
- The away mail body is plain text, no client data other than the greeting "Hi {first name}", sent from the studio address; it is the only variable besides `body` and `signature`.

**Acceptance Criteria**

**Given** Settings › Admin › (placement per the prototype: an Admin card on the Preferences-side of the admin area, "Away message")
**When** an Admin opens it
**Then** a switch **Send away message** reads "Off. Turn on when the studio is closed." or "On. {summary}", a required **Message** field, and the fieldset "When is the business off?" with three radio cards (once, weekly, daily) appear, with the prototype's labels, helper texts and error strings ("Pick the first day closed.", "The last day can’t be before the first day.", "Pick at least one day.", "Closing and reopening times must differ.").

**Given** a valid schedule
**When** it changes
**Then** the live summary updates: "Closed {date}[ to {date}]. Happens once.", "Closed every {days}, all day.", or "Closed every day from {time} until {time}.", and **Save** shows "Away message saved".

**Given** the switch is on and the message is empty
**When** Save is pressed
**Then** the field shows "Enter the message to send." and nothing is saved.

**Given** `GET`/`PUT /api/v1/admin/away` (permission `PERM_AWAY`, Admin by default; migration `V23__away_message.sql`)
**When** called
**Then** it stores `{enabled, message, schedule}` with `message_ct` encrypted, validates the schedule server-side with the same rules, returns the `version`, uses `If-Match`, returns 409 on a stale write, writes an `AWAY_CHANGED` audit entry, and rejects a Viewer or Staff caller with 403.

**Given** the feature is on
**When** a new inquiry arrives inside a closure window and its client has not had an away mail in this window
**Then** one mail from template `AWAY` goes to the client's address; a second inquiry in the same window sends nothing; an inquiry outside the window sends nothing; the send is recorded (`away_sent` with client id and window start) so a restart does not repeat it.

**Given** a send failure
**When** the mail server refuses
**Then** it is logged by class name only, the inquiry is still created, and no retry loop runs.

**Given** the mail template
**When** tested
**Then** `MailTemplateTest` shows `AWAY` carries only `body` and `first`; a leak test proves no email, id or inquiry text appears in its output beyond the greeting, and the model is refused if it holds any other key.

**Given** the leak suite
**When** extended
**Then** `away.message_ct` holds only an envelope and `away_sent` holds ids, not addresses.
