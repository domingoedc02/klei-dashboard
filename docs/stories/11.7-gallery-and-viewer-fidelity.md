# Story 11.7: Gallery, viewer and edit gown match the prototype

As a Staff member,
I want the Gallery, the gown viewer and the edit dialog to look and read like the approved prototype,
So that what I was shown is what I get.

**Assumptions**
- Prototype wins. The PRD already calls a saved gown a "folder" in the UI; the desktop says "gown" in dialogs and toasts. Copy changes to "folder".
- Paging stays (`fetchPage`, `.pager` in `Gallery.tsx`): the prototype loads everything, the API pages. Desktop-only behaviour is kept.
- The grid becomes 4 fixed columns at the prototype's content width (gap 16). `[ASSUMPTION]` below 960 px it falls back to `auto-fill` so narrow windows do not break.
- First task: confirm the rows the diff marked **verify** (filters option set, bulk bar, selection ring, empty copy, header subtitle, viewer stage size, "Copy description") against `Gallery.tsx`, `Viewer.tsx`, `EditGown.tsx` and `prototype/v0.1.0/js/gallery.js`. Record the confirmed list in the Dev record.
- Needs Story 11.1 tokens and icons.

**Acceptance Criteria**

**Given** the Gallery
**When** it renders
**Then** the header reads "Gallery" with the line "{n} of {total} gowns · latest upload first" and a primary **Upload photos** button; filters are Silhouette, Fabric, Date added (All time, Last 7 days, Last 30 days, Last 90 days), a sort chip "Latest upload first", and **Clear filters**.

**Given** gown cards
**When** they render
**Then** each card shows a 2x2 mosaic (gap 2, radius 8), the name, "Silhouette · Fabric", "{n} photos · {date}", a "New" pill for recent folders, and an always-visible 24 px checkbox that draws a 2 px accent ring when selected.

**Given** one or more cards selected
**When** the bulk bar shows
**Then** it reads "Select all" / "None selected" / "{n} selected", with **Download .zip** and **Delete**.

**Given** the delete confirmation (bulk or from the viewer)
**When** it opens
**Then** the title reads "Delete {n} folder(s)?" (viewer: "Delete “{name}”?"), the body "This removes {names} and {m} photos from Gallery. This can’t be undone." (viewer: "This removes the folder and its {n} photos from Gallery. This can’t be undone."), the confirm button "Delete {n} folder(s)" (viewer: "Delete folder"), and the toast "{n} folder(s) deleted" ("Folder deleted"); the existing limit `MAX_DELETE` and error toasts stay.

**Given** the viewer
**When** it renders
**Then** the header row shows **Edit**, **Download .zip**, **Copy description** and **Delete folder** as secondary buttons (not in a menu), the crumbs read "Gallery › {name}", the details list uses a 96 px label column (Silhouette, Fabric, Neckline, Sleeve, Train, Photos, Added) above a "Description" heading, and Copy description writes the description to the clipboard with the toast "Description copied".

**Given** the Edit dialog
**When** saved
**Then** the toast reads "Gown updated"; an empty name keeps the dialog open with "Name is required"; the dirty guard ("Your edits to this gown will be lost." / "Keep editing" / "Discard") and the 409 behaviour are unchanged.

**Given** the empty states
**When** the Gallery has no gowns
**Then** it shows art, "Your gallery is empty", "Saved gowns appear here as albums, newest first." and **Upload photos**; with filters and no match it shows "No gowns match these filters", "Try a different silhouette, fabric, or date range." and **Clear filters**.

**Given** loading
**When** the Gallery loads
**Then** 8 card skeletons show (shimmer from Story 11.1).

**Given** the axe run
**When** it covers Gallery, viewer and both dialogs
**Then** it reports no serious or critical issues.
