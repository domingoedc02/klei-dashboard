# Story 10.1: Grouping evaluation harness

As the operator,
I want to run the real clustering code over a folder of gowns I have labelled,
So that I can see precision and recall per sensitivity and tune grouping with numbers instead of guesses.

**Assumptions**
- No model training (user rule). This story measures; it changes no production behaviour.
- Operator-run only. Not a CI gate, not part of the default `./mvnw verify` result. The key lives in the operator's shell environment, never in the repo, and a Dev agent never asks for it.
- Input folder layout: `<gown-label>/<photo>.jpg|png|webp`. The folder name is the ground-truth label. Photos of the same gown share a folder.
- `[ASSUMPTION]` The script resizes to a 480 px JPEG with Pillow. This differs slightly from `ThumbnailService`; it is good enough to rank thresholds and is stated in the script header. Upgrade path: call the backend thumbnail endpoint.
- Embeddings come from the same endpoint shape as production: `POST {base}/v1/embeddings` (`/embeddings` when the base ends in `/v1`) with `input` = `data:image/jpeg;base64,...`. This also exercises S-1 on the real provider.
- Metrics are pairwise: a pair of photos is a true pair when both share a label, a predicted pair when both land in one cluster. Precision = TP / predicted pairs, recall = TP / true pairs, F1 as usual.
- The embedding model and the LLM keep separate URLs and keys (operator ruling 2026-11-10), so the script reads only the embeddings address and key (`KLEI_EMBED_URL`, `KLEI_EMBED_KEY`) and never the chat gateway's. The same harness lets the operator compare embedding models by changing `KLEI_EMBED_MODEL` (this answers "second embedding model" without building it).

**Acceptance Criteria**

**Given** a folder of labelled gowns and `KLEI_EMBED_URL`, `KLEI_EMBED_KEY`, `KLEI_EMBED_MODEL` set
**When** `infra/eval/embed.py <folder> vectors.json` runs
**Then** it writes one JSON file holding `{model, dim, items:[{label, file, vector}]}`, never writes the key, and exits non-zero with a one-line message when a variable is missing, the folder has fewer than two labels, or any provider call fails.

**Given** a `vectors.json`
**When** `./mvnw -pl app -am test -Dtest=GroupingEvalTest -Deval.vectors=/path/vectors.json` runs
**Then** it runs the real `Clusterer.cluster` once per sensitivity 1 to 5 using `Clusterer.threshold(s)` and prints one table with: sensitivity, threshold, groups found vs labels, pair precision, pair recall, F1, and for each confidence band (high, medium, low) the number of groups and the share that hold photos of one label only.

**Given** `-Deval.vectors` is not set
**When** `./mvnw verify` runs
**Then** `GroupingEvalTest` is skipped (JUnit assumption) and the build result is unchanged.

**Given** the metric functions
**When** `GroupingMetricsTest` runs on hand-made vectors
**Then** a perfect clustering gives precision 1.0 and recall 1.0, an over-merged one (two labels in one cluster) gives precision below 1.0 and recall 1.0, an over-split one gives precision 1.0 and recall below 1.0, and a folder with all singletons gives recall 0.0 without dividing by zero.

**Given** the printed report
**When** the operator reads the row for the default sensitivity
**Then** the report states how many groups were "pure" (one label) at High confidence, which is the number that shows the reported bug.

**Given** the leak suite
**When** extended
**Then** `vectors.json` is outside the repo by default (`--out` path required, no default inside the working tree) and `.gitignore` lists `*.vectors.json`, so no operator photos or vectors are committed.

**Tasks**
- `infra/eval/embed.py` (run with `uv run`, stdlib plus Pillow, header states the usage and the shortcut above).
- `backend/app/src/test/kotlin/co/klei/app/upload/GroupingMetrics.kt` (pure functions: `pairs`, `precisionRecall`, `purity`) and `GroupingMetricsTest.kt`.
- `backend/app/src/test/kotlin/co/klei/app/upload/GroupingEvalTest.kt` (skipped without `-Deval.vectors`; reads JSON with the Jackson already on the test classpath).
- `.gitignore` entry; one paragraph in `docs/ops.md` "Tuning grouping with your own photos".

**Checks**
- `cd backend && ./mvnw verify` (new metrics unit test passes, eval test skipped)
- `cd backend && ./mvnw -pl app -am test -Dtest=GroupingMetricsTest`
- Manual, operator only: run `embed.py` on a folder of at least 5 known gowns with at least 3 photos each, then `GroupingEvalTest`; paste the table into this story's Dev record.
