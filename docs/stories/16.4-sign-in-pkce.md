# Story 16.4: `sign_in` with PKCE

As a User, I want Sign in to open my system browser and bring me back signed in, so that my password is never typed into the app.

**Assumptions**
- Flow (from `session.rs::sign_in`): create PKCE verifier and challenge, create state, open `{AUTH}/authorize?client=desktop&challenge=…&state=…&redirect=…` in the system browser, wait up to 300 s for the callback, exchange `{ code, verifier }` at `POST /api/v1/auth/token`.
- Redirect is `klei://auth/callback` in the Tauri app. The Electron preview uses the **loopback** redirect `http://127.0.0.1:<port>/callback` (AD-27, OQ-M4), implemented in 16.5. This story is complete with a callback injection point so that 16.5 plugs in.
- The backend accepts exactly `klei://auth/callback` or `http://127.0.0.1:<port>/callback` with port 1024 to 65535 (`backend/app/src/main/kotlin/co/klei/app/auth/AuthCodeStore.kt::RedirectUri.valid`, read only). The loopback listener must therefore bind a port in that range, not an arbitrary one; if the OS picks a lower port, retry the bind.
- Opening the browser uses `shell.openExternal` from main with the URL main built, never a renderer value.

**Acceptance Criteria**

**Given** `sign_in`
**When** invoked
**Then** it first checks that the credential store is usable (`load` succeeds), else `keychain_unavailable`.

**Given** PKCE generation
**When** run
**Then** the verifier is 32 random bytes base64url without padding (43 characters), the challenge is base64url(SHA-256(verifier)) and matches the backend test vector (`dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk` → `E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM`), state is 24 random bytes base64url (32 characters, within the backend's `[A-Za-z0-9._~-]{16,128}`), all from `crypto.randomBytes`.

**Given** the callback arrives with a `state` that does not match
**When** processed
**Then** it fails `failed` "state mismatch" and the backend is **not** called; with an empty or missing `code` it fails "no code"; a non-200 from the token exchange fails "code rejected" and nothing is stored.

**Given** a good callback
**When** the exchange succeeds
**Then** only the refresh token is stored, the access token is kept in memory, and the pending command resolves.

**Given** a second `sign_in` while one is waiting
**When** it starts
**Then** the first resolves `cancelled` "sign-in cancelled"; `sign_out` cancels a pending one too.

**Given** no callback arrives within 300 s
**When** the timer fires
**Then** the pending state is cleared (only if it is still the same state) and `timeout` "sign-in timed out" is returned.

**Given** a callback arrives with no sign-in pending
**When** processed
**Then** it fails "no sign-in in progress" and does nothing else. One attempt only, whatever the outcome.

**Tasks**
- `electron/src/main/auth.ts`: `generatePkce`, `generateState`, `challengeFor`, pending-state management.
- `electron/src/main/session.ts`: `signIn`, `complete(url)`, `finish`.
- `electron/src/main/commands.ts`: `sign_in` handler.
- `electron/test/pkce.test.ts`: test vector and shape tests (port of `matches_the_backend_test_vector`, `generated_values_fit_the_backend_rules`).
- `electron/test/session-signin.test.ts`: `loopback_sign_in_exchanges_code_and_stores_only_the_refresh_token`, `wrong_state_is_refused_without_calling_the_backend`, `rejected_code_stores_nothing`, `sign_in_times_out`, plus supersede and cancel.

**Dev Agent Record**
- `main/auth.ts`: `generatePkce` (32 random bytes, 43-char verifier), `challengeFor` (base64url SHA-256), `generateState` (24 bytes, 32 chars), all `crypto.randomBytes`.
- `main/session.ts`: `signIn`, `complete(url)`, `#finish`, `#cancelPending`; `signOut` cancels a pending sign-in. Order as in `session.rs`: keychain `load` first (else `keychain_unavailable`), then PKCE and state, redirect, authorize URL, open. A superseded wait ends `cancelled`; timeout ends `timeout` and clears pending only if the state is still the same; a callback with nothing pending is `failed` "no sign-in in progress"; one attempt per callback.
- Seams: `new Session(cfg, keychain, {open, redirect})`. `open` is `shell.openExternal` in `index.ts` (URL built in main). `redirect` is a `StartRedirect` strategy returning `{uri, stop}`; the default is `klei://auth/callback`, and 16.5 supplies the loopback. `index.ts` does not pass the loopback yet, so a real sign-in works only after 16.5.
- `commands.ts`: `sign_in` returns `null`.
- Tests: `pkce.test.ts` (2, includes the backend vector), `session-signin.test.ts` (11): success, wrong state (backend not called), no code, rejected code, one attempt, malformed pair, timeout, supersede, sign-out cancel, broken keychain before browser opens, handler result.
- Full suite pass, typecheck clean, gate passes.
- Not verified: real browser and the compose backend (20.1); `shell.openExternal` on Windows and Linux.
