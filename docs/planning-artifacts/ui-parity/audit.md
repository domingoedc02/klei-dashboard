# UI parity audit

Evidence: `ui-parity/{prototype,desktop}/<screen>-<state>.png`, `ui-parity/diff/<screen>-<state>.png` (prototype | desktop | pixelmatch), `ui-parity/report.json`, `ui-parity/geometry.json`, `ui-parity/copy.json`. Regenerate: `cd desktop && npm run shots`.
Refs: `PT` = prototype root, `DK` = `desktop/src`. Severity P1 = broken, overlapping, clipped or missing behaviour; P2 = visible mismatch; P3 = polish. Status `open` until the owning story closes it with a fix commit and an after-screenshot.

## Summary

- 182 gaps. Severity: P1 21, P2 115, P3 46.
- By owner story: 13.10 (14), 13.11 (22), 13.12 (3), 13.13 (22), 13.14 (18), 13.15 (6), 13.2 (6), 13.3 (7), 13.4 (17), 13.5 (20), 13.6 (14), 13.7 (16), 13.8 (4), 13.9 (13).
- Capture: 53 pairs, 0 prototype-only, 16 desktop-only (no prototype twin, listed below).
- Geometry probe, desktop, after filtering: Review footer overlap, keychain hint over buttons, Edit dialog scroll (974px > 866px), Notifications glued text. Prototype: 0 real findings (10 `overlap` are the savebar over scrolled content, by design).

## Out of desktop scope

- Prototype `auth/*` (login, invite, verify, forgot, reset) are backend Thymeleaf templates. Desktop sign-in phases compared to `auth/login` for layout only.
- Prototype-only chrome hidden in capture: Wireframe state toggle (`.stsel`), `.seg[aria-label="Wireframe state"]`, profile menu "View as".
